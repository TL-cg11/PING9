## 2. 진행 방식

기존 미커밋 변경을 보존한 새 브랜치에서 문서만 보강했다. 긴 코드 블록을 그대로 복사할 수 있게 유지하면서 직후에 순서·실제 명령·입력 이유 표를 붙였다. 기존 장비나 실행 코드·예제 JSON 주소는 변경하지 않았다.

사용자가 실제로 배치한 구성은 기본 198.168 예제와 다르므로 별도 GRE 문서를 만들었다. R1 WAN=1.1.1.1, R3 WAN=2.2.2.2, PC LAN=192.168.0.0/24와 192.168.1.0/24, tun0=172.16.0.1/30과 172.16.0.2/30으로 정리했다. 사진의 실제 포트 Gi0/0·Gi0/3와 기본 예제 포트가 다른 점도 표시했다.

## 4. 결과와 검증

문서의 명령 블록을 직접 추출하는 임시 Vitest로 검증했다.

```text
pnpm --filter @ping9/engine exec vitest run src/vpn/vpn-walkthrough-rehearsal.test.ts
  Test Files 1 passed (1)
  Tests 4 passed (4)
  Duration 553ms
```

- 기본 198.168 GRE와 IPsec: commit 전 문서 불변·candidate show 확인 → 양쪽 commit → 양방향 TTL 126 및 GRE/ESP trace → 정책/터널 중단 실패 → 복구 성공.
- 사진 주소 GRE 2가지: 기존 LAN 일반 경로가 있는 경우/없는 경우. 조건부 delete 줄을 문서 지침대로 적용하고 WAN 왕복 경로 → 양쪽 GRE → 양방향 PC ping 및 GRE 캡슐화 확인.
- R2를 잘못 연 상황: GRE set을 candidate에만 입력했을 때 활성 문서 불변, discard → exit 후 문서 불변 및 일반 프롬프트 복귀 확인.

검증 후 임시 테스트는 삭제했다. 새 영구 테스트나 제품 코드 변경이 없어 전체 빌드/테스트는 반복하지 않았다. SSL은 기존 명령 블록을 바꾸지 않고 설명만 추가했다. 수동 브라우저 조작은 하지 않았다. Markdown 링크·비밀값·공백은 별도 확인했다.
