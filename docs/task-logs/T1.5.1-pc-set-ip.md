## 2. 진행 방식

1. 기존 `shared`를 확인했다. 검사 함수(`checkInterfaceAddress`, `checkGateway`), 오류 코드(`DEVICE_NOT_FOUND`, `DEVICE_KIND_MISMATCH`), 알림 코드(`DUPLICATE_IP`), Command 타입이 이미 있었다.
2. 빠져 있던 경우를 찾았다. "IP는 있는데 마스크가 없음", "IP 없이 게이트웨이만 있음"을 나타낼 오류 코드가 없었다.
3. 처리기를 `packages/engine/src/reducer/pc-set-ip.ts`에 만들고 `reducer.ts`의 `handlers`에 연결했다.
4. 예시 자료 `twoPcDocument`, `twoPcSwitchDocument`로 테스트했다. 장비 추가 Command(T1.3.1)가 없어도 테스트할 수 있다.

### 처리 순서

1. 장비가 있는가 → `DEVICE_NOT_FOUND`
2. PC인가 → `DEVICE_KIND_MISMATCH`
3. 값이 문자열이거나 null인가, 64자 이하인가 → `INVALID_IPV4` / `INVALID_MASK`
4. 세 값의 조합 → `PC_ADDRESS_INCOMPLETE { deviceId, missing: "ip" | "mask" }`. 세 값이 모두 없으면 설정 지우기
5. 주소와 마스크 → `checkInterfaceAddress`
6. 게이트웨이 → `checkGateway`
7. 새 Document를 만든다. 비운 칸은 키를 지운다
8. 같은 IP를 쓰는 다른 PC나 Router 인터페이스가 있으면 `DUPLICATE_IP` 알림. Document 순서대로 담는다

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 새 오류 코드 `PC_ADDRESS_INCOMPLETE { deviceId, missing }` | 설정 패널이 어느 칸에 어떤 문구를 띄울지 정확히 알 수 있다 | 기존 `INVALID_MASK { value: "" }` 재사용: "게이트웨이만 입력한" 경우와 뜻이 맞지 않음 |
| 중복 IP 검사에 Router 인터페이스를 넣음 | FR-27은 장비 종류를 가리지 않는다. Router 구성은 이미 스키마에 있다 | PC끼리만 검사 |
| 같은 값으로 다시 설정해도 성공, `docVersion`이 오름 | AD-16("받아들인 Command는 `docVersion`을 올린다")을 바꾸지 않는다. 불필요한 저장은 설정 패널(T1.5.2)이 값이 바뀌었을 때만 보내서 막는다 | 바뀐 게 없으면 버전을 그대로 두기: AD-16과 어긋남 |
| 64자를 넘는 값은 검사 함수에 넘기기 전에 거부 | `shared`의 검사 함수는 받은 값을 오류에 그대로 담는다. 오류 크기를 묶기 위해서다. 올바른 IPv4는 길어야 15자다 | `shared`의 검사 함수를 고치기: 이 Task의 범위를 넘음 |
| `HANDLED_COMMAND_TYPES`를 `reducer.ts`에서 내보냄 | `simulator.test.ts`의 "처리기가 없는 Command" 테스트가 구현된 Command를 빼고 돌게 하려고. 다음 Task(T1.3.1, T1.4.1)도 손대지 않아도 된다 | 테스트 안에 목록을 직접 적기: Task마다 테스트를 고쳐야 함 |

## 7. 남은 일과 다음 Task에 전할 것

- **T1.5.2 (PC 설정 패널):** 세 칸의 값이 지금 구성과 같으면 `pc/set-ip`를 보내지 않는다. `PC_ADDRESS_INCOMPLETE`의 `missing`으로 오류를 띄울 칸을 정한다.
- **T1.6.1 (`ipconfig`):** `ipconfig <IP> <마스크> [게이트웨이]`는 이 Command를 그대로 쓴다. 마스크가 빠진 입력은 명령 해석기가 먼저 막는다.
- **T1.8.1 (ARP):** IP가 바뀌면 그 PC의 ARP 테이블 같은 실행 중 상태를 정리해야 한다 (`onConfigChanged`, AD-4). 이 Task는 Document만 바꾼다.
- **T1.9.1 (메시지 카탈로그):** `PC_ADDRESS_INCOMPLETE`의 문구가 필요하다. 카탈로그가 모든 코드를 다루도록 타입으로 강제되므로 빠뜨리면 타입 검사가 알려 준다.
- **T1.3.1, T1.4.1:** 처리기를 `handlers`에 넣으면 `simulator.test.ts`는 따로 고치지 않아도 된다.
