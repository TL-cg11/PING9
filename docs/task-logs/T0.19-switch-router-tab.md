## 1. 목표와 완료 기준

T0.19([PR #61](https://github.com/TL-cg11/PING9/pull/61))는 PC 콘솔에 "Tab을 두 번 누르면 후보 나열"을 넣었다. PR 설명은 "PC만"이었지만 Switch·Router에서도 치다 만 글자가 있을 때는 후보가 나왔다 (빈 자리에서는 나오지 않았다). Switch 담당(SDY)이 이것을 버그로 되돌리지 않고 **Switch·Router의 기능으로 삼기로 정했다**. 반쪽이던 동작을 채우고 테스트로 고정한다.

- [x] Switch·Router 콘솔에서 Tab을 두 번 누르면 그 자리에서 칠 수 있는 명령어를 나열한다. 치다 만 글자가 있으면 그 글자로 시작하는 것, 빈 자리(빈 줄, 빈칸 뒤)에서는 그 자리의 명령어 전부
- [x] 값을 적는 자리(`vlan <id>`)와 모르는 단어에는 나열할 것이 없다
- [x] Tab 한 번은 예전 그대로다: 하나로 정해질 때만 완성한다. 빈 자리에서는 채우지 않고, 여러 키워드의 공통 부분만 채우지도 않는다
- [x] `?` 도움말과 PC 콘솔의 Tab(T0.19)은 그대로다
- [x] 공통 완료 조건: lint, 타입 검사, 단위 테스트, 빌드 (4절)
- [ ] 리뷰 — 팀원 검토 없이 병합했다 (6절)

## 2. 진행 방식

1. PR #61을 검토하다 Switch·Router에서도 후보가 나오는 것을 임시 테스트로 확인했다 (`candidates("e")` → `["enable", "exit"]`).
2. 처음에는 "PC만"이라는 PR 설명에 맞춰 되돌리는 수정을 이 브랜치에 올렸다 (커밋 `87b4f48`). 병합 전에 Switch 담당이 방향을 바꿨다: Switch·Router도 나열한다.
3. 테스트를 새 동작에 맞게 다시 썼다. 고치기 전에 돌려 실패하는 것을 봤다 (4절). 하나는 테스트에 도움말 표기를 잘못 적어(`<1-4094>` → `<id>`) 틀린 이유로 실패해 테스트를 고쳤다.
4. `completionAt`이 빈 자리에서도 키워드를 돌려주게 하고, Tab 한 번(`completeLine`)은 경로 완성이 없는 장비(Switch, Router)에서 예전 규칙을 지키게 했다.
5. 전체 검사를 돌리고 개발 서버에서 Switch, Router, PC의 터미널을 직접 눌러 봤다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| Switch·Router도 Tab 두 번에 후보를 나열한다 | 담당의 결정. 세 장비의 콘솔이 같게 동작하고, 무엇을 칠 수 있는지 `?` 없이도 보인다 | 실제 IOS처럼 `?`만 나열 (처음에 올린 수정) |
| 빈 자리에서도 나열한다 (`show ` 뒤, 빈 줄) | PC가 그렇게 한다. 글자를 쳐야만 나오면 `show ` 뒤에서 Tab을 두 번 눌렀을 때 아무 일도 없어 절반만 되는 기능이 된다 | PR #61이 남긴 그대로 치다 만 글자가 있을 때만 |
| 나열하는 것은 키워드뿐이다. 값 자리(`<id>`, `<ip>`)는 나열하지 않는다 | 후보는 "그대로 칠 수 있는 단어"다. 값의 설명은 `?`가 한다 | `?`처럼 `<id>`와 설명도 보이기 |
| Tab 한 번은 Switch·Router에서 예전 그대로 둔다 | 요청은 "두 번 눌렀을 때"다. 빈 자리에서 하나뿐인 단어를 채우거나(`configure ` → `configure terminal `) 공통 부분만 채우면 IOS와 달라지고, 줄여 쓰기에 익숙한 사람에게 방해가 된다 | PC처럼 빈 자리 채우기와 공통 부분 채우기까지 |
| PC와 IOS 장비는 경로 완성(`paths`)이 있는지로 가른다 | `paths`는 PC에만 준다 (`console.ts`의 `pathsOf`). 이미 있는 값이다 | `completeLine`에 장비 종류를 따로 넘기기 |

## 6. 계획과 달라진 점

- 계획(03 문서, T3.2.2)의 Tab은 "하나로 정해지면 완성"뿐이다. Tab 두 번의 후보 나열은 계획에 없는 추가다. 실제 Cisco IOS는 Tab으로 나열하지 않는다. 요구사항 추가라 팀 확인이 필요하다.
- 브랜치 이름이 `fix/`로 시작한다. 되돌리는 버그 수정으로 시작해서다. 내용은 T0.19의 후속 기능이 됐다.
- T0.19는 yysong1249의 Task다. 고친 `assist.ts`는 SDY가 T3.2.2에서 쓰고 yysong1249가 T0.19에서 고친 것이다.
- 작업 규칙 3번은 다른 팀원 한 명의 검토를 요구하지만, 담당자의 판단으로 검토 없이 병합했다.

## 7. 남은 일과 다음 Task에 전할 것

- 화면(`terminal-window.tsx`)의 "같은 입력에서 Tab을 두 번" 판단은 글자를 치거나 지워도 풀리지 않는다 (PR #61 리뷰). 이제 Switch·Router에서도 보인다: `c` Tab, `a`를 쳤다 지우고 Tab이면 한 번에 목록이 뜬다.
- Router에는 Switch의 "실제 명령 정의 전체로 Tab을 확인하는 테스트"(`assist.test.ts`)에 해당하는 것이 없다.
- PR #61 리뷰의 PC 쪽 항목은 그대로 남아 있다: 줄여 쓴 삭제 명령(`rm /s /q lab`, `rm - d`), OS를 바꿨다 돌아오면 되살아나는 파일 트리, 빈 단어에서 옵션을 넣는 Tab.
- 다음에 `cli/ios`의 완성을 고칠 때는 `assist-console.test.ts`와 `router-console.test.ts`로 Switch·Router의 Tab 한 번과 두 번을 함께 확인한다.
