## 1. 목표와 완료 기준

- [x] Windows PC `tracert`, Linux PC `traceroute`, Router `traceroute`로 지나는 Router가 hop마다 한 줄씩 보이고 마지막 줄이 목적지다

- [x] hop마다 Trace 하나. 콘솔의 hop 줄은 ping의 회차처럼 하나씩 보이고 펭귄이 걷는다

## 2. 진행 방식

1. 설계안(팀 합의 전)의 결정 5가지를 사용자가 모두 추천대로 정했다. RIP와 상관없어 `main`에서 새 브랜치를 땄다 (#41~#45 사슬과 따로 검토).
2. TTL을 1부터 하나씩 늘려 ICMP echo를 보낸다. Router가 TTL을 다 쓴 패킷에 `time-exceeded`를 돌려주는 것(T4.4.1)은 이미 있었다. 탐색 패킷의 TTL만 정할 수 있게 `sendEcho`에 `ttl` 인자를 더했다.
3. `Runtime.ping`의 회차 반복을 `runRounds`로 빼고 `traceroute`가 함께 쓴다. 회차의 sequence가 hop 번호라 shared의 `pingRoundKind`와 web의 회차 보이기가 그대로 맞는다.
4. 화면은 고칠 것이 거의 없었다. hop 줄도 "줄 하나 + 추적 줄 하나" 모양이라 `pacePing`이 그대로 나눈다. Ctrl+C로 멈췄을 때 ping 통계 대신 `^C`만 찍게 했다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| hop마다 탐색 1번, 시간 칸은 같은 값 세 번 | 같은 입력에 같은 결과라 세 번 보내도 시간이 같다. Trace가 hop마다 하나라 ping의 회차 보이기와 재생을 그대로 쓴다 | 실제처럼 3번 (hop 줄 하나에 Trace 3개, 최대 90회 실행) |
| 응답 없는 hop은 ping 타임아웃과 같이 4초. 최대 30 hop | 실제와 같은 최대값. 길면 `-h`·`-m`이나 Ctrl+C로 줄인다 | 실제처럼 hop마다 4초 × 3 |
| `TraceSummary`(`kind: "ping"`)에 `hop?` | 탐색 패킷이 ICMP echo라 ping과 같다. 새 `kind`면 `kind`로 나누는 곳을 모두 고쳐야 한다 | `kind: "traceroute"` |
| Linux도 ICMP로 보내고 머리 줄은 실제 기본값 `60 byte packets` | UDP 모델이 없다 (E11 결정 7) | UDP 33434~ |
| 최대 hop 옵션은 1~30. 넘으면 `TRACEROUTE_HOPS_OUT_OF_RANGE` | hop마다 추적이 하나다. 실제는 255까지 | 255까지 |
| `-d`(Windows), `-n`(Linux)을 받음 | 이름 풀이가 없다. Windows는 출력이 같고 Linux는 `(주소)`를 뺀다 | 받지 않음 |
| IOS 출력에서 `VRF info: ...` 줄을 뺌 | VRF가 없다. 그 자리는 옛 IOS처럼 빈 줄 | 그대로 |

끝나는 조건과 줄:

| 받은 것 | Windows | Linux | IOS | 다음 |
|---|---|---|---|---|
| `time-exceeded` | 시간과 주소 | `주소 (주소)  시간` | `주소 시간` | 다음 hop |
| echo reply | 시간과 목적지 | 같음 | 같음 | 끝 |
| `destination-unreachable` | `주소  reports: Destination net unreachable.` | 시간 뒤 `!N` | `!N  !N  !N` | 끝 |
| 응답 없음 | `*  *  *  Request timed out.` | `* * *` | `*  *  *` | 다음 hop |
| 출발 장비의 ARP 실패 | `자기 주소  reports: Destination host unreachable.` | 자기 주소, 시간 뒤 `!H` | `*  *  *` | 끝 |
| 보내지 못함 (게이트웨이 없음) | `Transmit error: code 1231.` | `connect: Network is unreachable` | — | 끝 |

## 6. 계획과 달라진 점

- 계획(04 문서 4.9절)에는 E11의 Task 분해가 없다. `T11.4.1`은 이 작업에서 정한 ID다.
- 실제 OS는 hop마다 3번 보낸다. PING9는 1번 보내고 시간을 세 칸에 쓴다 (주요 결정).
- 아래 문구는 알려진 실제 출력으로 맞췄고 실제 장비에서 다시 확인하지는 않았다: Windows `Transmit error: code 1231.`, Linux `connect: Network is unreachable`, Linux ARP 실패의 `!H`.
- Router가 출발지일 때 경로가 없거나 다음 홉의 ARP가 실패하면 `*  *  *` 한 줄로 끝낸다. 실제 IOS는 30 hop까지 `*`를 찍는다.

## 7. 남은 일과 다음 Task에 전할 것

- hop마다 Trace가 하나라 30 hop을 다 돌면 보관 한도(20개)를 넘어 앞의 추적이 밀려난다. 앞으로 RIP 교환 Trace가 들어오면 그것도 밀려날 수 있다.
- 돌아오는 `time-exceeded` 펭귄은 지금 요청과 같은 파랑이다. T11.5.1에서 구별한다 (설계안: 노랑에 `×`).
- 응답 없는 hop 사이에도 ping처럼 1초를 쉰다. 실제 traceroute는 쉬지 않는다.
- RIP 사각형(`fourRouterRipDocument`, PR #45)에서 R1–R2를 끊기 전후로 hop이 R2 → R4로 바뀌는 확인은 #45가 `main`에 들어온 뒤에 한다.
