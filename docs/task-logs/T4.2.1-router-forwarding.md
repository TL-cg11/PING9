## 2. 진행 방식

RouterModel을 Runtime에 등록하고 포트별 ArpModule을 유지한다. 기존 routingTable/lookupRoute와 링크 transmit을 재사용한다. PendingSend에 선택적 originalFrame을 추가해 전달 시 ctx.updateFrame으로 frameId를 보존한다. 기존 PC의 새 프레임 생성은 유지한다.

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 포트마다 ARP 모듈 | 다른 망의 학습과 대기를 격리 | Router 전체의 단일 IP 키 테이블 |
| 스위치 없는 예시 | 미구현 Switch 모델과 독립 검증 | Switch를 통과한 것처럼 성공 처리 |

## 3. 변경 내용

- RouterModel, Runtime의 모델 보관·재설정·ARP 조회·스냅샷 연결.
- IPV4_RECEIVED/IPV4_FORWARDED 이벤트, ARP의 frameId 보존.
- shared의 oneRouterLabDocument/staticRoutingLabDocument와 실제 통합 검사.

Windows 응답 TTL은 Router 한 대에서 127, 두 대에서 126이다. Linux PC의 응답은 두 대를 거쳐 62다. MAC 변경·IP 유지·frameId 보존, 게이트웨이 응답, ARP 재사용, shutdown/케이블 해제와 복구, 없는 다음 홉 ARP 종료와 load 초기화를 검사했다.

## 5. 추정과 실제

추정 2.0인일. 실제 인일은 별도 측정하지 않았다.

## 6. 계획과 달라진 점

기본 echo 응답도 수신 모델과 함께 구현했다. 경로 없음·TTL 소진은 우선 폐기 사유를 남기며 ICMP 오류 응답은 T4.4.1 후속에서 구현한다. Switch 모델은 이 범위에 없다.
