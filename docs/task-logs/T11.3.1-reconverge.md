## 1. 목표와 완료 기준

- [x] Router 4대 사각형에서 R1–R2 링크를 끊으면 R1이 R4 쪽 경로로 바꾸고 PC1 → PC2 ping이 다시 된다

- [x] 공통 완료 조건: lint, 타입 검사, 단위 테스트, 빌드 (4절). 리뷰는 PR에서

## 2. 진행 방식

1. 설계안(팀 합의 전)의 결정 6가지를 사용자가 모두 추천대로 정했다. T11.2.4와 커밋·PR을 하나로 하기로 해서 같은 브랜치에서 이어 했다 (기록 문서는 따로, PR #44 선례).
2. 재수렴 자체는 T11.2.2·T11.2.3에서 이미 된다. 교환마다 처음부터 배우고, 링크·구성이 바뀌면 교환이 저절로 돈다. 그래서 이 Task는 예시 토폴로지, 확인 테스트, 바뀐 경로 목록이 중심이다.
3. `fourRouterRipDocument`(사각형)를 예시 자료에 넣었다. 예시 목록에 "Router 4대 RIP 사각형"으로 들어가 기존 예시 검사(문서 검증, Simulator 속성 테스트)도 함께 받는다.
4. `Runtime.exchangeRoutes`: 교환이 끝나면 Router마다 라우팅 테이블의 RIP 경로를 앞의 교환 뒤 값과 비교해 `RouteChangeView` 목록을 만들고, 요약에 `added`·`removed`·`changed`를 더한다. 목록은 그 교환의 Trace와 함께 보관하고 `Simulator.getRouteChanges(traceId)`로 읽는다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| metric 16 철회 패킷(poison)과 hold-down은 넣지 않음 | 교환마다 처음부터 배우므로 철회할 옛 경로가 없다. 넣으려면 배운 경로를 교환 사이에 남기고 타이머를 흉내 내야 해서 구조를 다시 짜야 한다 | 실제 RIP처럼 넣음 |
| 무작위 그래프 속성 테스트 | 고리·여러 갈래에서 틀린 경로를 배우지 않는다는 것을 예시 몇 개가 아니라 많은 모양으로 확인한다 | 예시만 |
| 바뀐 경로는 요약에 개수, Runtime에 목록 | "끊었더니 무엇이 바뀌었나"가 이 Story의 학습 목표다. 화면(T11.5.1)이 쓸 값을 먼저 만든다 | 화면에서 계산 |
| 바뀐 경로를 Trace 이벤트로 넣지 않음 | 이벤트는 프레임 하나가 한 곳에 있는 순간이다(AD-6). 프레임 없는 "사라짐"을 넣을 자리가 없다 | 새 이벤트 |
| 같은 metric의 두 길은 먼저 들은 것 | 결정적이고, 실제 RIP도 같은 metric이면 바꾸지 않는다. ECMP는 E11 범위 밖 | 다음 홉 주소 순 |
| 비교 대상은 라우팅 테이블에 들어간 RIP 경로 | 요약의 `learned`(T11.2.3)와 같은 기준이다. ping에 쓰이는 경로만 보인다 | RIP가 배운 경로 전부 (Static에 가려진 것 포함) |
| 지운 Router의 경로는 목록에 넣지 않음, RIP를 끈 Router의 경로는 "사라짐" | 지운 장비는 화면에 없다. RIP를 끈 Router는 남아 있으니 경로가 빠진 것을 보여야 한다 | 둘 다 넣음 / 둘 다 뺌 |

R1–R2를 끊은 뒤의 목록 (테스트로 고정):

```text
R1  10.0.3.0/24   via 10.0.12.2 GI0/1 [2]  →  via 10.0.14.2 GI0/2 [2]
R1  10.0.23.0/30  via 10.0.12.2 GI0/1 [1]  →  via 10.0.14.2 GI0/2 [2]
R2  10.0.1.0/24   via 10.0.12.1 GI0/0 [1]  →  via 10.0.23.2 GI0/1 [3]
R2  10.0.14.0/30  via 10.0.12.1 GI0/0 [1]  →  via 10.0.23.2 GI0/1 [2]
R3  10.0.1.0/24   via 10.0.23.1 GI0/0 [2]  →  via 10.0.34.2 GI0/2 [2]
R3  10.0.12.0/30  via 10.0.23.1 GI0/0 [1]  →  (사라짐)
R4  10.0.12.0/30  via 10.0.14.1 GI0/0 [1]  →  (사라짐)
요약: learned 12, added 0, removed 2, changed 5
```

## 6. 계획과 달라진 점

- 계획(04 문서 4.9절)에는 E11의 Task 분해가 없다. `T11.3.1`은 이 작업에서 정한 ID다.
- E11 설계안은 이 Task에 triggered update의 metric 16 철회와 "다시 듣지 못한 경로 무효"를 넣었지만, 결정 1로 철회 패킷과 hold-down은 넣지 않았다. 다시 듣지 못한 경로는 교환마다 처음부터 배우므로 저절로 없어진다.
- 설계안은 Task마다 브랜치를 따로 두는 것이었지만, 사용자 결정으로 T11.2.4와 같은 브랜치·PR에 넣었다.

### 실제 RIP와 다른 점

| 실제 | PING9 |
|---|---|
| 인터페이스가 꺼지면 그 경로를 metric 16으로 이웃에게 알림 | 알리지 않는다. 다음 교환에서 이웃이 그 경로를 다시 듣지 못해 없어진다 |
| 이웃이 사라지면 180초 뒤 무효, 240초 뒤 삭제. Switch를 사이에 두면 포트가 살아 있어 이 시간을 기다린다 | 바로 바뀐다 |
| hold-down 180초 동안 더 나쁜 경로를 받지 않음 | 없음 |
| 수렴까지 수십 초~수 분 | 교환 1회 (가상 시간 수십 ms) |

## 7. 남은 일과 다음 Task에 전할 것
