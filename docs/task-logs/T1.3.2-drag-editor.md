## 1. 목표와 완료 기준

- [x] PC·Switch·Router를 목록에서 끌어 놓은 위치에 생성한다. 클릭만으로 생성하지 않는다.
- [x] 배치한 장비를 끌어 옮기고, 놓을 때 `device/move`를 한 번 보낸다.
- [x] 이동 중에도 링크와 포트 이름이 양 끝 장비의 위치를 따라간다.
- [x] 케이블 선택 상태가 보이고, 장비별 빈 포트를 순서대로 선택하면 연결한다.

## 2. 진행 방식

1. 최신 `main`을 병합해 기존 장비 아이콘, 선택 효과, 케이블 끝점 계산을 유지했다. 앞서 작업한 Router IP 설정도 보존했다.
2. 장비 목록과 캔버스 이동에 Pointer Events를 사용했다. 창 전체의 이동·놓기 이벤트를 받아 아이콘 밖에서 놓아도 조작이 종료되게 했다.
3. SVG의 `getScreenCTM()` 역변환으로 화면 좌표를 문서 좌표로 바꾼다. 드래그 중에는 임시 좌표만 그리고, 드롭할 때 문서 명령을 보낸다.
4. 케이블 도구와 첫 포트·열린 장비 목록 상태를 분리했다. 포트 선택 직전의 최신 문서로 빈 포트 여부를 다시 확인한다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |

| 포인터로 배치·이동 | 실제 Chrome 검사에서 네이티브 HTML 드래그와 SVG 포인터 캡처의 종료 이벤트 누락을 발견해 창 전체 이벤트 방식으로 보완 | HTML Drag and Drop만 사용 |

| 장비를 클릭해 포트 목록 열기 | 사용자가 요청한 연결 순서 | 양쪽 장비를 한 번에 고르는 기존 모달 |
| 입력 필드·터미널 출력은 선택 허용 | 설정 편집과 명령 출력 복사를 지원 | 모든 자식 요소의 선택 강제 차단 |

## 4. 결과와 검증

Node 24.19.0에서 검사했다.

```text
pnpm check
lint / typecheck / build 통과
scripts 35 + shared 307 + engine 1131 + web 248 + api 2 = 1723 tests passed

pnpm check:secrets
통과. 추적되지 않은 신규 파일 9개도 같은 검사 규칙으로 별도 검사해 통과했다.

pnpm --filter @ping9/engine exec vitest run --maxWorkers=2
Test Files 33 passed
Tests 1131 passed
```

중간 전체 검사에서 기존 `switch-vlan.property.test.ts` 한 건이 5초 제한을 넘었다(5.675초). 동시 실행 수를 2로 제한한 재검사는 전체 1,131개가 통과했다. 테스트의 제한 시간이나 기존 VLAN 구현은 바꾸지 않았다.

실제 Chrome의 `http://127.0.0.1:5173/`에서 확인:

- 장비 6개에서 Router·PC·Switch를 각각 드래그해 9개로 증가. 놓은 위치에 생성됐다.
- 장비 목록 클릭과 캔버스 밖 드롭은 장비 수를 바꾸지 않았다.
- 케이블 버튼의 `선택됨` 표시와 단계 안내, SW1·SW2의 사용하지 않은 Fa0/3~7 목록을 확인했다.
- SW1 Fa0/3 → SW2 Fa0/3, 새 R1 Gi0/0 → PC5 Eth0를 순서대로 선택해 연결했다.
- 연결된 PC를 다른 위치로 드롭한 뒤 Escape를 눌러도 확정 좌표와 케이블 끝점이 유지됐다.
- 드래그 과정에서 장비 이름 등 편집기 글자에 선택 영역이 생기지 않았다. Escape로 케이블 도구가 해제됐다.

- 사용자 요청에 따라 T1.4.2의 연결 방식을 케이블 도구 선택 → 첫 장비/포트 → 두 번째 장비/포트 선택으로 변경했다.
- `device/move` 종류만 정의돼 있어 이번 작업에 처리기를 포함했다.
- 확대·이동 도구 자체는 이번 범위에 추가하지 않았다. 좌표 역변환은 확대·이동·여백이 있는 행렬을 자동 검사한다.
- 계획 문서 본문은 수정하지 않았다.
