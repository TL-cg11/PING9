## 2. 진행 방식

1. 설계안 시안(`T0.13-시안-시뮬레이션조작.png`)의 A안을 사용자가 정했다 (2026-11-11). 내보내기·가져오기를 왼쪽에 둔 T7.1 시안과 같은 막대다.
2. **시뮬레이션 시계**(`sim-clock.ts`)를 새로 만들었다. 시뮬레이션의 시각은 실제 시각 대신 이 시계의 시각이다. 멈추면 시계가 서고, 2×면 두 배로 간다.
3. 펭귄 재생(`play`의 시작 시각, 펭귄 층의 매 프레임 시각)과 시뮬레이션의 콘솔 기다리기(`runLinePaced`의 `wait`)가 같은 시계를 쓴다. 그래서 둘이 함께 서고 함께 빨라진다. 엔진과 `ping-pacing.ts`는 바꾸지 않았다.
4. 시계는 실제 시각과 타이머를 밖에서 받아 가짜 시각으로 단위 테스트했다.
5. 개발 서버를 띄워 헤드리스 Chrome으로 눌러 확인했다 (4절).

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 시계 하나를 펭귄과 콘솔이 같이 쓴다 | 콘솔 줄은 응답 펭귄이 닿을 때 뜬다 (T6.1.2). 따로 멈추면 어긋난다 | 펭귄만 멈춤 |
| 멈춘 동안 Ctrl+C는 그대로 된다 | 기다리던 것을 바로 그만두고 통계 줄을 찍는다 | 멈춘 동안 막음 |
| 멈춘 동안 친 명령: 바로 끝나는 명령은 바로, ping은 첫 줄(`Pinging …`)까지 뜨고 선다 | 시계가 선 것이지 터미널이 잠긴 것이 아니다 | 입력을 막음 |
| 실시간으로 바꾸면 멈춤을 푼다. 속도는 그대로 | 멈춘 채 기다리던 ping이 실시간에서 서 있지 않게 | 멈춘 채 둠 |
| 속도 셋 0.5×·1×·2×, 처음 1× | 시안대로 | 더 많은 단계 |
| 멈춤·속도는 기억하지 않는다 (새로고침하면 실행 중, 1×) | 멈춘 채 열리면 고장으로 보인다 | 모드처럼 `localStorage` |
| 경로 교환 재생(Router 패널 `▶ 재생`)도 같은 시계 | 시뮬레이션의 펭귄은 모두 같은 규칙 | ping만 |
| `ping-tool.ts`, `ping-address-picker.tsx`와 그 테스트를 지운다 | 쓰는 곳이 없다 | 남겨 둠 |

브라우저 확인 (개발 서버, 헤드리스 Chrome. VLAN 예시를 가져와 PC1 터미널에서 `ping 10.0.10.3`):

```text
실시간 상단:   ⤓ 내보내기 | ⤒ 가져오기 | ⏱ 실시간 | ⏯ 시뮬레이션
시뮬레이션:    ⤓ 내보내기 | ⤒ 가져오기 | ⏸ 멈춤 | 0.5× | 1×* | 2× | ⏱ 실시간 | ⏯ 시뮬레이션
장비 한 번 누름 → 안내 띠 없음 (보통의 선택)
멈춤 → 2.5초 뒤에도 펭귄 자리와 콘솔 줄 수가 같음, 버튼은 "▶ 다시 실행"
다시 실행 → 펭귄이 다시 움직임
2× → 회차 줄이 약 1.8~2초 간격으로 뜸 (회차 사이 1초 + 펭귄 재생 시간이 절반으로)
실시간으로 → 멈춤·속도가 사라짐
```
