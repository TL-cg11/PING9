## 2. 진행 방식

1. 사용자 요청(2026-11-11 "내보내기, 가져오기 + 세션 저장")으로 설계안과 시안을 먼저 만들고, 정할 것 12가지를 사용자가 "시안대로" 정했다. 처음에는 PR 셋(T7.1.1 → T7.1.2 → 세션 저장)으로 나누려 했으나, 사용자가 T7.1.1과 T7.1.2를 한 커밋으로 올리기로 했다. 기록 문서는 Task마다 따로 둔다. 세션 저장은 다음 PR.
2. 파일 내용을 만드는 일(`exportFile`)과 받게 하는 일(`downloadText`)을 나눴다. 앞의 것은 순수 함수라 단위 테스트로 본다.
3. 겉 포장의 타입과 `kind` 값은 `shared`에 두었다. 가져오기(T7.1.2)와 나중의 서버 가져오기가 같은 것을 읽는다.
4. 버튼 자리는 사용자가 정한 대로 상단 막대 왼쪽, 토폴로지 이름 옆으로 옮겼다. 오른쪽에는 모드만 둔다.
5. 개발 서버를 띄워 브라우저를 자동으로 조작해 버튼을 누르고, 받은 파일을 열어 확인했다 (4절).

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 파일 이름 `<이름>.ping9.json` | PING9 파일인 것이 보인다. 열기 창은 `.json`으로 고른다 | `<이름>.json` |
| 파일 이름에 쓸 수 없는 글자(`\ / : * ? " < > \|`, 제어 문자)는 `_`. 앞의 점은 빼고, 비면 `topology` | Windows·macOS 어디서나 저장된다. 점으로 시작하면 숨김 파일이 된다 | 브라우저에 맡김 (브라우저마다 다르게 바꾼다) |
| 들여쓰기 2칸 + 끝 줄바꿈 | 사람이 열어 볼 수 있다. 크기는 가져오기 한도(2MB)보다 훨씬 작다 | 한 줄 JSON |
| Runtime(ARP, 콘솔 기록, RIP로 배운 경로)은 넣지 않음 | 계획대로. 열면 Runtime은 비어 있다 (03 문서 "불러오기") | 같이 넣음 |
| 장비가 없어도 받는다 | 빈 토폴로지도 토폴로지다 | 버튼을 끔 |
| `TopologyExport` 타입과 `TOPOLOGY_EXPORT_KIND`를 `shared`에 | 가져오기(T7.1.2)와 서버가 같은 모양을 읽는다 | web에만 둠 |
| 꺼진 `.ghost` 버튼을 흐리게 | 켜진 내보내기와 아직 꺼진 가져오기가 나란히 있어 구별해야 한다 | 그대로 (같아 보임) |
