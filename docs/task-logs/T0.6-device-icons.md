## 2. 진행 방식

1. 그림은 저장소 밖의 로컬 사본에서 먼저 그려 보고 확정했다. 사용자가 준 그림(PC → 이글루, Switch → 갈림길 표지판, Router → 관문, 경로 없음 → 닫힌 관문)을 따랐다. 시안(`mockup.html`)의 펭귄과 물고기 은유와 같은 세계다.
2. 아이콘은 `device-icons.tsx`의 32×32 SVG 컴포넌트로 만들고, 캔버스(56)와 장비 목록(30px)이 같은 그림을 쓴다.
3. 카드가 없어져 선이 아이콘을 뚫고 지나가는 문제는 `format/link-ends.ts`의 순수 함수로 선 끝을 장비 둘레에서 끊어 풀었다.
4. 캔버스를 그림으로 뽑아 선 끝과 trunk 끝 글자("허용 10, 20")가 아이콘·이름과 겹치지 않는 것을 확인했다.

### 왜 T1.3.2가 아니라 따로 하나

- 계획에서 아이콘은 T1.3.2(캔버스 노드와 끌어다 놓기)에 들어 있다. T1.3.2는 T1.3.1(장비 reducer)이 없어 막혀 있는데, 아이콘은 reducer와 상관없다.
- `canvas.tsx`를 SDY가 계속 고치고 있어(T5.2.1, T5.3.1) 먼저 넣을수록 충돌이 적다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 카드(`rect.card`)는 지우지 않고 투명한 클릭 영역으로 남긴다 | 아이콘의 빈 곳을 눌러도 선택된다. 클릭·더블클릭 동작을 바꾸지 않는다 | 카드 삭제 (아이콘 선만 눌러야 함) |
| 선택은 아이콘 뒤에서 퍼지는 파란 빛. `prefers-reduced-motion`이면 움직이지 않는다 | 카드 테두리가 없어져 다른 표시가 필요했다. 오른쪽 속성 패널도 함께 바뀌므로 색만으로 알리는 것이 아니다 (NFR-12) | 아이콘 아래 옅은 파란 원 (먼저 해 보고 바꿈) |
| 선 끝을 장비 둘레 상자(가로 ±30, 세로 ±40) 밖에서 끊는다. 너무 가까우면 끊지 않는다 | 이름과 IP 글자까지 상자 안에 든다. 연결이 안 보이는 것보다 겹치는 편이 낫다 | 원으로 끊기 (아래쪽 이름 줄을 덮지 못함) |
| 이글루는 바닥선 기준 1.2배 | 납작한 모양이라 같은 크기에서 다른 그림보다 작아 보였다 | 그대로 |
| 닫힌 관문(`GateClosedIcon`)도 넣는다. 아직 쓰는 곳은 없다 | 실패 사유 표시(T1.10.2)에서 쓴다. 테스트를 붙였다 | 그때 넣기 |
| 장비 목록 아이콘 크기는 30px 그대로 | 장비 목록의 칸 크기를 바꾸지 않는다 | 56px (칸이 커짐) |
