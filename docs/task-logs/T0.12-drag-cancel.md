## 1. 목표와 완료 기준

계획에 없는 Task라 완료 기준을 새로 정했다. 끌기를 시작한 뒤에 마음이 바뀌면 왼쪽 장비 목록에 다시 놓아서 그만둘 수 있게 한다.

- [x] 장비 목록에서 끌어 온 새 장비를 장비 목록에 다시 놓으면 추가되지 않는다
- [x] 캔버스에서 옮기던 장비를 장비 목록에 놓으면 옮기기 전 자리로 돌아간다 (`device/move`를 보내지 않는다)
- [x] 끄는 동안 장비 목록이 취소하는 방법을 알리고, 목록 위에 오면 놓았을 때 취소된다고 표시한다
- [x] lint, 타입 검사, 단위 테스트, 빌드 (`pnpm check`)
- [ ] 리뷰 — 팀원 검토 없이 병합했다 ([T1.3.3 기록](T1.3.3-rename-delete.md) 6절)

## 2. 진행 방식

1. 지금 동작을 확인했다. 새 장비는 캔버스 밖에 놓으면 추가되지 않으므로 장비 목록에 놓아도 이미 취소였다. 하지만 화면에 아무 표시가 없어서 취소할 수 있다는 것을 알 수 없었다. 옮기던 장비는 캔버스 가장자리에 붙어서, 장비 목록 위에서 놓으면 왼쪽 끝으로 옮겨졌다.
2. 점이 사각형 안인지 보는 `containsPoint`를 `canvas-interaction.ts`에 테스트와 함께 넣었다.
3. `Canvas`가 장비 목록의 자리(`cancelZoneRef`)를 받아, 두 끌기에서 포인터가 그 위인지 본다. 상태(`idle` / `armed` / `over`)를 `onCancelZone`으로 알린다.
4. `Palette`가 그 상태로 안내 한 줄과 모양을 바꾼다.
5. 로컬 개발 서버를 브라우저로 열어 확인했다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 옮기던 장비도 취소할 수 있게 한다 | "한번 끌기 시작한 것"에는 새 장비와 옮기던 장비가 다 들어간다. 옮기던 장비의 취소는 Esc뿐이었다 | 새 장비의 표시만 더한다 |
| 옮기던 장비를 목록에 놓으면 지우지 않고 제자리로 돌린다 | 삭제는 따로 있다 ([T1.3.3](T1.3.3-rename-delete.md)). 끌어서 지우면 케이블이 있는 장비의 확인을 건너뛰게 된다 | 목록에 놓으면 삭제 |
| 목록 위에 있는 동안 옮기던 장비를 원래 자리에 그린다 | 놓으면 어떻게 되는지를 놓기 전에 보여 준다 | 캔버스 왼쪽 끝에 붙여 둔다 |
| 목록에서 끌기 시작한 직후에는 "놓으면 취소" 표시를 하지 않는다. 한 번 목록을 벗어난 뒤부터 한다 | 누르자마자 목록이 빨갛게 바뀌면 잘못 누른 것처럼 보인다 | 누른 순간부터 표시 |
| 놓은 자리는 캔버스가 판단한다. 장비 목록은 자기 자리(`ref`)와 모양만 맡는다 | 두 끌기의 포인터를 캔버스가 이미 창 전체에서 따라간다. 판단을 한 곳에 둔다 | 장비 목록이 `pointerup`을 따로 받는다 |

  캔버스에서 끄는 중  장비가 포인터를 따라감, 목록 armed
