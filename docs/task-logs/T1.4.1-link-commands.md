## 2. 진행 방식

`reducer/link.ts`에 링크 추가·삭제와 장비 삭제 처리기를 두고 `reducer.ts`에 등록했다. 링크를 추가할 때 기존 `validateDocument()`에 새 문서를 넘겨 참조, 포트 점유, 한도를 확인한다. 실패하면 기존 문서와 스냅샷을 유지한다.

꺼진 포트에도 케이블은 연결할 수 있다. Router가 꺼져 있으면 Router는 `admin-down`, 상대 포트는 `peer-down`이다. Router를 켜면 양 끝이 `up`, 케이블을 지우면 켜진 포트는 `no-link`가 된다. 상태 계산은 기존 `computeViews`를 사용한다.

### 주요 결정

| 결정 | 이유 | 선택하지 않은 대안 |
|---|---|---|
| 연결 검증을 shared의 유일한 문서 검증기로 수행 | API/가져오기와 같은 규칙을 사용 | 포트 점유/참조 검증 중복 구현 |
| 장비 삭제 시 링크도 같은 반환 문서에서 삭제 | 삭제 직후 끊어진 참조가 남지 않음 | 화면이 따로 링크를 지움 |
| Document 변경만 구현 | 커널과 DeviceModel은 아직 Simulator에 연결되지 않음 | 없는 런타임 훅을 형식적으로 추가 |

## 6. 계획과 달라진 점

- `device/remove`가 아직 없어 T1.3.1의 해당 명령도 이 Task에서 구현했다. 삭제 버튼과 확인 창은 포함하지 않는다.
- 구성 변경 시 Runtime 정리는 공통 DeviceModel/Simulator 연결 뒤에 남긴다. `computeViews`의 연결 상태는 이미 즉시 갱신된다.
