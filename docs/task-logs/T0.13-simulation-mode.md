## 2. 진행 방식

1. 사용자 요청(2026-11-11)으로 설계안을 쓰고, 5180 화면에서 찍은 시안(실시간 / 시뮬레이션 나란히)을 먼저 보였다. 정할 것 11가지를 사용자가 정했다. 8번(모드 기억)은 추천과 다르다. 10번(`▶ ping 실행`)은 처음에 "그대로 꺼 둠"으로 정했다가 사용자가 "시뮬레이션에서는 가능하게"로 바꿨다. 그 흐름의 시안(출발 → 목적지 → 주소 → 터미널)을 다시 보이고 P1~P11을 정했다 (모두 추천).
2. 엔진은 고치지 않았다. 펭귄이 나오는 곳은 `app.tsx`의 `play` 두 군데(콘솔 회차, 경로 교환)뿐이다.
3. 실시간의 콘솔 속도는 새로 계산하지 않았다. `runLinePaced`의 `play`가 0을 돌려주면 `waitAfterStart(kind, 0)`이 실제 OS 간격이 된다 (T1.8.3).
4. `▶ 재생` 버튼(T11.5.1)과 `app.tsx`가 겹쳐 PR #49 위에서 시작했다. 그사이 `main`에 #50, #51이 들어와 #49를 그 위로 다시 올렸다.
5. 5180 화면을 사각형 RIP 예시로 잠시 열어 브라우저를 자동으로 조작해 확인했다 (4절).

## 6. 계획과 달라진 점

- 모드 전환은 계획(02 문서, 03 문서 3.3절)에 없다. 03 문서는 재생 막대 하나다. 시안을 따른 요구사항 추가라 팀 확인이 필요하다 (VPC-웹페이지 설계안 10절 3).
- 계획의 재생(E6)은 이벤트 목록에서 고른 추적을 재생 막대로 본다. 지금은 시뮬레이션 모드에서 ping 회차마다 저절로 재생한다 (T6.1.2부터).

## 7. 남은 일과 다음 Task에 전할 것

- 시뮬레이션 하단 패널: 이벤트 목록(T1.9.2), 재생 막대(T6.2.1), 동기화(T6.2.2), 프레임 보기(T6.3.1). 펭귄을 그릴지 말지는 `app.tsx`의 `modeRef`와 `mode`를 보면 된다.
