## 2. 진행 방식

설정 명령은 기존 CLI 정의 → Simulator.dispatch → reducer 경로를 사용한다. 주소 형식은 기존 `checkInterfaceAddress`로 검사하고 Router 내부 네트워크 겹침 규칙을 추가했다. 마스크가 서로 달라도 하나가 다른 네트워크를 포함하면 겹침으로 판정한다. 포트가 꺼져 있어도 설정 충돌은 거부한다.

네트워크 겹침 규칙은 shared에 두어 reducer의 새 설정과 `validateDocument`의 불러오기에서 함께 사용한다. 문서의 형태나 schemaVersion은 변경하지 않았다. 새 오류 코드 `INTERFACE_NETWORK_OVERLAP`에는 설정한 포트, 겹치는 포트, IP와 마스크를 담고 웹 메시지 카탈로그에서 한국어로 표시한다.

Router 구성은 포트 4개를 기본 꺼짐 상태로 채우고 포트 순서대로 정규화한다. `show running-config`는 기본값과 다른 인터페이스 설정만 출력한다. 이미 있는 공통 모드·인터페이스 명령과 PC에서 구현한 IPv4/마스크 매개변수 해석을 재사용했다.

### 주요 결정

| 결정 | 이유 | 선택하지 않은 대안 |
|---|---|---|
| 서로 다른 접두사 길이는 더 넓은 네트워크 기준으로 비교 | /16이 /24를 포함하는 경우도 검출, 부호 있는 비트 연산 회피 | 같은 마스크일 때만 비교 |
| 겹침은 거부, 장비 간 중복 IP는 기존 경고 | FR-27 준수 | 중복 IP를 무조건 거부 |
| 불러오기에서도 같은 겹침 검사 | CLI/파일에 서로 다른 유효성 규칙이 생기지 않음 | reducer에서만 검사 |
| 기존 Router 상태와 정적 경로 설정 보존 | IP 설정만 바꾸는 명령의 책임 유지 | Router 전체 설정 초기화 |
| 공통 설정 함수에서 정규화 후 문서 전체 검증 | 희소 구성 왕복, 문서 크기/스키마 제약 유지 | 처리기마다 전체 규칙 중복 구현 |

## 6. 계획과 달라진 점

- 겹침 오류 코드와 공통 검증 규칙을 추가했다. 기존 문서 형태는 유지하지만 과거에 검증을 통과하던 Router 내부 중첩 네트워크는 이제 불러오기에서도 거부된다.
- Router 설정을 직접 바꾸는 화면 패널은 추가하지 않았다. IP는 CLI에서 설정하고 조회한다.
- 공통 `device/rename` 처리기는 아직 없어 다른 이름을 가진 새 Router로 hostname까지 복원하는 것은 후속 작업이다. 현재 지원하는 기본 동일 이름의 Router에서 IP/포트 구성 왕복을 검증했다.
- 구성 출력은 이미 문서에 저장된 staticRoutes가 있으면 `ip route` 줄도 보여 준다. 그 명령의 입력/삭제 지원과 정적 경로 왕복 검사는 T4.3.1에 남는다.
