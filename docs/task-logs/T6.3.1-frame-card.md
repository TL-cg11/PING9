## 1. 목표와 완료 기준

시뮬레이션에서 걷고 있는(또는 넘어진) 펭귄을 누르면 그 프레임의 내용을 계층별로 본다.

- [x] 계층별 구역: Ethernet(VLAN 태그 포함), ARP 또는 IPv4, ICMP. 지금 엔진에 있는 UDP와 RIP도
- [x] 필드 이름과 값. 프레임에 있는 칸은 모두 보인다
- [ ] 같은 `frameId`의 앞 이벤트와 비교해 달라진 필드 강조 — 이 PR에 없음 (6절)
- [ ] 한 단계에 프레임이 여럿이면 고르기 — 펭귄을 하나씩 누르는 것으로 대신함 (6절)
- [x] 공통 완료 조건: lint, 타입 검사, 단위 테스트, 빌드 통과. 리뷰는 PR에서

## 2. 진행 방식

1. 디자인 사본(5180)에서 시안을 여러 번 만들어 골랐다: 봉투(계층이 안쪽으로 겹친 상자)와 계층 탭 가운데 봉투. 설명 문구·장비가 한 일·노란 강조는 빼고 패킷 값만 남겼다. 카드 읽는 법은 `?`에 마우스를 올리면 뜨는 창으로 뺐다.
2. 5180에 구현해 headless Chrome으로 실습 파일을 가져와 `ping`을 보내고 펭귄을 눌러 확인했다.
3. 저장소의 main(Firewall이 들어온 뒤)에서 브랜치를 만들어 옮겼다. 5180에는 T6.4.1(PR #64) 변경이 섞여 있어 파일을 통째로 복사하지 않고 이번 변경만 옮겼다. Firewall의 인터페이스 IP도 주소 주인으로 찾게 더했다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 하단 도크가 아니라 펭귄을 누르면 펭귄 옆에 카드 | 학생이 보고 있는 그 펭귄의 내용을 바로 본다. 하단 도크(T6.2)가 아직 없다 | 하단 도크의 탭 |
| 바깥(L2)부터 안쪽으로 겹친 상자 | 캡슐화가 모양으로 보인다 | 계층 탭 (한 번에 한 계층만 보임) |
| 누르면 시뮬레이션 시계를 멈추고, `✕`·같은 펭귄 다시 누르기·"다시 실행"이면 닫고 이어감 | 걷는 펭귄 옆에 카드가 따라가면 읽기 어렵다 | 멈추지 않고 카드만 |
| 주소 옆에 그 주소의 장비·포트 (회색) | MAC 주소만으로는 누구인지 알 수 없다. MAC은 엔진의 `macAddressFor`로 같은 규칙을 계산해 찾는다 | 주소만 |
| VLAN 태그가 없으면 "없음", Switch access 포트 쪽 케이블이면 "없음 (access 포트)" | trunk에서만 태그가 붙는다는 것이 비교된다. Router 포트는 access 포트가 아니다 | 태그가 없으면 칸을 숨김 |
| 카드는 SVG 밖 HTML로 화면 좌표에 띄움 | 확대 배율에 따라 카드가 커지거나 잘리지 않는다 | SVG `foreignObject` (배율 따라 커짐) |
| 카드 읽는 법은 `?`를 가리킬 때만 | 카드를 짧게 둔다 | 카드 안의 범례 |
| 노란 강조 없음 | 왜 눈여겨봐야 하는지 설명 없이 칠만 하면 뜻이 통하지 않는다 | 브로드캐스트·TTL 등 칠하기 |

## 6. 계획과 달라진 점

- 계획은 "하단 도크의 프레임 보기 탭"이다. 하단 도크가 아직 없어서 펭귄을 누르면 펭귄 옆에 카드로 보인다. 팀 확인 필요.
- 계획의 완료 기준 "Router를 지난 단계에서 MAC 주소와 TTL이 강조됨"은 하지 않았다. 강조를 시안에서 빼기로 했다. 대신 Router 앞뒤의 카드에서 MAC과 TTL이 다른 것을 테스트로 확인한다. 팀 확인 필요.
- "한 단계에 프레임이 여럿이면 고르기"는 따로 만들지 않았다. 같은 순간의 펭귄이 여럿이면 하나씩 누른다.
- 계획에 없는 UDP·RIP 상자를 더했다 (E11에서 RIP가 들어옴).

## 7. 남은 일과 다음 Task에 전할 것

- 달라진 필드 강조는 남았다. 하려면 강조에 이유를 함께 보여 줄 방법을 정해야 한다.
- main에서는 펭귄이 장비 아이콘 아래에 그려져, 아이콘과 겹친 순간의 펭귄은 누를 수 없다. T6.4.1(PR #64)이 펭귄 층을 장비 위로 옮기면 풀린다.
- 카드가 펭귄 왼쪽에 뜨는 경우(꼬리 `>`)는 화면으로 확인하지 않았다.
- 펭귄을 누르면 이벤트 목록에서도 같은 이벤트가 선택되지만, 이벤트 탭을 연 상태로는 화면 확인을 하지 않았다.
