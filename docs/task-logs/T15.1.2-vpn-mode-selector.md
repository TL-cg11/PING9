## 2. 진행 방식

사용자는 VPN을 사용할지 화면에서 선택할 수 있어야 하는 것 아닌지 물었다.
앞선 구현은 GRE 경로/IPsec selector에 따라 이미 캡슐화와 검사를 수행했지만 화면에는 명시적 모드 선택이 없었다.
기존 설정을 지우지 않고 해당 Router의 모드를 저장하는 Command와 UI를 붙였다.
T15.1.1의 미커밋 작업을 보존한 새 브랜치에서 이어서 작업했다.

### 주요 결정

| 결정 | 이유 |
|---|---|
| Router별 선택 | site-to-site 양 끝의 설정을 각각 관찰·실습할 수 있음 |
| off는 기존 물리 라우팅 | 선택만으로 경로나 상대 설정을 만들어 주지 않으며 캡슐화 없이 전달 |
| GRE는 Tunnel 경로, IPsec은 보호 subnet만 적용 | 선택했다고 모든 트래픽을 무조건 터널에 넣지 않음 |
| 터널/프로필/경로는 보존 | 껐다 켤 때 다시 CLI 설정할 필요가 없음 |
| 모드 전환 시 SA sequence/만료 유지 | off/on으로 재전송 검사를 초기화하거나 만료를 우회하지 않음 |
| optional vpnMode | 옛 문서는 기존 CLI 설정에 따른 동작 유지 |

## 3. 변경 내용

- `RouterConfig.vpnMode`, `router/set-vpn-mode`와 공통 schema·정규화.
- off/gre/ipsec 선택 및 옛 문서 모드 해석 헬퍼. 두 종류의 독립 설정이 함께 있는 옛 문서는 기존 CLI 설정 상태를 표시.
- GRE 비선택 시 논리 경로 제외·수신 복원 중지·Tunnel IP 로컬 응답 중지.
- IPsec 비선택 시 selector 보호/수신 평문 요구를 끄고 수신 ESP는 복원하지 않음. 물리 중간 Router의 일반 L3 전달은 유지.
- IPsec 선택 상태에서 잘못된 키·SA 등 실패 시 기존 평문 우회 차단 유지.
- Router Inspector의 VPN 라디오 선택, 적용 범위, 미설정 안내, 암호화 없는 교육용 모델 표시.
- `vpn mode off|gre|ipsec`, `no vpn mode`, `show vpn`, running-config 저장/복원.
- [로컬 실습 안내](../guides/vpn-local-lab.md)에 선택 방법과 일반 라우팅 비교를 추가.

## 4. 결과와 검증

```text
pnpm --filter @ping9/engine exec vitest run src/devices/router/vpn-mode.test.ts
9 tests passed

pnpm check: exit 0
lint / typecheck / build 통과
scripts 35 + shared 370 + engine 1599 + web 395 + api 2 = 2401 tests passed
```

- GRE/IPsec 각각 off/on, 설정 보존, 문서 로드와 CLI 왕복.
- VPN off에서 ISP에 양쪽 LAN 일반 경로를 추가하면 GRE/ESP 없이 ping 성공(TTL 125).
- 같은 일반 경로가 있어도 IPsec on + 잘못된 키는 폐기하며 평문 우회하지 않음.
- 한쪽만 off이면 복원하지 않음. 모드가 다른 경우 기존 모드로 계속 송신하지 않음.
- mode 전환이 SA sequence를 되돌리지 않음. 잘못된 모드/장비 dispatch는 문서 유지·거부.
- 화면의 선택 값, 상태, 미설정 안내, 기존 문서 표시를 검증.

실제 Chrome의 새 IPsec 예시 탭에서 R1 선택 → 오른쪽 VPN 라디오를 확인했다.

```text
IPsec(기존 설정에 따라 선택됨) → 사용 안 함 클릭
VPN disabled, 일반 물리 경로 필요 안내
PC_A> ping -n 1 192.168.2.10
Request timed out. / Received = 0, Lost = 1 (100% loss)

R1에서 IPsec 다시 클릭
VPN configured → PC_A ping 실행 → VPN active 송신 1 · 수신 1
Reply from 192.168.2.10: bytes=32 time=12ms TTL=126
Received = 1, Lost = 0 (0% loss)
```

GRE off/on, 양 끝 모드 일치, 일반 경로를 추가한 평문 성공은 자동 통합 테스트로 검증했다.

`pnpm check:secrets`는 추적 파일 659개 통과. 신규 미추적 파일 23개도 같은 비밀값 검사 함수로 별도 통과.
문서 상대 링크와 `git diff --check` 통과.
Vite chunk 크기 안내는 기존처럼 경고이며 빌드는 성공했다.

## 7. 남은 일과 제한

- 선택만으로 GRE/IPsec 상세 설정이나 일반 라우팅 경로를 자동 생성하지 않는다. 없는 설정은 UI가 안내한다.
- 양 끝 Router에서 같은 모드를 선택하고 주소·경로/정책을 맞춰야 한다.
- 기존 VPN 예시는 ISP에 일반 LAN 경로가 없으므로 off에서 ping이 실패한다. 일반 통신 비교용 경로는 안내서에 별도 제공했다.
- IPsec은 여전히 실제 암호화/IKE 없는 교육용 모델이다.
- 기존 작업과 이번 선택 UI 모두 커밋/push/PR 전이다.
