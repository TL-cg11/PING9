## 2. 진행 방식

1. Switch 콘솔의 동작을 공개 인터페이스(`createSimulator().console(id).exec(line)`)로 확인하는 테스트를 먼저 썼다. 프롬프트가 `SW1>`에서 바뀌지 않아 실패하는 것을 확인했다.
2. 기본 명령어 여섯 개를 명령 정의로 만들었다.
3. `console.ts`의 `DEFINITIONS_BY_KIND`에 `switch: SWITCH_COMMANDS`를 넣었다.

### 명령어와 모드

| 명령어 | 쓸 수 있는 모드 | 결과 |
|---|---|---|
| `enable` | user | privileged로 |
| `disable` | privileged | user로 |
| `configure terminal` | privileged | config로 |
| `exit` | 모든 모드 | 한 단계 위로 (user에서는 그대로, privileged → user, config → privileged, config-if·config-vlan → config) |
| `end` | privileged, config, config-if, config-vlan | privileged로 |
| `hostname <이름>` | config | `device/rename`을 dispatch |

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 기본 명령어를 `cli/switch`가 아니라 `cli/ios/base-commands.ts`에 둠 | Router도 똑같은 명령이 필요하다. `devices`를 지정하지 않아 모든 장비에 쓰인다 | Switch 폴더에 두고 Router가 복사 |
| user 모드의 `exit`는 아무것도 하지 않음 | 실제 장비는 접속을 끊지만 여기에는 끊을 접속이 없다 | 터미널 창을 닫는 신호를 화면에 보냄 |
| `hostname`의 이름 검증을 CLI에서 하지 않음 | 검증은 reducer의 `device/rename`이 한다 (AD-3: 구성 변경의 규칙은 한 곳). CLI는 오류를 그대로 보여 준다 | CLI에서 `checkDeviceName`을 먼저 부름 |

## 6. 계획과 달라진 점

- **기본 명령어를 장비 공통(`cli/ios`)에 두었다.** 계획은 "Switch 기본 명령어"라고 적었고 Router는 E4에서 "같은 명령 트리를 이어 쓴다"고 했다. 공통 폴더에 두면 Router 담당이 다시 만들지 않는다.
- **`hostname`은 아직 이름을 바꾸지 못한다.** 선행인 `device/rename` 처리기(T1.3.x, 다른 담당)가 없다.

## 7. 남은 일과 다음 Task에 전할 것

- **`device/rename` 처리기를 만드는 사람에게**: 처리기가 들어오면 `hostname`은 고칠 것 없이 동작한다. 그때 `switch-console.test.ts`의 "처리기가 없는 동안은 그 오류가 그대로 나온다" 테스트를 "이름이 바뀌고 프롬프트가 `CORE(config)#`가 된다"로 바꾼다.
- **Router 담당에게**: `ROUTER_COMMANDS = [...BASE_COMMANDS, ...]`로 시작하면 위 표의 명령이 그대로 들어온다.
- `interface`, `vlan`으로 들어가는 하위 모드는 T3.3.1과 T5.1.1에서 넣는다. `exit`와 `end`는 그 모드에서도 이미 동작한다.
