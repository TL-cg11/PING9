## 2. 진행 방식

ICMP 타입과 Trace 스키마에 destination-unreachable/time-exceeded 및 원래 요청의 IP·sequence 인용을 추가했다. Router는 정상 귀환 경로로 오류를 보내며 PC/Router는 자기 IP와 인용된 회차가 맞을 때 받는다. Runtime은 이를 echo 성공과 구분해 회차 결과로 만든다.

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 오류도 라우팅·ARP를 거쳐 실제 전송 | 귀환 경로의 중요성을 검증 | 원격 실패를 바로 출발 PC에 표시 |
| 오류·브로드캐스트·특수 주소에는 오류 생성 억제 | 오류 폭주 방지 | 폐기마다 무조건 응답 |
| Windows 오류 수신도 Received로 집계 | 기존 Windows 출력 규칙과 일치 | Received를 echo 성공으로만 해석 |

## 3. 변경 내용

shared의 ICMP 타입·스키마·이벤트 코드, Router 오류 생성과 TTL=0 폐기 기록, PC 오류 수신, Runtime 회차 판정, Windows/Linux/Router 출력과 통합 검사를 추가했다.


가는 경로 누락의 출발 PC 오류 수신, 돌아오는 경로 누락의 원래 PC timeout, 순환 경로 TTL 소진, 오류 패킷 자체의 순환에서 추가 오류를 만들지 않는 것, Linux 출력, 브로드캐스트·특수 주소 응답 억제를 검사했다. 경로 복구 후 성공도 확인했다.

## 5. 추정과 실제

추정 1.5인일, 실제 인일은 별도 집계하지 않았다.

## 6. 계획과 달라진 점

인용 정보는 이 시뮬레이터에 필요한 원래 IP·회차로 표현하며 실제 바이트 전체가 아니다. ARP 다음 홉이 응답하지 않는 경우에는 기존 ARP_TIMEOUT 기록과 timeout 결과를 유지하고 별도 ICMP host-unreachable은 만들지 않는다. 문서 구성 스키마 버전은 바꾸지 않았다. 기존 Trace의 echo 타입도 계속 허용한다.

## 7. 남은 일과 다음 Task에 전할 것

Trace의 NO_ROUTE/TTL_EXPIRED params에는 원인 Router 참조가 들어 있다. 상세 Trace 뷰어는 별도 화면 작업이다. 사용자 실습 안내와 CLI 구성에서 시작하는 최종 검증을 이어 기록한다. 원격 푸시는 하지 않았다.
