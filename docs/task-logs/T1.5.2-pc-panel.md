## 2. 진행 방식

1. 속성 패널(`inspector.tsx`)에 PC일 때만 `PcSettings` 구역을 넣었다. Switch 구역을 `switch-inspector.tsx`로 뺀 것과 같은 방식이다.
2. 판단(칸별 형식 검사, 같은 값인지, Command 만들기, 오류를 붙일 칸, 적용 한 번의 결과)은 `format/pc-address.ts`의 순수 함수로 뺐다. 적용은 실제 `Simulator`의 `dispatch`로 테스트했다.
3. 화면은 상태가 없는 `PcSettingsView`와 입력 중인 값을 드는 `PcSettings`로 나눴다. `PcSettingsView`는 `renderToString`으로 오류·경고 위치를 확인했다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| "적용" 버튼과 Enter(폼 제출)로만 dispatch | 세 칸을 한 Command에 담는다. 칸을 벗어날 때마다 보내면 IP만 쓰고 마스크 칸으로 가는 순간 `PC_ADDRESS_INCOMPLETE`가 뜬다 | 칸을 벗어날 때마다 저장 |
| 화면에서도 `shared`의 `checkIpv4`, `checkMask`로 칸마다 형식을 본다 | 여러 칸의 형식 오류를 한 번에, 정확한 칸에 보인다. CLI 해석기와 같은 함수라 규칙이 갈라지지 않는다 (AD-3) | reducer 오류만 보이기 (한 번에 하나, 칸 추측 필요) |
| 지금 구성과 같은 값이면 보내지 않는다 | reducer는 같은 값도 받아 `docVersion`을 올린다 (T1.5.1) | 늘 보내기 |
| 중복 IP 경고는 그 적용의 결과로만 보인다. 값을 바꿔 다시 적용하거나 다른 장비를 고르면 사라진다. 같은 값으로 다시 적용하면 남는다 | 화면이 중복을 직접 계산하지 않는다 (AD-7) | `PcView`에 중복 정보 추가 (`shared` 변경) |
| 구성이 바깥(콘솔의 `ipconfig`)에서 바뀌면 입력 중인 값과 칸 오류를 새 구성으로 바꾼다. 장비가 바뀌면 `key`로 새로 만든다 | 패널과 콘솔이 같은 값을 보인다 | `key`에 구성 값까지 넣기 (적용 직후 경고가 바로 사라짐) |
| 적용 버튼 아래에 결과 한 줄: "✓ 적용했어요"(초록), "바뀐 값이 없어요"(회색). 칸을 다시 고치면 사라진다 | 수동 확인에서 "바뀌었다는 표시가 더 분명했으면" 하는 의견이 나왔다 | 표시 없음 (캔버스의 IP 글자만 바뀜) |
| 중복 IP는 계획(FR-27)대로 설정하고 경고만 한다. 대신 문구에 결과를 덧붙이고 패널에서는 앞에 ⚠를 붙인다 | 수동 확인에서 "중복이면 안 바뀌어야 하지 않나"는 의견이 나왔다. 막는 것은 요구사항 변경이라 팀 합의가 필요하다. 실제 장비도 막지 않고, 두 PC의 IP를 맞바꿀 때 잠깐 중복이 생긴다 | 중복이면 거부 (FR-27, T1.5.1 변경) |
| DOM 테스트 도구(`@testing-library/react`, `jsdom`)를 넣지 않았다 | 판단이 순수 함수에 있어 충분하다. 의존성과 CI를 바꾸지 않는다 | 클릭·입력을 흉내 내는 컴포넌트 테스트 |

오류를 붙일 칸:

| 오류 코드 | 칸 |
|---|---|
| `PC_ADDRESS_INCOMPLETE` | `missing`이 가리키는 칸 |
| `IP_IS_NETWORK_ADDRESS`, `IP_IS_BROADCAST_ADDRESS` | IP |
| `GATEWAY_NOT_IN_NETWORK` | 게이트웨이 |
| `INVALID_MASK` | 마스크 |
| `INVALID_IPV4`, `RESERVED_IPV4` | 값이 IP 칸과 같으면 IP, 아니면 게이트웨이 (reducer가 IP를 먼저 봄) |
