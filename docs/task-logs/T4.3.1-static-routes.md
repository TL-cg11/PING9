## 2. 진행 방식

공통 checkStaticRoute를 직접 명령과 문서 불러오기에 함께 쓴다. reducer는 구성만 바꾼다. routingTable은 직접 연결 경로로 다음 홉을 해석해 실제 출력 포트를 붙인다. 정적 경로를 통한 재귀 해석은 하지 않는다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 목적지 주소와 마스크의 네트워크 정렬 검사 | 호스트 비트가 있는 잘못된 경로 방지 | 조용히 다른 네트워크로 변경 |
| 같은 네트워크·마스크·다음 홉 재추가는 멱등 | CLI 구성 재입력 지원 | 중복 항목 생성 |
| 삭제는 정확한 세 필드로 식별, 없으면 오류 | 다른 다음 홉 설정 보존 | 같은 네트워크의 모든 경로 삭제 |
| 꺼진 포트의 자기 IP도 거부 | 정적 설정 검증 일관성 | 현재 켜진 IP만 확인 |

## 6. 계획과 달라진 점

- 파일 불러오기에서도 네트워크 정렬과 자기 IP 규칙을 적용한다. 이전에 허용됐던 해당 잘못된 구성은 이제 거부된다.
- 인터페이스 IP를 기존 다음 홉과 같게 바꾸는 것도 문서 검증에서 거부한다. 먼저 해당 경로를 삭제해야 한다.
- 다음 홉이 직접 연결망의 네트워크/브로드캐스트 주소이면 활성화하지 않는다. 도달 불가 설정은 저장할 수 있다.
- ip route 추가로 공유 접두사가 생겨 no ip address의 모드 오류가 가려지는 문제가 드러났다. 현재 모드에서 키워드가 불일치하고 다른 모드에서 완전히 일치할 때만 모드 오류로 판정한다. 기존 축약·도움말 검사도 통과했다.
