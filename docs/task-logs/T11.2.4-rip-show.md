## 1. 목표와 완료 기준

- [x] `show ip protocols`: RIP 상태를 실제 IOS와 같은 명령어로 본다. 출력은 PING9에서 참인 줄만
- [x] `show ip route rip`, `show ip route connected`, `show ip route static`: 그 출처만
- [x] `show ip route`의 줄이 출처와 상관없이 네트워크 주소 순
- [x] 공통 완료 조건: lint, 타입 검사, 단위 테스트, 빌드 (4절). 리뷰는 PR에서

`show ip route`의 `R` 줄은 T11.1.1~T11.2.3에서 이미 나왔다.

## 2. 진행 방식

1. 설계안(팀 합의 전)의 결정 6가지를 사용자가 모두 추천대로 정했다.
2. `show ip protocols`(`cli/router/rip-show.ts`): 실제 IOS 출력 가운데 PING9에서 참인 줄만 남겼다. 값은 RIP 구성과 Runtime의 라우팅 테이블에서 계산한다. 새 Runtime 값은 더하지 않았다.
3. `show ip route`: 표 만들기를 함수 하나로 모으고, 주소 순으로 정렬하고, 출처별 명령 세 개를 더했다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 타이머 줄은 `Sending updates when the topology changes (PING9 does not use timers)`로 바꾸고 180/240 줄은 뺌 | 실제처럼 30초를 보이면 학생이 30초를 기다리거나 `next due in`이 바뀌지 않는 것을 이상하게 본다. PING9는 설정이 바뀔 때 교환한다 (T11.2.3) | 실제 값 그대로 |
| `Last Update` 대신 `Routes` (그 이웃에게서 배운 경로 수) | 실제 시각이 없다. 배운 경로 수가 실습에 더 쓸모 있다 | `Last Update`에 `-` |
| filter list, Redistributing, Maximum path, Triggered RIP, Key-chain 칸은 뺌 | 기능이 없다 | 기본값으로 채움 |
| 보내는 인터페이스 = 켜져 있고 IP의 클래스풀 네트워크가 `network`에 있으며 passive가 아님 | `RipModule`(T11.2.2)이 보내는 인터페이스와 같다 | |
| `show ip route` 주소 순 (같은 네트워크는 긴 마스크, 다음 홉 순) | 실제 IOS와 같다. 출처별로 모으면 같은 대역의 줄이 떨어진다 | 출처별로 모음 (지금까지) |
| `show ip rip database`, `debug ip rip`은 뺌 | `database`는 `show ip route rip`과 거의 같다. `debug`는 실시간 로그라 "한 번에 계산" 모델과 맞지 않는다 | 함께 넣음 |

출력 예 (Router 3대 실습의 R1, GI0/2를 passive로 둔 경우):

```text
R1# show ip protocols
Routing Protocol is "rip"
  Sending updates when the topology changes (PING9 does not use timers)
  Default version control: send version 2, receive version 2
    Interface           Send  Recv
    GigabitEthernet0/0  2     2
    GigabitEthernet0/1  2     2
  Automatic network summarization is not in effect
  Routing for Networks:
    10.0.0.0
  Passive Interface(s):
    GigabitEthernet0/2
  Routing Information Sources:
    Gateway    Distance  Routes
    10.0.12.2  120       2
  Distance: (default is 120)
```
