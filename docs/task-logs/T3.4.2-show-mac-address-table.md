- [x] 출력의 열 구성과 글은 직접 설계한 것이다 (다른 제품의 문구를 복제하지 않음).
- [ ] 실제로 배운 주소가 나온다 — 프레임이 흘러야 한다 (kernel 연결, 설계 9절의 18번). 지금은 늘 머리줄만 나온다.
- [x] lint, 타입 검사, 단위 테스트, 빌드가 통과한다.
- [ ] 다른 사람이 Pull Request를 검토했다.

## 2. 진행 방식

`show-commands.test.ts`에 테스트 3개를 먼저 쓰고(3개 실패) 구현했다.

- `macAddressTableLines(entries)`가 줄을 만든다. 줄 맞춤은 T5.3.2의 `tableLines`다.
- 명령어는 화면과 같은 계산(`computeViews`)에서 `macTable`을 읽는다. kernel이 `DeviceView.macTable`을 채우면 이 명령어는 고치지 않아도 값이 나온다.

```text
SW1# show mac address-table
VLAN  MAC address        Port
10    02:00:00:00:01:00  Fa0/1
```

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 값을 `switchForward`의 테이블이 아니라 `DeviceView.macTable`에서 읽음 | 화면의 테이블과 같은 값이어야 한다 (AD-7). 실행 중 상태를 누가 들고 있을지는 kernel이 정한다 | 명령어가 테이블을 직접 들고 있음 |
| 줄을 만드는 함수를 따로 내보냄 | 지금은 테이블이 비어 있어 명령어로는 줄의 모양을 확인할 수 없다 | 머리줄만 테스트 |

### 브라우저에서의 확인 (T3.3.1 ~ T3.4.2 전체)

Chromium, 1440×860, `http://localhost:5173`, SW1의 터미널. 입력한 줄과 화면에 나온 것:

```text
SW1> enable
SW1# conf t
SW1(config)# vlan 30
SW1(config-vlan)# name LAB
SW1(config-vlan)# int fa0/3
SW1(config-if)# sw acc vlan 30
SW1(config-if)# int f0/4
SW1(config-if)# sw acc vlan 40
VLAN 40이 없어서 새로 만들었어요
SW1(config-if)# shutdown
SW1(config-if)# vlan 5000
                      ^
VLAN 번호는 1~4094여야 해요: 5000
SW1(config-if)# end
SW1# sh int tr
Port   Status  Allowed VLANs
Fa0/8  up      10,20
SW1# sh run
hostname SW1
!
vlan 10
 name SALES
…
interface FastEthernet0/4
 switchport access vlan 40
 shutdown
!
interface FastEthernet0/8
 switchport mode trunk
 switchport trunk allowed vlan 10,20
!
end
SW1# sh mac add
VLAN  MAC address  Port
```

- 속성 패널(SW1): VLAN 목록에 `VLAN 30 LAB Fa0/3`, `VLAN 40 VLAN0040 Fa0/4`가 바로 나오고, 포트 줄마다 `VLAN n` 표시, Fa0/8은 `trunk`와 `허용 10, 20`.
- 캔버스: PC 쪽 링크 4개에 `VLAN 10`·`VLAN 20` 표시, SW1-SW2는 굵은 보라색 선과 `trunk` 표시, 양 끝에 `허용 10, 20`·`허용 20`.
- 콘솔 오류 없음 (개발 서버를 새로 띄운 뒤).
- 확인하지 않은 것: 다른 화면 크기, Chromium이 아닌 브라우저, 끈 포트(Fa0/4)의 상태 점 색.
