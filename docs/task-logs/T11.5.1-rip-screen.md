## 2. 진행 방식

1. 설계안(팀 합의 전)의 결정 7가지를 사용자가 정했다. 결정 5·6은 추천과 다르게 골랐다 (아래 표).
2. 시안 두 장(패널, 물고기)을 먼저 보이고 확정했다. 엔진은 고치지 않았다. 라우팅 테이블(`Snapshot.views`), 교환 요약(`kind: "rip"`), 바뀐 경로(`getRouteChanges`)가 이미 있다.
3. 물고기 그림 8장(보라·빨강 × 걷기 2, 서기, 놓침)은 파란 그림에서 물고기 픽셀만 색을 바꿔 만들었다. 물고기 픽셀은 파란 그림과 초록 그림(T6.1.2에서 같은 방법으로 만든 것)이 다른 곳이다. 펭귄은 그대로다.
4. 사각형 RIP 실습(`fourRouterRipDocument`)을 개발 서버에서 열어 R1–R2 케이블 삭제, 패널, 재생, 넓은 패널을 눈으로 확인했다 (4절).

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 1. RIP 재생은 패널의 `▶ 재생`을 누를 때만 | 교환은 설정 명령마다 돈다. 저절로 재생하면 `network`를 칠 때마다 펭귄이 캔버스를 덮는다 | 바뀐 경로가 있을 때만 저절로 |
| 2. AD/metric은 패널 안쪽 폭이 310px 이상이면 줄 끝에, 좁으면 목적지 아래 줄에 (container query) | 지금 패널(270px)에는 한 줄에 다 들어가지 않는다 | 칸을 빼고 `show ip route`로만 |
| 3. 표 줄에 `새로`·`바뀜`, 경로 교환 묶음에 이전(취소선) → 이후, 사라진 경로는 묶음에만 | "끊었더니 무엇이 바뀌었나"가 Story 11.3의 학습 목표다 | 표시 없음 |
| 4. 이벤트 목록의 "경로 교환 #n"은 넣지 않음 | 이벤트 목록(Story 1.9)이 아직 없다 | — |
| 5. ICMP 오류(`time-exceeded`, `destination-unreachable`)는 빨간 물고기, 머리 위 글자 없음 | 사용자 결정. 설계안 추천은 노란 물고기에 `×` | 노랑 + `×`, 지금처럼 파랑 |
| 6. RIP는 보라 물고기, Request `R?`, Response `R!` | 사용자 결정. ARP의 `?`·`!`와 같은 방식. 설계안 추천은 `R` 하나 | `R` 하나 |
| 7. `main`에서 시작 | #41~#47이 모두 `main`에 들어왔다. 검토 중 #48, #50, #51이 병합되어 그 위로 다시 올렸다(`app.tsx`·`inspector.tsx`의 props, README 목록이 겹쳐 양쪽을 살림) | #45 브랜치 |
| 교환 재생은 첫 시도만 남기지 않는다 (`exchangeTimeline`) | ping 재생의 `firstAttempt`는 긴 틈에서 자른다. 교환에서는 30ms 뒤의 정기 갱신이 잘린다 | `previewTimeline`을 그대로 |
| 교환 재생의 열쇠는 `"rip"` 하나 | ping 재생(장비마다)과 따로 돈다. 다시 누르면 처음부터 | 누른 Router의 ID |
| 놓친 단계에서 돌려보내는 펭귄(빨간 물고기)은 놓침 그림이 사라진 뒤(`FALL_MS`)에 출발 | 화면 확인에서 traceroute 첫 hop의 놓침 그림이 빨간 물고기가 돌아오는 동안 남았다. 놓침과 time-exceeded가 같은 단계라 동시에 시작했고, 다음 단계가 없어 그림이 사라지지 않았다. T11.4.1부터 있던 문제 | 놓침과 동시에 출발하고 그림만 지움 |
| 스크린리더 이름: "ICMP 오류 알림", "RIP 요청", "RIP 응답" | 놓침 그림의 "…을 잃어버림"과 조사가 맞는다 | "RIP 경로 정보" |

| 펭귄 층 | 보라 물고기와 `R?`, 빨간 물고기와 글자 없음, 스크린리더 이름 |

- R1–R2 케이블 삭제 뒤 R1 패널이 시안 1과 같다

## 6. 계획과 달라진 점

- 계획(04 문서 4.9절)에는 E11의 Task 분해가 없다. `T11.5.1`은 이 작업에서 정한 ID다.

- 돌아오는 ICMP 오류를 따로 그리는 것은 E11 설계안에 없던 것이다. traceroute(T11.4.1)에서 필요해 더했다.

## 7. 남은 일과 다음 Task에 전할 것

- 이벤트 목록(Story 1.9)을 만드는 사람: 교환 요약은 `Snapshot.traces`의 `kind: "rip"`(늘 하나), 바뀐 경로는 `Simulator.getRouteChanges(traceId)`. 패널과 같은 값을 쓰면 된다.
- 실제 RIP는 30초마다 보내고 끊김을 180초 뒤에 알아채기도 한다. PING9는 설정이 바뀔 때 교환을 한 번 돌려 바로 수렴한다. 화면에 이 차이를 알리는 문구는 아직 없다.
- 빨간 물고기는 색으로만 구별한다 (결정 5). 빨강·파랑을 구별하기 어려운 사용자를 위해 글자를 붙일지는 접근성 점검 때 다시 본다 (NFR-12).
- 사각형 예시를 화면에서 여는 메뉴는 아직 없다 (E7).
