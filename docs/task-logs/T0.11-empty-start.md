## 1. 목표와 완료 기준

계획에 없는 Task라 완료 기준을 새로 정했다. 지금까지는 앱을 열면 예시 문서(`twoSwitchVlanDocument`: PC 4대, Switch 2대, 케이블 5개)가 이미 놓여 있었다. 장비 배치(T1.3.2)와 케이블 연결(T1.4.2)이 들어와서 사용자가 직접 만들 수 있으므로, 처음에는 아무것도 없게 한다.

- [x] 앱을 열면 캔버스에 장비와 케이블이 하나도 없다. 장비 수 표시는 "장비 0 / 50"
- [x] 빈 상태에서 왼쪽 목록의 장비를 끌어다 놓으면 배치된다
- [x] 예시 문서(`@ping9/shared/examples`)는 그대로 둔다. 테스트가 쓴다
- [x] lint, 타입 검사, 단위 테스트, 빌드 (`pnpm check`)
- [ ] 리뷰 — 팀원 검토 없이 병합했다 (6절)

## 2. 진행 방식

1. 예시 문서가 어디서 들어오는지 찾았다. 테스트가 아닌 코드에서 `@ping9/shared/examples`를 가져오는 곳은 `apps/web/src/simulator.ts` 한 곳이고, 모듈을 읽을 때 `simulator.load(twoSwitchVlanDocument)`를 한 번 부른다.
2. `app.test.tsx`의 첫 테스트를 "처음 화면에는 배치된 장비와 케이블이 없다"로 먼저 바꾸고 실패하는 것을 봤다.
3. `simulator.ts`에서 `load` 호출과 import를 지웠다. `createSimulator()`는 `EMPTY_DOCUMENT`로 시작하므로 따로 빈 문서를 넣지 않는다.
4. 상단 막대의 이름 "VLAN 실습 1"을 "새 토폴로지"로 바꿨다.
5. 로컬 개발 서버에서 빈 화면과 장비 배치를 확인했다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| `load` 호출을 지운다 | engine이 이미 `EMPTY_DOCUMENT`로 시작한다. 같은 일을 두 번 하는 코드를 남기지 않는다 | `simulator.load(EMPTY_DOCUMENT)`를 부른다 |
| 예시 문서 파일은 건드리지 않는다 | engine과 web의 테스트 여러 개가 `twoSwitchVlanDocument`를 쓴다. 화면이 처음에 불러오지 않을 뿐이다 | 예시 문서를 지운다 |
| 이름을 "새 토폴로지"로 바꾼다 | "VLAN 실습 1"은 지운 예시의 이름이다. 빈 캔버스에 남으면 맞지 않는다. 이름은 서버가 생길 때까지 고정 값이다 | 이름을 그대로 둔다 |
| "꺼진 버튼 5개" 테스트를 상단 막대 안으로 좁히고, 케이블 도구 테스트를 따로 둔다 | 장비가 2대보다 적으면 케이블 도구가 꺼진다(T1.4.2의 기존 동작). 빈 화면에서는 꺼진 버튼이 6개라 화면 전체로 세면 뜻이 섞인다 | 숫자만 6으로 고친다 |
