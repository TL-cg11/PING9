## 1. 목표와 완료 기준

ping 회차를 하나씩 보이는 중에 Ctrl+C를 누르면 멈춰야 한다 ([PR #37](https://github.com/TL-cg11/PING9/pull/37)). 한글 입력 상태에서는 멈추지 않았다.

- [x] 한글 입력 상태에서 Ctrl+C를 누르면 ping이 멈추고 `^C`가 찍힌다
- [x] 영문 입력 상태, Ctrl 없는 c, macOS의 Cmd+C(복사)는 지금과 같다
- [x] 공통 완료 조건: lint, 타입 검사, 단위 테스트, 빌드 (4절). 리뷰는 PR에서

## 2. 진행 방식

1. 개발 서버의 사본을 브라우저 자동화(Playwright, 저장소에 넣지 않음)로 열어 PC1에서 `ping 10.0.10.3`을 실행하고, 회차가 나오는 중에 Ctrl+C를 눌렀다.
2. 영문 입력 상태(`key: "c"`)는 바로 멈췄다. 한글 입력 상태와 같은 키 입력(`key: "ㅊ"`, `code: "KeyC"`)은 멈추지 않고 남은 회차가 모두 나왔다.
3. 원인: `keyAction`이 눌린 글자(`event.key`)가 `c`·`C`일 때만 Ctrl+C로 봤다. 한글 입력 상태에서는 같은 키의 글자가 `ㅊ`다.
4. 수정: 키 자리(`event.code`)가 `KeyC`이면 Ctrl+C로 본다. 글자로 보던 기존 판단도 남겼다.
5. 같은 브라우저 재현으로 한글 입력 상태에서도 바로 `^C`가 찍히고 멈추는 것을 확인했다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 키 자리(`KeyC`)와 글자(`c`·`C`)를 모두 받음 | 키 자리는 입력 언어와 상관없다. 글자 판단은 `code`를 주지 않는 기존 호출과 테스트를 위해 남긴다 | 키 자리만 |
| 조합 중(`composing`)이면 지금처럼 받지 않음 | 조합을 끝내는 키 입력을 명령으로 읽지 않는 규칙(T3.2.3)을 그대로 둔다. ping 중에는 입력란이 비어 있어 조합 중일 일이 없다 | 조합 중에도 멈춤 |
