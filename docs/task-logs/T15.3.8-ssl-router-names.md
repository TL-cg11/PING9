## 1. 목표와 완료 기준

- [x] PC_A → R1 → R2 → R3 → PC_B 이름으로 통일.
- [x] R3를 VPN 서버로 표시하고 가이드 설정 대상·케이블·경로 설명 일치.
- [x] 가이드·가져오기 JSON·로컬 ?lab=ssl 예제의 이름 일치.
- [x] 기존 SSL 접속 테스트와 웹 이벤트/저장 테스트 통과.
- [ ] 팀원 리뷰·PR (이번 요청 범위 밖).

## 2. 진행 방식

기존 미커밋 작업을 보존하고 새 작업 브랜치를 만들었다. 이전 VPN 서버 R1은 R3로, 이전 중간 ISP는 R1으로 동시 치환해 이름이 뒤섞이지 않도록 했다. 장비 UUID·케이블 연결·IP·정적 경로·VPN 프로필 값은 보존했다. 빈 캔버스에서는 Router를 순서대로 추가하면 R1/R2/R3 기본 이름을 그대로 쓰도록 안내를 단순화했다.

```text

  Test Files 1 passed (1)
  Tests 23 passed (23)
pnpm --filter @ping9/web exec vitest run src/ssl-vpn-session.test.tsx
```

가져오기 JSON의 이름 배열 PC_A/R1/R2/R3/PC_B, 가이드와 JSON의 PC_A/R3 config 일치, 로컬 예제 R1/R3 표시 이름을 별도 확인했다. pnpm typecheck도 전체 패키지에서 통과했다. 변경 파일의 상대 링크·비밀값과 git diff --check는 오류가 없었다. 전체 빌드는 이름 변경만 있어 반복하지 않았다. 수동 브라우저 조작은 하지 않았다.

## 5. 추정과 실제

인일 추정은 하지 않았다. 사용자 표시 이름과 문서·예제 동기화 작업이다.

## 6. 계획과 달라진 점

공식 계획과 과거 작업 기록은 변경하지 않았다. 현재 SSL 실습 이름만 사용자 요청대로 통일한다.

## 7. 남은 일과 다음 Task에 전할 것

- 이미 사용자가 배치한 캔버스는 자동 변경하지 않는다. 직접 이름을 바꿀 때 기존 서버 R1→R3를 먼저 적용한 뒤 ISP→R1로 바꾸면 중복을 피할 수 있다.
- 기존 IP·경로와 OFFICE 프로필은 그대로다.
- 커밋·push·PR은 요청받지 않아 하지 않았다.
