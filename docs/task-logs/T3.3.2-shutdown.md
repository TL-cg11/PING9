## 2. 진행 방식

`interface-admin.test.ts`를 먼저 쓰고 17개 중 16개가 실패하는 것을 확인한 뒤 구현했다.

1. `switch-common.ts`에 포트 이름 확인(`checkSwitchPort`)과 포트 설정 일부 바꾸기(`withSwitchPort`)를 더했다. 뒤의 `switchport/*` 처리기도 이것을 쓴다.
2. `interface-admin.ts`에 처리기를 만들고 `reducer.ts`에 한 줄을 더했다.
3. `INTERFACE_COMMANDS`에 `shutdown`과 `no shutdown`을 더했다.

포트 상태 계산(`views.ts`)은 이미 `adminUp`을 보고 있어 고치지 않았다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| reducer는 포트의 전체 이름만 받음 (`fa0/1`은 `UNKNOWN_PORT`) | 줄임은 CLI의 일이다. Document에는 전체 이름만 있다 | reducer가 줄임도 풂 |
| `adminUp`이 참거짓이 아니면 `DOCUMENT_INVALID_SHAPE { path: "adminUp" }`로 거부 | 경계 밖에서 온 값을 참거짓으로 바꿔 읽으면 `"no"`가 켜짐이 된다. 이 경우에 맞는 오류 코드가 없어 형태 오류 코드를 썼다 | 새 오류 코드 (`shared` 변경) |
| Switch가 아닌 장비는 `DEVICE_KIND_MISMATCH` | Router 분기는 Router 담당이 더한다 (설계 5.2절) | Router도 여기서 처리 |
| 켠 포트는 기본값이라 구성에서 항목이 사라짐 | 정규화 규칙(설계 5.3절). `show running-config` 왕복의 기준이다 | `adminUp: true`를 남김 |

## 6. 계획과 달라진 점

- **"꺼진 포트는 송수신하지 않음", 폐기 사유 `IF_DOWN`의 통합 테스트(끄고 ping)는 하지 않았다.** kernel과 ping이 아직 없다. 꺼진 포트로 들어온 프레임을 `IF_DOWN`으로 폐기하는 규칙은 T1.7.3의 전달 규칙에 넣는다.
- **`IF_DOWN`의 한국어 문구는 넣지 않았다.** 폐기 사유의 문구는 T1.9.1의 몫이다 (설계 8.4절).
