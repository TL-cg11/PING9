## 2. 진행 방식

Goorm은 변경 없는 이전 main이었다. 최신 main을 받은 뒤 별도 브랜치를 만들었다. 원본 Codex 작업은 그대로 보존하고, 기존 파일의 full-index patch와 새 파일을 Goorm에 복사했다. 최신 main과 겹친 TCP·메시지·재생·문서 충돌은 다음처럼 처리했다.

- 기존 HTTP/FTP 등 서비스용 TCP flag 문자열/기존 이벤트 코드는 유지.
- SSL 선행 TcpSegment는 sequence·flag 배열·payload를 가진 별도 형태로 유지.
- shared schema는 기존 TcpHeader와 새 TcpSegment를 함께 허용. protocol 6의 추가 검증을 새 형태에 적용해 기존 서비스 trace를 거부하지 않음.
- 새 전송 이벤트는 TCP_SIM_SEGMENT_SENT/RECEIVED로 구분해 기존 TCP_SEGMENT_SENT/RECEIVED 계약을 덮어쓰지 않음.
- 최신 main의 Router/Firewall transportLayersOf와 GRE/ESP 전달 보존 코드를 유지.
- PC의 기존 TransportHost와 새 TcpSegmentHost를 함께 유지. 기존 서비스 handler는 새 flag 배열을 해석하지 않음.
- 기존 서비스 재생 종류와 새 세그먼트의 재생 종류를 함께 유지.

## 3. 변경 내용
