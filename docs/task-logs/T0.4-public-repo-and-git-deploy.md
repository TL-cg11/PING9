## 2. 진행 방식

1. T1.1.3의 Deploy 워크플로에 토큰을 등록하고, 소유자의 커밋과 팀원의 커밋으로 각각 실행했다. 소유자는 배포됐고 팀원은 막혔다.
2. Vercel 문서와 커뮤니티 글을 확인했다. 문서는 "Hobby 플랜은 비공개 저장소의 협업을 지원하지 않는다", "공개 저장소의 협업은 무료"라고 한다. Vercel 커뮤니티의 글에서 Vercel 직원은 Hobby에서 협업을 우회하던 길을 막았다고 답했다.
3. 저장소를 공개로 바꾸기로 했다. 공개 전에 모든 브랜치의 커밋 25개를 비밀값 형태와 넣으면 안 되는 파일로 검사했다. 비밀값은 없었고, 커밋 작성자 정보에 개인 이메일 두 개가 있었다.
4. 이메일을 지우려고 기록을 다시 쓰기로 했으나, 강제 push로는 지워지지 않는다는 것을 확인했다. GitHub이 PR마다 보관하는 `refs/pull/N/head`는 push로 고칠 수 없고, 옛 커밋 전체가 그 참조에 매달려 남는다.
5. 그래서 저장소를 새로 만들었다.
   1. 작업 폴더가 아닌 별도의 복제본에서 작성자·커미터 이메일만 GitHub의 noreply 주소로 바꿨다 (`git filter-branch --env-filter`).
   2. 바꾼 기록이 원래와 같은 내용인지 커밋마다 비교했다 (4절).
   3. 옛 저장소의 이름을 `PING9-archive`로 바꿨다. 비공개 그대로다.
   4. 새 저장소 `TL-cg11/PING9`를 비공개로 만들고 브랜치 넷을 올린 뒤, GitHub에서 이메일을 다시 확인하고 공개로 바꿨다.
   5. 팀원 2명을 쓰기 권한으로 초대했다.
6. GitHub 환경 `production`의 `VERCEL_TOKEN`을 지웠다 (옛 저장소). 새 저장소에는 등록하지 않았다.
7. `deploy.yml`을 없애고 `ci.yml`이 `main`에 들어온 커밋에서도 돌게 했다.
8. Vercel 프로젝트를 옛 저장소에서 끊고 새 저장소에 연결하려 했으나 실패했다 (7절).

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 저장소를 공개로 바꿈 | Vercel이 무료 협업을 허용하는 방법. 팀원의 PR에 미리보기 배포도 생김 | Pro 플랜 (유료), 소유자만 병합 (팀원의 PR에 미리보기가 없고 소유자가 매번 병합해야 함) |

| 새 저장소를 비공개로 만들어 확인한 뒤 공개 | GitHub에 올라간 상태에서 이메일을 한 번 더 확인하기 위함 | 처음부터 공개로 생성 |
| 배포 워크플로를 따로 두지 않고 `ci.yml`에 `main` push를 추가 | 배포 단계를 빼면 두 워크플로가 같은 검사를 함. 파일 하나가 관리하기 쉬움 | `deploy.yml`에서 배포 단계만 지움 |
| `vercel.json`은 그대로 | Git 연동 배포는 기본으로 켜져 있음 | — |
