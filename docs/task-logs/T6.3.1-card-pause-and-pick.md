## 1. 목표와 완료 기준

PR #68의 리뷰에 적은 결함 가운데 두 가지를 고친다. 둘 다 시뮬레이션 모드에서만 생긴다.

**재생이 멈춘 채 남는다.** 펭귄을 누르면 시계를 멈추고 카드를 띄우는데, 카드가 내려가는 길 가운데 닫기 단추와 "같은 펭귄 다시 누르기"만 시계를 다시 돌렸다. 반대로 그 두 길은 사용자가 "멈춤"으로 세운 시계까지 돌렸다.

- [x] 카드가 어느 길로 내려가든 카드가 멈춘 시계는 다시 돈다: 빈 캔버스 누르기, 터미널의 Ctrl+C, 장비 삭제, 가져오기, 다음 재생의 시작, 추적이 바뀜
- [x] 사용자가 "멈춤"으로 세운 시계는 카드를 열었다 닫아도 서 있다
- [x] 보여 줄 이벤트가 없는 펭귄을 누르면 카드도 뜨지 않고 시계도 멈추지 않는다

**펭귄이 장비 누르기를 가로챈다.** T6.4.1부터 펭귄 층이 장비 아이콘 위에 있고, 누를 수 있는 펭귄은 그림 네모 전체(투명한 곳 포함)가 눌렸다. 펭귄과 겹친 장비를 누르면 장비 고르기·끌기·터미널 열기 대신 카드가 떴다. 실패한 ping의 넘어진 펭귄은 다음 재생까지 남는다.

- [x] 펭귄과 장비가 겹친 곳을 누르면 장비가 받는다. 겹치지 않은 곳의 펭귄은 그대로 눌린다
- [x] Firewall의 DROP으로 다 흩어져 보이지 않는 펭귄은 누를 수 없고 Tab 자리도 아니다
- [x] 공통 완료 조건: lint, 타입 검사, 단위 테스트, 빌드 (4절)
- [ ] 리뷰

## 2. 진행 방식

1. 실패하는 테스트를 먼저 썼다.
   - `card-pause.test.ts` 9개: 카드와 시계의 규칙. 가짜 시각을 넣은 실제 시뮬레이션 시계를 쓴다.
   - `packet-card.test.tsx` 1개, `firewall-scene.test.tsx` 1개: 엔진이 만든 실제 추적으로 캔버스를 그려, 누르는 자리의 마크업을 본다.
2. 고치기 전의 동작 그대로(열면 멈춤, 닫으면 무조건 다시 실행, 재생만 남아 있으면 카드를 띄움) `card-pause.ts`를 먼저 만들어 돌렸다. 9개 가운데 4개가 기대한 이유로 실패하고, 캔버스 테스트 2개도 실패했다 (4절).
3. `card-pause.ts`를 고쳤다. `app.tsx`에서 카드를 내리는 길을 하나로 모았다.
4. 펭귄을 누르는 자리를 그림에서 따로 둔 네모(`.penguin-hit`)로 옮기고, 그 네모를 "장비 카드를 뺀 영역"으로 잘랐다.
5. 전체 검사를 돌리고, 개발 서버에서 직접 확인했다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| "카드가 멈춘 시계만 카드가 다시 돌린다"를 `createCardPause`에 모으고, 카드를 내리는 모든 길이 `close()`를 지난다 | 내려가는 길이 여섯 가지가 넘는다. 길마다 `clock.resume()`을 부르면 하나를 빠뜨리거나 사용자의 멈춤을 풀게 된다 | 길마다 `resume()`을 더하기. 카드가 떠 있는 동안 "멈춤" 단추를 막기 |
| 카드를 내릴지는 effect 하나가 정한다: 시계가 돌거나, 그 펭귄의 재생이 지워졌거나, 추적에서 이벤트를 찾을 수 없으면 내린다 (`cardStillShown`) | 재생을 지우는 곳(`setReplays`)이 여러 군데다. 지우는 쪽이 카드를 알 필요가 없다. 추적이 바뀌어 카드만 사라지고 멈춤이 남던 경우도 같이 풀린다 | 재생을 지우는 곳마다 카드를 내리기 |
| 펭귄 층은 그대로 장비 위에 그리고, 누르는 자리만 `clip-path`로 장비 카드(`rect.card`, 80×72)를 뺀다 | 펭귄이 아이콘에 가려지지 않게 한 T6.4.1의 결정을 지킨다. 겹친 곳의 누르기는 아래의 장비가 받으므로 고르기, 끌기, 두 번 눌러 터미널 열기가 고치지 않아도 된다. T6.3.1 기록의 "겹친 순간에는 누르기가 장비로 간다"와 같아진다 | 장비와 겹친 펭귄을 통째로 못 누르게 하기 (장비 옆에 서는 넘어진 펭귄을 누를 수 없게 된다). 펭귄 누르기에서 좌표를 보고 장비 동작을 대신 부르기 (끌기와 두 번 누르기까지 옮겨야 한다). 누르는 층을 장비 아래에 하나 더 두기 (펭귄 층이 매 프레임 두 번 계산된다) |
| 케이블 위의 펭귄은 케이블보다 먼저 눌린다 (그대로 둠) | 펭귄은 케이블 위를 걷는다. 케이블은 펭귄이 없는 곳을 누르면 된다 | 케이블도 빼기 (걷는 펭귄을 누를 곳이 거의 남지 않는다) |
| 다 흩어진(진행 1) DROP 펭귄은 `role="img"`로 그리고 누르는 자리를 두지 않는다 | 보이지 않는 것이 눌리고 Tab에 걸렸다. 그 패킷은 이벤트 탭에서 볼 수 있다 | 흩어진 뒤에도 흐린 그림을 남기기 (장면의 그림을 바꾸는 일이다) |

## 7. 남은 일과 다음 Task에 전할 것

[PR #68](https://github.com/TL-cg11/PING9/pull/68) 리뷰에 적은 것 가운데 이 수정에 넣지 않은 것:

- 카드의 "이벤트 #"이 이벤트 탭의 줄 번호보다 1 작다 (`event.seq`와 `event.seq + 1`).
- 펭귄에 포커스는 가지만 Enter나 Space로 카드를 열 수 없다. 카드가 포커스를 받거나 돌려주지 않고 Esc로 닫히지 않는다.
- 확대·축소 단추나 휠 뒤에 카드 위치가 한 번 늦게 따라온다. 420px보다 큰 카드는 아래가 잘린다.
- Firewall 장면: REJECT의 ICMP 오류를 보내기 전에 ARP가 필요하면 ARP 펭귄이 막힌 것으로 그려진다. FORWARD REJECT와 OUTPUT 정책 DROP이 함께 있으면 말풍선이 OUTPUT 쪽을 보인다.

펭귄을 누르는 자리를 바꿀 때는 `.penguin-hit`만 누르기를 받는다는 것, 그리고 장비 카드의 크기(`CARD_WIDTH`, `CARD_HEIGHT`)가 `rect.card`와 누르는 영역에 함께 쓰인다는 것을 같이 본다.
