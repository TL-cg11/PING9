## 1. 목표와 완료 기준

[T0.12](T0.12-drag-cancel.md)는 새 장비와 이미 놓인 장비 둘 다 왼쪽 장비 목록에 놓으면 취소되게 했다. 써 본 담당자의 판단: 이미 놓인 장비를 목록 쪽으로 끌면 목록이 "놓으면 취소돼요"로 바뀌는데, 놓아도 장비가 캔버스에 그대로 있어서 취소된 것으로 보이지 않는다. 이미 놓인 장비에는 취소 표시가 뜨지 않게 한다.

- [x] 이미 놓인 장비를 장비 목록 위로 끌어도 목록의 안내와 모양이 바뀌지 않는다
- [x] 그 장비는 T0.12 전처럼 캔버스 가장자리에서 멈추고, 놓으면 그 자리로 옮겨진다
- [x] 목록에서 끌어 온 새 장비는 그대로다: 목록에 다시 놓으면 추가되지 않고, 끄는 동안 취소 안내가 보인다
- [x] lint, 타입 검사, 단위 테스트, 빌드 (`pnpm check`)
- [ ] 리뷰 — 팀원 검토 없이 병합했다 (6절)

## 2. 진행 방식

1. `canvas.tsx`에서 옮기던 장비의 취소 처리를 뺐다: 끌기 전 자리(`origin`)와 취소 영역 위인지(`overCancel`)를 끌기 상태에서 지우고, 목록 위에서 제자리에 그리던 것과 놓을 때 옮기지 않던 것을 지웠다.
2. 장비 목록에 알리는 상태를 새 장비를 끄는 동안에만 `armed` / `over`가 되게 했다. 전에는 장비를 옮기는 동안에도 그랬다.
3. 로컬 개발 서버를 브라우저로 열어 두 끌기를 확인했다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 옮기던 장비의 취소를 표시만이 아니라 동작까지 뺀다 | 표시 없이 "목록에 놓으면 제자리로 돌아간다"만 남으면 알 길이 없는 동작이 된다. T0.12 전의 동작으로 되돌린다 | 표시만 지우고 제자리로 돌아가는 동작은 남긴다 |
| 옮기던 장비의 취소는 Esc만 남긴다 | T0.12 전부터 있던 길이다 | 목록에 놓으면 장비를 삭제한다 (삭제는 속성 패널의 버튼과 Delete 키가 있고, 케이블이 있는 장비의 확인을 건너뛰게 된다) |
| 끄는 사이에 지워진 장비는 옮기지 않는 확인은 남긴다 | [T1.3.3](T1.3.3-rename-delete.md)의 검토에서 넣은 것이고 취소 영역과 상관없다 | |
| Delete 키를 막는 조건에서 `dragCancel`을 뺀다 | 이제 `dragCancel`은 새 장비를 끌 때만 바뀌고, 그 조건은 `dragKind`로 이미 본다 | |
