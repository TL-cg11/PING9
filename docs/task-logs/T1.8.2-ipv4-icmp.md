## 2. 진행 방식

1. 기대 결과 `twoPcPingTrace`(shared 예시)의 seq 6~9와 T1.8.1의 `ArpModule`을 기준으로 모듈 모양을 정했다.
2. ARP처럼 장비 종류를 모르는 프로토콜 모듈(`Ipv4Host`)로 만들었다. 장비 모델이 `ArpModule`과 함께 들고 있고, `ctx`는 콜백마다 받는다.
3. 받은 프레임의 입구는 `onFrame` 하나다. 목적지 MAC을 확인한 뒤 ARP면 `ArpModule.onArp`로 넘기고, IPv4면 직접 처리한다.
4. 테스트는 T1.8.1처럼 **진짜 kernel**에 가짜 `transmit`을 붙여 돌렸다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 받는 쪽은 `ICMP` 이벤트 하나만 남기고, L2·L3 이벤트는 폐기할 때만 남긴다 | 예시가 그렇다. 실제 OS도 층마다 기록하지 않는다. 매번 남기면 Trace가 2~3배 길어진다 | 층마다 받음 이벤트 |
| TTL은 장비 모델이 넘긴다 (`Ipv4HostConfig.ttl`) | 이 모듈은 OS를 모른다. Windows 128, Linux 64는 T1.8.3이 고른다 | 모듈이 OS를 보고 정하기 |
| 이 모듈은 받은 응답의 sequence만 모은다 (`repliesReceived`, `startRun`이 비움). 회차의 성공 판정은 하지 않는다 | 판정과 OS별 출력 문구는 ping 명령(T1.8.3)의 일이다 | 모듈이 `outcome`을 정하기 |
| `NO_IP`·`NO_GATEWAY` 폐기는 목적지 MAC이 `UNKNOWN_MAC`인 "보내려던 패킷"을 만들어 기록한다 | `record`에 프레임이 꼭 필요하다. 추적 화면에서 원인을 보기 쉽다 | 프레임 없는 폐기 (shared와 kernel을 고쳐야 함) |
| 다음 홉: 같은 네트워크면 목적지, 아니면 게이트웨이. echo 응답도 같은 규칙 | 실제 호스트의 동작이다. 다른 네트워크에서 온 요청에 게이트웨이가 없으면 응답이 `NO_GATEWAY`로 버려진다 | 응답은 받은 프레임의 출발 MAC으로 바로 보내기 |
| echo 응답은 `arp.send`에 `parentSeq`로 받음 이벤트를 넘긴다 | 예시 seq 8의 부모가 7이다 (T1.8.1 PR #30에 넣은 `parentSeq`) | kernel 기본값 (6이 됨) |
| 자기 IP로 ping은 이번에 뺀다 | 링크를 지나지 않아 Trace 모양이 다르다. T1.8.3에서 정한다 | — |

## 6. 계획과 달라진 점

- **선행 T1.7.2 없이 했다.** 링크 전달은 `ArpModule`의 `transmit`이 그대로 맡는다. 이 모듈은 직접 내보내지 않는다.
- **`NO_IP`·`NO_GATEWAY` 때 프레임을 만든다.** 실제 OS는 패킷을 만들지 않고 경로를 찾는 단계에서 실패한다 (Windows `PING: transmit failed. General failure.`, Linux `ping: connect: Network is unreachable`). 추적 화면에는 "PC1을 떠나지 못한 패킷"으로 보인다.
- **테스트의 가짜 세상을 파일로 꺼내지 않았다** (설계안은 T1.8.1 테스트와 함께 쓰기로 했다). 꺼내면 빌드에 들어가는 파일이 생기고 T1.8.1(PR #30)의 테스트도 고쳐야 한다. 열 줄 남짓이라 이 테스트에 따로 두었다.
- **담당:** 분담안에서는 Router 담당 일이었는데 yysong1249가 했다.

## 7. 남은 일과 다음 Task에 전할 것

- **T1.8.3(PC 모델, `ping`):** PC마다 `ArpModule`과 `Ipv4Host`를 만든다. `addressOf`는 PC 구성의 IP·마스크·게이트웨이, `ttl`은 `osOf`로 고른다 (Windows 128, Linux 64). kernel의 `onFrame`에서 `Ipv4Host.onFrame`을, `onTimer`에서 `ArpModule.onTimer`를 부른다. 회차마다 `startRun()`(과 ARP의 `discardPending()`) 뒤 `sendEcho(ctx, port, targetIp, sequence)`를 부르고, 끝나면 `repliesReceived()`에 그 sequence가 있는지로 성공을 판정한다. 출력의 TTL은 받은 응답 프레임의 값이다.
- **E4(Router):** Router의 IPv4 전달(TTL 줄이기, `TTL_EXPIRED`, `NO_ROUTE`)은 이 모듈에 없다. 지금 이 모듈은 자기 IP가 아닌 패킷을 `NOT_FOR_ME`로 버린다.
- **PR 순서:** 이 브랜치는 T1.8.1 위에 있다. PR #30이 먼저 병합되어야 한다.
