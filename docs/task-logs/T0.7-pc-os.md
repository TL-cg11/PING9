## 1. 목표와 완료 기준

첫 회의에서 정한 목표인데 계획 문서에는 빠져 있다. 계획의 PC 명령어는 Windows식 `ipconfig`와 `ping`뿐이다. 이 Task는 그중 **ping 없이 할 수 있는 부분**이다. ping과 ARP 명령의 OS별 문법은 ping(T1.8.3)과 함께 한다.

- [x] PC 구성에 OS(`windows` / `linux`). 없으면 Windows라 옛 문서와 예시가 그대로 읽힌다
- [x] 설정 패널에서 OS를 바꾸면 콘솔의 명령 목록과 프롬프트가 바뀐다 (`PC1>` / `PC1$`)
- [x] Linux에서 주소와 기본 게이트웨이를 보고 바꾼다: `ip`, `ifconfig`, `route`
- [x] Windows의 `ipconfig`, Linux의 `ip addr add`, 설정 패널이 같은 Command(`pc/set-ip`)로 같은 결과를 낸다 (AD-3)
- [x] CIDR 표시: 캔버스의 PC IP `10.0.0.1/24`, 설정 패널 마스크 칸 아래 `/24`. IP 칸과 마스크 칸에 `/24`로 써도 된다
- [x] lint, 타입 검사, 단위 테스트, 빌드
- [ ] OS별 이글루 그림 (창 모양만 다르게). 아이콘에 OS 클래스(`icon-os-linux`)만 붙어 있고 그림은 같다
- [ ] 리뷰

## 2. 진행 방식

1. OS 칸을 **선택 항목**으로 두었다. 칸이 없으면 Windows로 보아 `schemaVersion`을 올리지 않고, 예시 토폴로지와 기존 테스트를 고치지 않았다. T1.3.1(장비 reducer) 전이라 PC를 만드는 코드가 없어 지금 넣는 것이 가장 싸다.
2. 콘솔은 장비 종류별 명령 목록을 쓰는데, PC일 때만 OS를 한 번 더 보아 Windows 목록(T1.6.1의 것)과 Linux 목록을 고른다. Switch·Router 쪽은 바뀌지 않는다.
3. Linux 명령은 모두 기존 Command(`pc/set-ip`)를 낸다. 주소 검사와 중복 IP 알림은 reducer의 것을 그대로 쓴다.
4. `10.0.0.2/24` 입력은 공용 해석기(`cli/ios`)를 고치지 않고, 해석기에 있는 `customParam`으로 PC 명령 파일 안에서 읽었다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 칸 이름 `os`, 값 `windows` / `linux`, 선택 항목 | 같은 구성의 `ip`, `mask`처럼 짧다. 코드와 명령어에 겹치는 이름이 없다 | 필수 값 + 버전 올림 + migrate (예시와 테스트를 모두 고쳐야 함) |
| OS를 나중에 바꿀 수 있다 (`pc/set-os`) | 실습에서는 PC를 지우고 다시 놓는 것보다 낫다. IP와 링크는 그대로 둔다 | 놓을 때만 고르기 (장비 목록에서 끌어 놓기는 T1.3.2) |
| `device/add`에 `os?` | T1.3.1 reducer가 PC를 만들 때 받는다. T1.3.2에서 장비 목록을 "Windows PC" / "Linux PC"로 나눈다 | 그때 더하기 (공용 Command를 두 번 고침) |
| Linux 프롬프트 `PC1$` | Windows `PC1>`와 짝. 짧다 | `user@PC1:~$` |
| `ip addr`에 `lo`를 보인다, `ifconfig`는 실제 형식 (flags, broadcast) | 실제 출력과 같아야 실습이 된다 | eth0만 |
| `ip addr add`, `ifconfig`로 주소를 바꾸면 새 네트워크 밖의 게이트웨이는 지운다 | 실제 Linux도 주소가 바뀌면 그 주소로 가던 경로가 사라진다. 남기면 reducer가 거부해 주소를 못 바꾼다 | 게이트웨이를 남기고 거부 |
| `ifconfig eth0 <IP>`만 쓰면 지금 마스크를 쓴다. 없으면 "마스크가 빠졌어요" | 클래스 기본 마스크는 요즘 쓰지 않는 규칙이다 | 클래스 기본 마스크 |
| 새 오류 코드 `PC_ADDRESS_NOT_FOUND` | `ip addr del`로 없는 주소를 지우려 함. 기존 코드에 맞는 것이 없다 | 실제 Linux 문구를 글 줄로 (AD-14 위반) |
| Linux도 대소문자를 구분하지 않고, 모르는 명령 문구도 공용 | 공용 해석기를 고쳐야 한다. OS별 ping과 함께 한다 | 이번에 하기 |
| OS 표시는 아이콘으로 (캔버스에 OS 글자 없음). 이름표(`aria-label`)에 OS | 글자 줄이 늘면 링크 선을 끊는 상자(T0.6)를 넘는다. 화면 낭독기는 이름표로 안다 (NFR-12) | 이름 아래 OS 글자 |
| 문서가 바뀌면 열려 있는 콘솔의 프롬프트를 맞춘다 | 콘솔 기록은 닫아도 남아서, OS를 바꿔도 명령을 칠 때까지 옛 프롬프트가 보였다. 이름을 바꿀 때도 같다 | 명령을 칠 때만 |

### Linux 명령

| 입력 | 하는 일 |
|---|---|
| `ip addr`, `ip a`, `ip addr show`, `ip addr show eth0` | 주소 보기 (`lo`와 `eth0`, 링크 상태, MAC, `inet 주소/길이`) |
| `ip addr add <IP>/<길이> dev eth0` | 주소 설정 |
| `ip addr del <IP>/<길이> dev eth0` | 지금 주소와 길이가 같을 때만 지움 |
| `ip addr flush dev eth0` | 주소와 게이트웨이 지움 |
| `ip route add default via <IP>`, `ip route del default` | 기본 게이트웨이 |
| `ifconfig`, `ifconfig eth0` | 실제 `ifconfig` 형식으로 보기 |
| `ifconfig eth0 <IP>[/길이] [netmask <마스크>]` | 주소 설정. `netmask`가 길이보다 앞선다 |
| `route add default gw <IP>`, `route del default` | 기본 게이트웨이 |

## 6. 계획과 달라진 점

- **계획에 없는 Task다.** 첫 회의의 목표가 계획 문서에 빠져 있어 새 ID(T0.7)를 썼다. 계획 문서 본문(02 문서의 PC 명령어 표, 03 문서의 Command 목록)은 팀이 합의한 뒤에 고친다.
- **Command가 하나 늘었다** (`pc/set-os`, 03 문서 3.4절의 MVP 목록에 없음). `device/add`에 `os?`가 붙었다.
- **오류 코드가 하나 늘었다** (`PC_ADDRESS_NOT_FOUND`).
- PC의 MAC 표기는 Windows도 지금처럼 소문자 콜론이다. 실제 Windows 형식(대문자 하이픈)은 부모 SPINE의 규칙과 달라 바꾸지 않았다.

## 7. 남은 일과 다음 Task에 전할 것

- **OS별 이글루 그림:** `device-icons.tsx`의 `Igloo`가 `os`를 받아 창 모양만 바꾼다 (Windows 네 칸 네모 창, Linux 둥근 창과 `$`). 담당자가 그린다.
- **T1.3.1(장비 reducer):** `device/add`의 `os`를 PC 구성에 넣는다. 없으면 넣지 않는다 (Windows).
- **T1.3.2(끌어다 놓기):** 장비 목록의 PC 칸을 "Windows PC" / "Linux PC" 두 칸으로 나누고 `device/add`에 `os`를 싣는다.
- **T1.8.3(PC 모델과 ping):** OS별 `ping` (Windows `-n`, 4회, TTL 128 / Linux `-c`, TTL 64), `arp -a` / `ip neigh`. Linux 대소문자 구분과 OS별 "명령 없음" 문구도 이때 본다. Windows PC에서 `ip addr`는 `ip`가 `ipconfig`의 줄임으로 읽혀 주소 오류가 된다.
- 라우팅 조회(`ip route`, `route -n`, `route print`)는 아직 없다.
