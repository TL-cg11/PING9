## 1. 목표와 완료 기준

- [x] 로컬 폴더가 Git 저장소이고 `https://github.com/TL-cg11/PING9.git`에 연결되어 있다.
- [x] 계획 문서가 저장소에 올라가 팀원이 받을 수 있다.
- [x] Task마다 기록 문서를 남기는 규칙과 템플릿이 있다.
- [x] Vercel 프로젝트가 있고 운영 주소가 열린다.
- [ ] `main`에 push하면 Vercel이 자동으로 배포한다. — Vercel GitHub 앱에 저장소 접근 권한이 없어 실패
- [ ] Vercel 안에 무료 DB가 만들어져 프로젝트에 연결되어 있다. — 약관 동의가 필요해 진행하지 않음

## 2. 진행 방식

1. 폴더와 계획 문서를 읽고, 저장소에 넣을 것과 뺄 것을 나눴다.
2. `git init -b main`, 원격 `origin` 등록. 커밋 전에 토큰·키 형태의 문자열과 `.env` 파일을 검색해 없음을 확인했다.
3. `.gitignore`, `.gitattributes`, `CLAUDE.md`, 루트 `README.md`, `docs/task-logs/`(규칙, 템플릿)를 만들었다.
4. 첫 커밋을 `origin/main`에 push했다.
5. Vercel CLI로 로그인(브라우저 승인) → 프로젝트 `ping9` 생성 → 폴더 연결 → 운영 배포.
6. `vercel git connect`로 GitHub 저장소 연결을 시도했으나 실패했다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 기본 브랜치 `main` | 계획 문서(T1.1.3)가 main 브랜치 보호를 전제로 함 | `master` |
| 줄 끝을 LF로 통일 (`.gitattributes`) | 첫 `git add`에서 파일마다 CRLF 변환 경고가 나옴. OS가 섞이면 의미 없는 diff가 생김 | 각자 `core.autocrlf` 설정에 맡김 |
| `_bmad/config.user.toml`, `.claude/settings.local.json`은 커밋하지 않음 | 파일 머리말이 개인별 설정이라고 밝히고 있음 | 전부 커밋 |
| `docs/project-plan/project-plan.zip`은 커밋하지 않음 | 같은 폴더의 문서를 묶은 사본. 파일은 지우지 않고 로컬에 둠 | 커밋 |
| Vercel 프로젝트 하나, 루트 디렉터리는 저장소 루트, 설정은 `vercel.json` | 화면과 `/api`가 같은 출처여야 함 (AD-12, 쿠키 기반 인증). 설정이 코드로 남아 PR로 검토됨 | web과 api를 Vercel 프로젝트 둘로 분리 |
| 자리표시 화면 `apps/web/index.html` + `outputDirectory: "apps/web"` | 빌드할 앱이 아직 없음. 출력 폴더를 지정하지 않으면 저장소 루트가 그대로 공개되어 계획 문서가 노출됨 | 앱이 생길 때까지 배포 연결을 미룸 |
| DB 후보는 Neon (Vercel Marketplace, 무료 플랜) | 설계가 PostgreSQL + Drizzle. Vercel 문서에 따르면 Vercel Postgres는 없어졌고 Neon으로 옮겨짐 | Supabase (인증·스토리지까지 딸려 옴), Upstash Redis (관계형이 아님) |

## 6. 계획과 달라진 점

이번에 팀이 정한 것으로, 계획 문서 본문은 아직 고치지 않았습니다.

| 항목 | 계획 문서 | 바뀐 내용 | 영향을 받는 곳 |
|---|---|---|---|
| 제품 이름 (00 문서 U4, 미결정) | PacketTracer WEB (임시) | **PING9** | 문서 전체의 이름. 폴더 이름과 BMad 산출물 경로는 그대로 둠 |
| 배포 (03 문서 3.10절, 3.12절) | VM 한 대 + Docker Compose + Caddy | **Vercel** (정적 파일 + Functions) | 3.10절 전체, Story 2.2의 T2.2.1 ~ T2.2.3, T2.8.3의 컨테이너 점검 |
| DB (03 문서 D13) | PostgreSQL 18 컨테이너 | **Vercel Marketplace의 무료 Postgres** (후보: Neon) | T2.1.2의 로컬 `postgres` 컨테이너, T2.8.1의 `pg_dump` 백업 절차 |
| 03 문서 X6, X7 (배포 위치, 도메인, TLS) | 미결정 | `https://ping9.vercel.app`, TLS는 Vercel이 제공 | M1 확인 항목 중 하나가 해소됨 |
| 03 문서 X8 (Arm에서 컨테이너 이미지 동작) | 미검증 | 해당 없음 | — |

그대로 유지되는 것: Hono, better-auth, Drizzle ORM, PostgreSQL, pnpm 모노레포 구조, 엔진과 화면의 설계 전부.

새로 생긴 ⚠️ 미검증 항목:

| # | 내용 | 확인 시점 |
|---|---|---|
| V1 | Hono API가 Vercel Functions에서 설계대로 동작하는지. `@hono/node-server` 대신 Vercel용 진입점이 필요함. AD-12("같은 프로세스가 SPA와 `/api`를 제공")는 "같은 출처"로 읽어야 하며 문구 변경은 팀 합의 필요 | T2.1.1 |

V2가 "배포되지 않음"으로 확인되면 고를 수 있는 방법: 저장소를 공개로 전환 / 소유자만 `main`에 병합 / GitHub Actions에서 Vercel 토큰으로 배포(`vercel build` → `vercel deploy --prebuilt`) / Pro 플랜.

## 7. 남은 일과 다음 Task에 전할 것

남은 일:

- **GitHub 자동 배포 연결.** 저장소 소유자가 Vercel GitHub 앱에 `PING9` 저장소 접근 권한을 준 뒤 `vercel git connect`를 다시 실행.
- **DB 생성.** `vercel install neon --name ping9-db --plan free -e production -e preview`. 약관 동의가 필요할 수 있어 소유자 확인 뒤 진행.
- 계획 문서(03의 3.10절, 04-tasks의 Story 2.2, 05)를 Vercel 기준으로 고치기. 팀 합의 뒤 별도 Task로.
- 팀원 2명을 GitHub 저장소 collaborator로 초대.

다음 Task에 전할 것:

- **T1.1.1**: 루트에 `vercel.json`과 `apps/web/index.html`이 이미 있음. `apps/web`을 만들 때 자리표시 `index.html`은 덮어써도 됨.
- **T1.1.4**: `vercel.json`을 `installCommand: "pnpm install --frozen-lockfile"`, `buildCommand`: web 빌드 명령, `outputDirectory: "apps/web/dist"`로 바꿔야 함. SPA 경로를 위한 rewrite도 여기서 추가. 완료 기준의 "배포된 주소"는 `https://ping9.vercel.app`.
- **T1.1.3**: main 브랜치 보호는 아직 없음. V2 결과에 따라 배포 워크플로가 필요할 수 있음.
- 미리보기 배포에는 Vercel 인증 보호가 켜져 있어(`deploymentProtection: vercel_authentication`) Vercel 팀에 속하지 않은 사람은 미리보기 주소를 열 수 없음. 운영 주소는 누구나 열림.
- 로컬에서 Vercel과 연결하려면 각자 `npx vercel link` 실행 (`.vercel/`은 커밋되지 않음).
