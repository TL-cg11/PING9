## 2. 진행 방식

`running-config.test.ts`를 먼저 쓰고(7개 실패) 구현했다.

1. `runningConfigLines(device)`가 Switch의 구성을 줄의 목록으로 쓴다. 구성은 `shared`의 읽기 함수(`switchVlans`, `switchPorts`)로 읽어서 기본값이 채워진 값을 본다.
2. `show running-config` 명령 정의를 더했다 (privileged 모드).
3. `hostname`이 지금 이름과 같으면 아무 일도 하지 않게 했다. 출력의 첫 줄(`hostname SW1`)을 다시 넣었을 때 오류가 나지 않아야 한다.

### 출력의 규칙

| 구역 | 규칙 |
|---|---|
| `hostname <이름>` | 항상 |
| `vlan <번호>` | VLAN 1은 쓰지 않는다. 이름이 기본 이름(`VLAN0010`)이면 ` name` 줄을 생략한다 |
| `interface <전체 이름>` | 기본값과 다른 설정이 있는 포트만, 포트 순번대로 |
| 포트 안의 줄 | ` switchport mode trunk`, ` switchport access vlan <번호>`(1이 아닐 때), ` switchport trunk allowed vlan <목록>`(전부 허용이 아닐 때), ` shutdown` 순 |
| `!` | 구역 사이. 다시 입력할 때는 설명 줄로 무시된다 |
| `end` | 마지막 줄. 다시 입력하면 privileged 모드로 돌아간다 |

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 명령 정의마다 `serialize`를 두지 않고, 장비의 구성을 쓰는 함수 하나로 | 출력의 순서(VLAN 먼저, 포트는 순번대로, 포트 안의 줄 순서)는 정의 하나가 정할 수 없다. 구성 → 줄은 함수 하나가 읽기 쉽다 | 03 문서의 `serialize` (설계 7.1절) |
| 왕복은 속성 기반 테스트가 지킨다 | 명령 정의와 출력이 어긋나면(명령어 이름을 바꾸는 등) 테스트가 실패한다. `serialize`가 주려던 보장이 이것이다 | 정의에서 출력 글을 꺼냄 |
| trunk 모드가 아니어도 허용 목록이 있으면 쓰고, access 모드가 아니어도 access VLAN이 있으면 쓴다 | 구성에 저장된 값이다. 쓰지 않으면 왕복이 깨진다 | 지금 모드의 설정만 |
| `hostname`이 같은 이름이면 dispatch하지 않음 | `device/rename` 처리기가 아직 없어 dispatch하면 오류가 난다. 처리기가 생겨도 같은 이름으로 바꾸는 것은 할 일이 없다 | 그대로 dispatch |

## 6. 계획과 달라진 점

- **명령 정의의 `serialize`를 두지 않았다** (2절의 결정). 03 문서의 `defineCommand` 형태와 다르다.
- **Switch만 했다.** Router의 `show running-config`는 Router 담당이 자기 구성을 쓰는 함수를 만들어 같은 방식으로 넣는다.

### 검토에서 나온 것 (2026-11-06)

- **긴 허용 목록이 왕복되지 않았다.** 서로 떨어진 범위가 많으면 `switchport trunk allowed vlan …` 한 줄이 콘솔의 줄 길이 한도(512자)를 넘어, 다시 넣을 때 `CLI_LINE_TOO_LONG`으로 거부됐다 (범위 49개에서 520자, 64개에서 670자). 속성 기반 테스트가 목록을 4개까지만 만들어서 놓쳤다.
- **고친 것**: 목록을 16개씩 나눠 첫 줄은 그대로, 다음 줄은 `switchport trunk allowed vlan add <목록>`으로 쓴다 (실제 장비와 같은 방식). 그 `add` 명령어를 T5.3.1의 명령 정의에 더했다. 실패하는 테스트(범위 64개의 왕복)를 먼저 썼고, 속성 기반 테스트의 생성기에 떨어진 번호 30~64개의 목록을 더했다.

## 7. 남은 일과 다음 Task에 전할 것

- **왕복이 보장되지 않는 경우 (알고 두는 예외, 설계 7.4절)**: VLAN을 지운 뒤에도 포트에 그 번호가 남아 있는 구성. 출력에 `switchport access vlan 10`은 있고 `vlan 10`은 없어서, 다시 입력하면 VLAN 10이 자동으로 만들어진다. 실제 장비도 같다. 가져온 문서에서 이름이 바뀐 VLAN 1도 출력하지 않는다.
- **Switch 명령어를 더하는 사람에게**: 구성에 새 값을 저장하는 명령을 더하면 `runningConfigLines`에도 그 줄을 더한다. 빠뜨리면 속성 기반 테스트가 그 값을 만들지 않는 한 알 수 없으니, 테스트의 Command 목록에도 더한다.
- **Router 담당에게**: `hostname`, `!`, `end`의 처리는 `cli/ios`에 있어 그대로 쓸 수 있다.
