## 2. 진행 방식

1. `assist.test.ts`를 먼저 썼다 (모듈이 없어 실패). `assist.ts`에 `helpFor`와 `completeLine`을 만들었다.
2. `assist-console.test.ts`를 먼저 썼다 (3개 실패: `complete`가 늘 `null`, `help`가 늘 `[]`). `console.ts`의 `complete`와 `help`를 연결했다.

완성과 도움말은 해석기와 같은 함수(`walkWords`, `candidatesFor`)로 "볼 자리 앞까지의 단어가 맞은 정의들"을 구하고, 그 정의들의 그 자리 토큰을 본다. 따로 만든 명령어 표가 없으므로 해석기와 어긋날 수 없다.

### `help(line)`의 규칙

| 줄 | 결과 |
|---|---|
| 비었거나 빈칸으로 끝남 | 다음에 올 수 있는 단어 전부 |
| 글자로 끝남 | 마지막 단어로 시작하는 키워드만 (매개변수 자리는 그대로 보임) |
| 여기서 끝나도 되는 줄 (빈칸으로 끝날 때) | 끝에 `<cr>`이 붙고, 설명은 그 명령어의 설명 |
| 앞의 단어가 틀렸거나 모호함 | 빈 목록 |

순서는 키워드(가나다순), 매개변수(`<이름>`), `<cr>`이다.

### `complete(line)`의 규칙

- 마지막 단어가 키워드 하나로 정해지면 `앞부분 + 키워드 + 빈칸`. 앞의 단어는 줄여 쓴 그대로 둔다 (`conf t` → `conf terminal `).
- 후보가 없거나 둘 이상이거나, 매개변수 자리거나, 줄이 빈칸으로 끝나면 `null`.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 매개변수의 표시는 `<매개변수 이름>` (`<id>`, `<name>`) | 정의에 이미 있는 이름이다. 매개변수 종류마다 표시를 정한 표를 두면 다른 담당이 종류를 더할 때(`ipv4`, `mask`) 그 표도 고쳐야 한다 | 실제 장비처럼 `<1-4094>`, `WORD`, `A.B.C.D` |
| 치다 만 값이 있어도 매개변수 자리는 항상 보임 | 값이 맞는지는 다 쳐야 알 수 있다 (`10.0`은 틀린 IPv4지만 치는 중일 수 있다) | 지금까지 친 글이 유효할 때만 보임 |
| `show`, `no`의 설명은 `assist.ts`의 작은 표(`KEYWORD_HELP`)에서 | 정의의 `help`는 명령어 하나의 설명이다. `no`의 설명이 첫 정의의 "Delete a VLAN"이면 `no` 명령이 늘었을 때 틀린다 | 토큰마다 설명을 달 수 있게 정의 형태를 바꿈: 다른 담당의 정의도 고쳐야 함 |
| 후보가 여럿이면 `null` (공통 접두사까지도 완성하지 않음) | 실제 장비와 같다. 무엇이 있는지는 `?`로 본다 | 셸처럼 공통 접두사까지 완성 |
| `complete`와 `help`는 세션과 문서를 바꾸지 않음 | 조회일 뿐이다. `docVersion`도 오르지 않는다 | — |

### 도움말의 예 (Switch)

```text
SW1(config)# ?                                   SW1(config)# vlan ?
  end       Return to privileged mode              <id>  VLAN ID (1-4094)
  exit      Leave the current mode
  hostname  Set the device name                  SW1# show vlan ?
  no        Negate a command or set its defaults   brief  Show VLANs and their access ports
  vlan      Create a VLAN or enter its ...         <cr>   Show VLANs and their access ports
```

(줄 맞춤은 화면이 한다. engine은 `{ token, description }`의 목록만 돌려준다.)

- 단위 테스트: 도움말 10가지 경우, 완성 22줄.
- 해석기와의 일치(AD-8): Switch의 모든 정의에 대해, 모드마다 앞에서부터 한 단어씩 친 모든 자리에서 네 가지를 확인한다.
  1. 그 자리에 칠 수 있는 단어가 도움말에 나온다.
  2. 도움말에 나온 단어를 이어 치면 해석기가 그 단어를 틀렸다고 하지 않는다.
  3. `<cr>`은 줄이 거기서 끝나도 될 때만 나온다.
  4. Tab은 도움말의 단어 하나로만 완성하고, 완성된 줄은 줄여 쓴 줄과 같은 명령어로 읽힌다.
- 콘솔 경계: 모드에 따라 달라지는 결과, 세션과 문서를 바꾸지 않음, 없는 장비, 글이 아닌 값, 너무 긴 줄.

## 6. 계획과 달라진 점

- **매개변수의 표시가 `A.B.C.D` 형태가 아니라 `<이름>`이다** (2절의 결정). 설명은 정의에 적은 글이다 (예: `VLAN ID (1-4094)`).
- **일치 확인을 임의 생성이 아니라 전수로 했다.** 계획은 속성 기반 테스트다. 정의의 수가 적어 모든 자리를 다 도는 편이 빠짐이 없다.
