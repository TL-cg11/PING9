## 2. 진행 방식

1. 그림: 사용자의 펭귄 스프라이트 시트(1536×1024, 투명 배경 PNG)를 포즈마다 잘라 128px로 줄였다. 다시 그리지 않았다.
   - 물고기 든 포즈의 바깥 날개를 몸 윤곽을 따라 잘라 손이 한쪽에 하나만 보이게 했다. 놓침 포즈도 같다.
   - 시트에 "물고기를 들고 걷는" 그림이 없어 물고기 든 상체에 걷기 A·B의 발을 붙였다.
   - 초록(ARP)과 노란 놓침은 파란 물고기의 색을 바꿔 만들었다. 초록은 형광 그대로 (차분한 후보 셋과 비교한 뒤 사용자 결정).
   - 크기는 36 (장비 아이콘 50보다 조금 작게, 사용자 결정).
2. 시간표(`timeline.ts`): 단계(T6.1.1)를 화면 시각에 놓는다. 펭귄은 케이블 길이와 상관없이 같은 빠르기(캔버스 좌표 0.2 / ms)로 걷는다. ARP 재시도처럼 아무 일 없이 기다린 시간은 0.6초로 줄인다.
3. 펭귄 층(`packet-layer.tsx`): 매 프레임 `지금 - 시작`으로 그릴 것을 계산한다. 걷는 펭귄이 없으면 시계를 멈춘다.
4. 콘솔과 시점 맞추기(`ping-pacing.ts`, `terminal-state.ts`): 회차를 시작할 때 재생을 시작하고, 재생이 끝날 때(응답 물고기가 출발 PC에 닿을 때) 회차 줄을 보인다. 다음 회차는 그 1초 뒤.
5. 사용자가 개발 서버에서 보고 고친 것: 속도를 두 번 늦춤, 길이와 상관없이 같은 빠르기, 놓친 펭귄과 다음 펭귄이 겹치지 않게, 실패 회차는 한 번 가고 줄이 뜨게, 다른 PC에서 ping해도 남은 펭귄이 지워지게.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 회차 줄은 재생이 끝날 때 뜬다 | 줄과 그림이 같은 순간이라 무엇이 무엇인지 보인다. 대신 ping이 실제보다 느리다 | 콘솔은 1초마다, 재생은 따로 |
| 같은 빠르기로 걷기 (케이블 길이에 비례한 시간) | 케이블마다 같은 시간이면 긴 케이블에서 펭귄이 빨라진다 | 링크마다 같은 시간 |
| 놓침은 1초 보이고, 다음 펭귄이 출발하기 직전 0.2초 동안 흐려지며 사라진다. 마지막 놓침은 남는다 | 같은 자리에서 재시도하는 펭귄과 겹치지 않게 (사용자 요청) | 다음 ping까지 남김 |
| 남은 놓침은 어느 장비든 다음 회차가 시작되거나 캔버스 빈 곳을 누르면 지운다 | 다른 PC에서 ping할 때 앞 PC의 펭귄이 남지 않게 (사용자 요청). 다른 PC에서 걷는 중인 재생은 그대로 | 장비마다 따로 남김 |
| PNG를 SVG `<image>`로 | 사용자의 그림을 그대로 쓴다. 공개 저장소에 넣는 것도 확인받음. 12장 약 250KB | 그림을 SVG로 다시 그리기 (발이 잘 안 보였다) |
| 좌우 뒤집기 없음 | 그림이 정면을 본다 | 가는 방향으로 뒤집기 |

## 6. 계획과 달라진 점

- 프레임 표시가 점이나 상자가 아니라 사용자 그림의 펭귄과 물고기다.
- 콘솔의 회차 줄을 재생에 맞춘다 (계획에 없음). ping이 실제보다 느리다: Switch 둘을 지나는 예시에서 4회 ping이 수십 초 걸린다.
- 실패 회차는 첫 시도만 재생한다 (T6.1.1 기록 2절).
- 펭귄 층은 매 프레임 React 상태를 바꿔 다시 그린다 (층 하나만 다시 그림). 설계안은 SVG 속성만 바꾸는 방식이었다. T6.1.3(장비 50대 성능)에서 다시 본다.
