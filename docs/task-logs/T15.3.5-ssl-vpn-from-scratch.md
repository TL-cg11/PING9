## 2. 진행 방식

기존 SSL VPN 기능과 미커밋 작업을 보존하고 문서 작업용 브랜치를 만들었다. 화면 설정·IOS/Linux CLI·내보내기/가져오기 구조를 읽어 현재 지원되는 방법만 문서에 적었다.

VPN 설정 폼과 서버 설정 명령이 없으므로, 물리 구성은 화면과 CLI에서 직접 만들고 VPN 설정은 내보낸 JSON의 두 장비 config에 추가하도록 했다. 사전 설정된 예제 URL이나 소스 코드 수정을 요구하지 않는다. JSON 설정은 현재 한계에 따른 대체 절차임을 처음에 밝혔다.

## 4. 결과와 검증

검증용 임시 Vitest 파일에서 빈 Simulator에 device/add·link/add를 실행했다. PC IP는 속성 패널과 같은 pc/set-ip Command로 적용했고, ISP·FW1·R1 명령은 가이드 코드 블록을 직접 추출해 실행했다. 두 PC의 게이트웨이 ping 성공을 확인했다.

가이드의 두 JSON 블록을 추출해 내보내기 구조의 PC_A/R1 config로 넣고 parseExportJson 검증 → Simulator.load → 접속·상태·해제 → 방화벽 규칙 삭제로 timeout → 허용 규칙 복구로 재접속을 확인했다. 완성된 SSL 예제 fixture는 사용하지 않았다.

```text
pnpm --filter @ping9/engine exec vitest run src/vpn/ssl-vpn-guide-rehearsal.test.ts
  Test Files 1 passed (1)
  Tests 1 passed (1)
  Duration 456ms
```

임시 검증 파일의 문서 상대 경로를 한 번 수정한 뒤 통과했다. 검증 완료 후 임시 파일은 삭제했으며 제품 코드나 영구 테스트를 추가하지 않았다. 문서 변경이므로 전체 lint/타입 검사/빌드는 다시 실행하지 않았다. 수동 브라우저 클릭은 실행하지 않았다. Markdown 상대 링크·diff 공백·신규 문서 비밀값 검사를 별도 확인했다.
