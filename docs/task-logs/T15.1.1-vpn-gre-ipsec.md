## 2. 진행 방식

현재 main 5d887b0의 물리 포트·ARP·MAC·링크·Router·RIP·CLI를 읽고 재사용했다.
미커밋 계획 초안을 사용자 최신 범위로 수정하고 GRE부터 구현했다.
사용자에게 IPsec 구현 수준을 물은 동안 GRE 구현과 검증을 계속했고, 사용자가 실제 암호화 없는 교육용 모델을 선택한 뒤 IPsec을 연결했다.
설정만 만들고 끝내지 않고 기존 Simulator·CLI·Runtime·Trace를 통과하는 통신으로 연결했다.

### 주요 결정

| 결정 | 이유 |
|---|---|
| Tunnel0~3은 config.tunnels의 논리 인터페이스 | 기존 물리 포트·케이블 포트·MAC 순번을 보존하고 터널에 ARP하지 않음 |
| 기존 다음 홉 정적 경로 문법 재사용 | 상대 터널 IP를 next-hop으로 지정하면 Tunnel 출구로 해석 가능 |
| GRE/ESP 안쪽은 IPv4 ICMP 한 단 | 현재 ping·오류 모델에서 정확히 전달·검증 가능한 첫 범위 |
| IPsec은 수동 SA 교육 모델 | 사용자가 실제 암호화 없는 시뮬레이션을 선택함. IKE/암호학적 인증 완료를 가장하지 않음 |
| 보호 selector가 일치하면 실패 시 폐기 | 꺼짐·미완성·만료·상대 불일치 때문에 평문으로 우회하지 않게 함 |
| SA/sequence/counters는 Runtime | 저장 문서는 설정만 보존하고 같은 실습 세션의 회차 사이에는 재전송 창을 유지 |
| 물리 상태와 자기 Router 포트만 계산 | 패킷마다 전체 장비의 뷰를 반복 계산하지 않도록 기존 전달 경로의 비용을 줄임 |

## 3. 변경 내용

- shared: GRE/IPsec 설정, schema/검증, Command, Trace 프로토콜 47/50과 GRE/ESP 모델, 오류/이벤트 코드, 상태 View.
- reducer: 논리 Tunnel 생성·수정·삭제, IP/admin, IPsec 프로필 생성·수정·삭제. 최대 개수·네트워크·SPI·selector 검증.
- Router: 논리 연결망과 물리망 경로 분리, GRE 캡슐화/역캡슐화, 일반 전달 중 GRE/ESP 보존, 원래 ICMP 처리와 TTL 재사용.
- IPsecModule: 송수신 selector, manual inbound/outbound SPI, 공개 key-id 일치, 64개 수신 창, sequence 증가, 가상 lifetime.
- Runtime: kernel 가상 시계를 Router에 제공하고 SA 상태/조회 API를 CLI와 화면에 연결.
- CLI: `interface tunnel 0`, `tunnel source/destination/mode`, `show interfaces tunnel0`, `crypto ipsec profile`, `show crypto ipsec sa`, running-config 왕복.
- 화면: 물리 포트와 별도 GRE/IPsec 패널, GRE의 G와 ESP의 E 재생 표식, 암호화 없는 시뮬레이션 표시.
- 개발 예시: `?lab=gre`, `?lab=ipsec`. 일반 시작 화면은 빈 캔버스. 개발 서버에서만 예시를 선택한다.
- [로컬 실습 안내](../guides/vpn-local-lab.md), [범위·계약](../proposals/vpn-gre-ipsec.md).

## 4. 결과와 검증

### 자동 검증

- GRE/IPsec 집중 테스트: 24개 통과.
- 실제 Simulator/CLI: 터널/정책 설정 전후, PC 양방향, Router 출발, IPsec 내부 TTL 만료의 ICMP 오류 반환.
- 중간 ISP에는 사설 LAN 경로가 없고 바깥 주소만 전달. GRE와 ESP에서 안쪽 IP 보존·독립 TTL·기존 MAC/ARP 전송·Trace 검증.
- GRE: 잘못된 상대·shutdown·경로 없음·케이블 단절·재귀 터널 차단, JSON/running-config 왕복.
- IPsec: key/SPI/peer/selector/꺼짐/미완성 거부, 실제 Router에 동일 ESP를 중복 주입해 두 번째 복원을 거부, 평문 보호 우회 거부.
- 64개 창 안의 순서 뒤바뀜 허용, 중복/창 밖/잘못된 sequence 거부. 잘못된 키 패킷이 수신 창을 전진시키지 않음.
- 가상 시계로 lifetime 만료를 확인하고 다음 ping 폐기·조회 상태 확인. 이동/경로/포트 장애 복구에서는 sequence 유지.
- 화면 재생 구분과 15초 상한, 원본 Trace 불변, 상태 패널·물리 포트 수 검증.

한 번의 전체 검사에서 기존 RIP 재수렴 속성 테스트가 5초 제한에 걸렸다.
Router의 추가 조회에서 전체 뷰를 재계산하던 부분을 자기 장비의 물리 포트 계산으로 바꾸고 전체 검사를 다시 실행했다.
최종 검사 결과:

```text
pnpm check: exit 0
lint / typecheck / build 통과
scripts 35 + shared 370 + engine 1589 + web 389 + api 2 = 2385 tests passed
pnpm check:secrets: 파일 659개 통과
신규 미추적 파일도 동일 findSecrets/forbiddenFileReason으로 별도 검사
상대 문서 링크 검사 / git diff --check 통과
```

Vite의 500 kB chunk 안내는 경고이며 빌드는 성공했다. 코드 분할은 이번 작업에서 변경하지 않았다.

새 테스트 탭을 각각 열어 확인했다. 기존 사용자 탭을 새로고침하지 않았다.

## 5. 추정과 실제

인일 추정은 새로 확정하지 않았다. 작업 단위를 여러 PR로 나누는 대신 사용자의 두 모드 구현 착수 요청에 따라 공통 계약·전달·최소 CLI·실습 예시를 한 브랜치에서 연결했다.

## 6. 계획과 달라진 점

- E15 상위 계획의 GRE+IPsec은 사용자가 이번 범위에서 제외했다. 원래 확정 계획 본문은 유지했다.
- 후속 세부 Task로 제안했던 최소 CLI와 관찰·예시까지 첫 구현과 함께 제공했다.
- IPsec은 사용자 선택대로 교육용 수동 SA이다. 실제 ESP wire format의 암호화/ICV, IKE 협상을 구현하지 않았다.
- 터널 출구는 별도 정적 경로 타입을 추가하지 않고 기존 next-hop을 논리망으로 해석했다.

## 7. 남은 일과 제한

- PR과 팀원 검토 전이며 커밋/push/PR은 하지 않았다.
- SSL VPN, GRE+IPsec, NAT-T, 실제 IKE/rekey·암호화·암호학적 무결성, 터널 내 RIP, IPv6는 미구현.
- 고정 ICMP 자료만 지원한다. MTU·조각화·바깥 ICMP 오류를 안쪽 송신자에게 번역하는 기능은 미구현.
- IPsec Trace의 payload/keyId는 평문 교육 자료다. 기밀성·변조 방지 또는 실제 VPN과의 상호운용성을 제공하지 않는다.
- SA active는 로컬 사용 상태다. 실제 상대와의 보안 협상 완료 표시가 아니다.
- 정책 수정은 해당 로컬 SA를 새로 시작한다. 한쪽만 바꾸면 반대쪽 수신 창과 달라질 수 있다. 예시 새로고침은 양쪽을 함께 새 실습 세션으로 시작한다.
- 문서 load/새로고침은 실습 세션 초기화이며 실제 수동 키 장비의 재부팅 간 sequence 영속성은 구현하지 않는다.
