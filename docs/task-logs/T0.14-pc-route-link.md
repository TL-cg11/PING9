## 2. 진행 방식

1. 문서: `PcConfig`에 선택 칸 `adminUp`을 더했다. 칸이 없으면 켜짐이라 `schemaVersion`은 그대로이고 옛 문서도 그대로 읽힌다.
2. reducer: Switch·Router가 쓰던 `interface/set-admin`에 PC 갈래를 더했다. 새 Command는 없다. 패널 토글과 Linux 명령이 같은 Command를 낸다 (AD-3).
3. 엔진: `isAdminUp`이 PC의 칸을 읽게 했다. 보내는 쪽은 `transmit`이 이미 `IF_DOWN`으로 버리고, 받는 쪽은 `PcModel.onFrame`이 버린다. ping 회차는 보내기 전에 `Ipv4Host.sendEcho`에서 막아 보내지 못한 회차가 된다. 화면의 포트 상태(`admin-down`, 상대는 `peer-down`)는 이미 `isAdminUp`으로 계산하고 있었다.
4. 명령어: 경로 계산(`routes.ts`)을 하나 두고 Windows·Linux가 각자 모양으로 보인다.
5. 화면: 시안대로 OS 아래에 토글 한 줄.
6. 개발 서버를 띄워 헤드리스 Chrome으로 눌러 확인했다 (4절).

### 주요 결정

설계안의 결정 1~11을 따랐다. 구현하며 정한 것:

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 꺼진 포트 확인을 IP 확인보다 먼저 | IP가 없어도 포트가 꺼져 있으면 꺼진 것이 원인이다 | IP 확인 먼저 (`NO_IP`) |
| 출발 장비의 `IF_DOWN` 폐기를 `unsent`로 센다 (`pingRoundKind`) | 출발에서 `IF_DOWN`이 나오는 것은 꺼진 PC뿐이다. Router는 꺼진 인터페이스를 경로에서 뺀다 | 새 폐기 코드 |
| `route print`의 `Interface List`에도 `Ethernet0` 한 줄만 | loopback 경로를 뺀 것에 맞춘다 (설계안 5절) | loopback 줄도 둠 |
| `ip route`의 `linkdown`은 케이블 없음과 상대 꺼짐 둘 다 | 둘 다 신호가 없는 상태다. `ip addr`도 둘을 같은 `NO-CARRIER`로 보인다 | 케이블 없음만 |
| 케이블이 없어도 Windows `route print`에는 경로가 보인다 | `ipconfig`도 주소를 그대로 보인다 (결정 7과 같은 쪽) | 실제처럼 빼기 |
| 켜면 `adminUp: true`로 남긴다 | 설계안 3절대로. Router 인터페이스와 같다 (Switch 포트는 기본값이면 항목을 지운다) | 칸을 지움 |
| 토글은 `role="switch"`와 `aria-checked`, 이름은 "포트 Ethernet0" | 화면 읽기 프로그램이 켜짐·꺼짐을 읽는다 | 체크박스 |

## 6. 계획과 달라진 점

- 계획에 없는 Task다. 요구사항 추가라 팀 확인이 필요하다.
- 설계안 결정 10은 꺼진 Windows PC의 `tracert`를 `General failure.` 줄로 적었다. 보내지 못한 hop의 줄은 T11.4.1에 이미 `  1  Transmit error: code 1231.`로 있어 그것을 그대로 쓴다 (실제 Windows의 줄).
- `route print`는 실제 출력에서 loopback·멀티캐스트·브로드캐스트 줄과 IPv6 부분을 뺐다 (결정 2). `help`의 설명에 "default gateway and own network only"로 적었다.
- 포트를 꺼도 문서의 게이트웨이를 지우지 않는다 (결정 4). 실제 Linux는 지운다.

## 7. 남은 일과 다음 Task에 전할 것

- 캔버스에 꺼진 포트를 표시하는 일은 모든 장비 공통으로 따로 정한다 (결정 8).
- Windows `route add`·`route delete`, `netsh`는 넣지 않았다.
- PC 경로는 `cli/pc/routes.ts`의 `pcRoutes`가 계산한다. PC에 경로를 더하는 기능이 생기면 여기서 보인다.
