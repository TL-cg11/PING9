## 2. 진행 방식

테스트(`show-commands.test.ts`)와 구현을 함께 썼다. 실패하는 것을 먼저 돌려 보는 단계는 건너뛰었다 (새 파일뿐이라 구현 전에는 모듈이 없어 실패한다).

1. 표를 만드는 함수 `tableLines`를 `cli/ios/table.ts`에 두었다. 설계 7.5절의 규칙(열 너비, 공백 2칸, 줄 끝 공백 없음, 줄이 없으면 머리줄만)을 한곳에 모았다.
2. `show interfaces trunk`는 구성에서 trunk 모드인 포트를 포트 순번대로 뽑고, 상태는 화면과 같은 계산(`computeViews`)에서, 허용 목록은 `formatVlanList`로 쓴다.

### 출력

```text
SW1# show interfaces trunk
Port   Status  Allowed VLANs
Fa0/8  up      10,20
```

| 열 | 값 |
|---|---|
| Port | 줄인 포트 이름 |
| Status | 포트 상태 코드 그대로: `up`, `no-link`, `admin-down`, `peer-down` |
| Allowed VLANs | `10,20-30`, 전부 허용이면 `all`, 빈 목록이면 `none`. `switchport trunk allowed vlan`에 그대로 넣을 수 있는 글이다 |

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 상태를 `up`/`down` 둘이 아니라 포트 상태 코드 넷으로 | 화면의 포트 상태와 같은 값이다 (AD-7). 왜 내려갔는지가 보인다 | `up`/`down` |
| `tableLines`를 `cli/ios`에 둠 | Router의 `show`도 같은 모양을 쓸 수 있다 | Switch 폴더 |
| `show vlan brief`는 `tableLines`로 바꾸지 않음 | Ports 열이 여러 줄로 이어지는 특별한 표다 | 함께 바꿈 |
