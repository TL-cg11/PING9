## 1. 목표와 완료 기준

PR #55를 병합하기 전 검토에서 임시 테스트로 재현한 결함 두 개를 고친다.

- [x] 포트를 꺼 둔 PC의 IP를 다시 설정해도 포트가 켜지지 않는다 (패널의 "적용", Windows `ipconfig <ip> <mask>`, Linux의 주소·게이트웨이 명령이 모두 `pc/set-ip`를 쓴다)
- [x] Router에 직접 꽂힌 PC의 포트를 끄거나 켜면 RIP 경로 교환이 다시 돈다. 끄면 그 LAN을 잊고, 켜면 다시 배운다
- [x] 달라진 것이 없으면 교환하지 않는다: 끈 적 없는 PC에 "켜기"를 보내는 것, PC의 주소·OS 바꾸기
- [x] 공통 완료 조건: lint, 타입 검사, 단위 테스트, 빌드 (4절)
- [ ] 리뷰 — 팀원 검토 없이 병합했다 (6절)

## 2. 진행 방식

1. 실패하는 테스트를 먼저 썼다. `pc-set-ip.test.ts`에 3개, `route-exchange-run.test.ts`에 2개.
2. 고치기 전에 돌려 4개가 기대한 이유로 실패하는 것을 봤다 (4절). 다섯째("끈 적 없는 포트를 켜는 것은 교환하지 않는다")는 너무 넓게 고치는 것을 막는 테스트라 이때는 통과한다.
3. `pc/set-ip`가 구성을 새로 만들 때 `adminUp`을 `os`처럼 옮기게 했다.
4. `routingInputs`에 PC 포트의 상태를 넣었다. 먼저 저장된 값(`adminUp`) 그대로 넣어 보니 다섯째 테스트가 실패했다 (없음 → `true`인데 교환이 한 번 더 돎). 실제 상태(`adminUp ?? true`)로 바꿔 모두 통과시켰다.
5. PC 구성을 새로 만드는 다른 곳이 있는지 찾았다. `pc/set-os`와 `interface/set-admin`은 구성을 펼쳐서 옮기므로 그대로 뒀다.
6. 전체 검사를 돌리고, 개발 서버에서 RIP 예시(`threeRouterRipDocument`)로 직접 확인했다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| `pc/set-ip`는 주소가 아닌 칸(`os`, `adminUp`)을 있던 그대로 옮긴다. 없던 칸은 만들지 않는다 | 이 명령은 IP 구성만 바꾼다는 기존 주석의 뜻 그대로다. 문서 모양(칸이 없으면 켜짐)도 바뀌지 않는다 | 구성 전체를 펼치고 주소 칸만 지우기 (지울 칸 목록을 따로 관리해야 한다) |
| 교환을 돌릴지는 PC 포트의 실제 상태(`adminUp ?? true`)로 비교한다 | 값이 없는 것과 `true`는 같은 켜짐이다. 저장된 값으로 비교하면 끈 적 없는 PC를 "켜기"만 해도 교환이 돈다 | 저장된 `adminUp` 값 그대로 비교 |
| Router에 꽂힌 PC인지 따지지 않고 모든 PC의 상태를 넣는다 | Switch에 꽂힌 PC는 RIP 결과를 바꾸지 않지만, "RIP에 영향이 있는 PC"만 고르려면 링크를 따라가야 한다. 포트를 끄고 켜는 일은 드물어 교환 한 번의 값이 작다 | Router의 맞은편인 PC만 넣기 |
| 켰을 때 `adminUp: true`가 남는 것은 그대로 둔다 | T0.14의 결정 4다. 이 수정의 범위가 아니다 | 켜면 칸을 지우기 |

## 7. 남은 일과 다음 Task에 전할 것

PR #55 리뷰에 적은 것 가운데 이 수정에 넣지 않은 것:

- 포트를 껐다 켜면 `adminUp: true`가 남아 끄기 전 문서와 모양이 다르다.
- 포트가 꺼진 Windows PC가 자기 주소로 보낸 ping에 응답한다 (`route print`에는 그 경로가 없다).
- 캔버스의 케이블이 PC 쪽이 꺼진 것을 그리지 않는다 (T0.14 결정 8로 미룬 것).
- 직접 이은 PC 둘 가운데 하나가 꺼져도 다른 쪽의 ARP 항목이 남는다.
- `ip link set dev eth0 down` 형태를 받지 않는다. `ifconfig eth0 d`가 `down`으로 줄여 읽힌다.

다음에 PC 구성(`PcConfig`)에 칸을 더할 때는 `pc/set-ip`가 그 칸을 옮기는지, RIP 결과에 영향이 있으면 `routingInputs`에 들어가는지 함께 본다.
