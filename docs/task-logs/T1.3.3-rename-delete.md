## 2. 진행 방식

1. 지금 상태를 확인했다. `device/remove` 처리기는 T1.4.1에서 들어와 있었지만 화면에서 부르는 곳이 없었다. `device/rename`은 Command 목록에만 있고 처리기가 없어서, Switch와 Router 콘솔의 `hostname`이 "아직 지원하지 않는 동작이에요"로 거부되고 있었다.
2. `device/rename` 처리기의 테스트를 먼저 쓰고(13개 모두 `UNKNOWN_COMMAND`로 실패) 처리기를 만들었다. 이름 형식은 `checkDeviceName`, 중복은 `validateDocument`가 본다.
3. `hostname`의 테스트를 "처리기가 없는 동안의 오류"에서 "이름과 프롬프트가 바뀐다"로 고치고, 중복 이름이 거부되는 테스트를 더했다.
4. 속성 패널의 제목 줄을 `DeviceName`으로 떼어 이름 바꾸기를 넣었다. PC 설정과 같은 방식으로 상태가 없는 `DeviceNameView`와 입력 값을 드는 `DeviceName`으로 나눴다.
5. 속성 패널에 "장비 삭제" 버튼과 확인 구역을, `app.tsx`에 Delete·Backspace 키 처리를 넣었다.
6. 로컬 개발 서버를 브라우저로 열어 확인했다. 여기서 key가 겹치는 버그를 찾아 고쳤다 (4절).
7. 변경 전체를 AI 도구의 다른 실행에 맡겨 검토받았다. 지적 5건과 실패할 수 없는 테스트 1개를 고치고 브라우저에서 다시 확인했다 (4절).

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 이름은 속성 패널의 제목 줄에서 바꾼다. 이름 옆 연필 버튼을 누르면 이름 자리가 입력란이 된다 | 시안의 속성 패널에 이름이 이미 있다. 그 자리에서 바꾸면 새 화면 요소가 버튼 하나뿐이다 | 캔버스의 이름 글자를 더블클릭 (이름 글자는 마우스가 통과하는 층이고, 장비 더블클릭은 터미널 열기다). 따로 뜨는 창 |
| Enter나 입력란을 벗어나면 적용, Esc는 취소. 거부되면 입력란을 남기고 사유를 그 아래에 보인다 | 완료 기준이 "거부되고 사유가 보임"이다. 입력한 값을 말없이 버리지 않는다 | 벗어나면 취소 |
| 형식과 중복 판단은 reducer에만 둔다. 화면은 앞뒤 공백만 떼고 dispatch한다 | 규칙이 한 곳에 있어야 화면과 `hostname`의 결과가 같다 (AD-3) | 화면에서 정규식으로 먼저 검사 |
| 케이블이 있는 장비만 한 번 더 묻는다. 없는 장비는 바로 지운다 | T1.4.3의 범위가 "링크가 있는 장비를 지울 때"다 | 항상 묻는다 |
| 확인은 속성 패널 안에서 묻는다. 삭제 버튼 자리가 "케이블 N개도 함께 지워요" 안내와 [삭제] [취소]로 바뀐다 | 브라우저의 `confirm()`은 화면을 멈추고 시안의 모양과 다르다. 서버 렌더링 테스트로 볼 수도 없다 | `window.confirm()`. 가운데에 뜨는 창 |
| Delete와 Backspace 둘 다 받는다. 입력란과 터미널 안에서는 받지 않는다 | Mac의 delete 키는 Backspace다. 입력란에서는 글자를 지우는 키다 | Delete만 |
| 묻는 중에 Delete를 다시 눌러도 지우지 않는다. [삭제] 버튼에 포커스가 가 있어서 Enter로 확정한다. 누르고 있어서 반복된 Enter는 받지 않는다 | 키를 누르고 있거나 두 번 눌러서 확인을 건너뛰지 않게 한다 | 두 번째 Delete로 확정 |
| Delete가 지우는 것은 언제나 고른 것(속성 패널에 보이는 것)이다. 키보드 포커스가 고르지 않은 장비나 케이블에 있으면 지우지 않고 그것을 먼저 고른다 (`removeKeyAction`) | 포커스가 있는 것과 패널에 보이는 것이 다를 때 엉뚱한 쪽이 묻지도 않고 지워질 수 있었다 (검토 지적 1) | 포커스가 있는 것을 먼저 지운다 |
| 캔버스의 장비나 케이블을 누르면 터미널 입력란이나 다른 장비에 있던 포커스를 뗀다. 속성 패널의 입력은 캔버스 어디를 눌러도 끝낸다 | 캔버스가 끌기를 위해 누르기의 기본 동작을 막아서 포커스가 전에 있던 곳에 남는다. 그러면 터미널을 쓰다가 장비를 눌러도 Delete가 터미널 입력란으로 가고, 이름 입력란은 벗어난 줄 모른다 | 누른 장비에 포커스를 준다 (입력란에서 넘어오면 키보드용 점선 표시가 마우스 클릭에도 보인다) |
| 같은 키로 고른 케이블도 지운다 | 고른 것을 지우는 키가 장비에서만 듣고 케이블에서는 안 들으면 어색하다. 케이블 삭제 자체는 T1.4.2에 이미 있다 | 장비만 |
| 장비를 지우면 재생 중인 펭귄을 모두 지우고, 그 장비에서 회차를 보이던 ping을 멈추고, 그 장비 터미널의 화면 기록을 버린다 | 지운 장비나 케이블 위를 걷는 펭귄이 남는다. 되돌리기가 없어서 그 장비의 기록을 다시 볼 일이 없다 | 그 장비를 지나는 재생만 골라 지운다 |

브라우저에서 찾아 고친 것: 속성 패널에서 `DeviceName`과 그 아래 `PcSettings`가 둘 다 장비 ID를 `key`로 써서, PC를 고르면 React가 "two children with the same key" 오류를 냈고 PC를 지운 뒤에 그 PC의 제목이 패널에 남았다. `DeviceName`의 key 앞에 말을 붙였다. 서버 렌더링은 겹친 key를 알리지 않아서, 패널이 돌려준 자식의 key를 직접 보는 테스트를 더했고 고치기 전 코드에서 실패하는 것을 확인했다.

AI 도구의 검토에서 나온 것과 처리:

| 지적 | 처리 |
|---|---|
| Delete가 고른 장비가 아니라 포커스가 남아 있던 다른 장비를 지운다. 케이블이 없으면 묻지도 않는다 | 고침. Delete는 고른 것만 지우고, 포커스가 다른 것에 있으면 그것을 먼저 고른다. 장비나 케이블을 누르면 남아 있던 포커스를 뗀다 |
| "장비 삭제"에서 Enter를 누르고 있으면 반복 입력이 확인의 [삭제]까지 누를 수 있다 | 고침. [삭제]는 반복된 키 입력을 받지 않는다 |
| ping 회차를 보이는 중에 장비를 지우면 그 터미널의 기록이 다시 들어간다 (화면에는 안 보임) | 고침. 기록이 없는 장비에는 다시 쓰지 않는다 |
| 이름을 바꾸다가 캔버스를 누르면 입력란이 벗어난 줄 모른다. 다른 장비를 누르면 입력하던 이름이 말없이 버려진다 | 고침. 캔버스를 누르면 속성 패널의 입력을 끝낸다 (이름은 적용된다) |
| 장비를 누른 채로(아직 끌기 전) Delete로 지운 뒤 끌어서 놓으면 "장비를 찾을 수 없어요"가 뜬다 | 고침. 끄는 사이에 지워진 장비는 옮기지 않는다 |
| "이름 값은 글자 그대로 넣는다" 테스트는 React가 속성 값을 항상 바꿔 쓰므로 실패할 수 없다 | 그 테스트를 지움 |

## 6. 계획과 달라진 점

- T1.3.3의 "삭제 키와 메뉴" 가운데 메뉴(오른쪽 버튼 메뉴)는 만들지 않았다. 속성 패널의 버튼과 Delete 키로 지운다. 시안에 오른쪽 버튼 메뉴가 없다.
- T1.4.3의 "확인 창"을 따로 뜨는 창이 아니라 속성 패널 안의 확인 구역으로 만들었다.
- T1.3.1의 `device/rename` 처리기가 빠져 있어서 이 Task에서 만들었다.
- 작업 규칙 3번은 다른 팀원 한 명의 검토를 요구한다. 이 PR은 담당자의 요청으로 AI 도구의 코드 검토만 거쳐 병합했다. 팀원 검토는 없었다.

## 7. 남은 일과 다음 Task에 전할 것

- 되돌리기(undo)가 없다. 케이블이 없는 장비는 묻지 않고 지워지므로, 구성을 많이 한 Router를 실수로 지우면 다시 만들어야 한다. 되돌리기를 만들거나 "구성이 있는 장비"도 묻게 할지 정해야 한다.
- 이름을 바꿔도 engine의 실행 중 상태(ARP·MAC 테이블)는 그대로다. 이름은 통신에 쓰이지 않는다.
- engine의 `consoles`와 `sessions`는 지운 장비의 항목을 지우지 않는다. ID가 다시 쓰이지 않아 동작에는 영향이 없다.
- 키보드만으로 지울 때는 Delete를 두 번 누른다: 포커스가 있는 장비가 먼저 골라지고, 그다음에 지워진다. Space로 고른 뒤 Delete를 눌러도 된다.
- 캔버스의 장비나 케이블을 누르면 터미널 입력란의 포커스가 떨어진다. 빈 곳을 누르거나 끌어서 화면을 옮길 때는 터미널의 포커스가 그대로다.
