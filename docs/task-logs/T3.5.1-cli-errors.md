## 2. 진행 방식

다섯 가지 오류의 대부분은 앞의 Task들(T3.1.1 해석기, T3.2.1 줄임)에서 이미 나오고 있었다. 이 Task에서는 Switch의 실제 명령어로 오류 유형별 입력 표(`cli-errors.test.ts`, 37줄)를 쓰고, 표에서 실패한 3줄을 고쳤다.

실패한 것은 모두 "모드가 틀린 명령"의 판정이었다.

| 입력 | 전 | 지금 |
|---|---|---|
| `SW1#`에서 `vlan abc` | `CLI_UNKNOWN_COMMAND` | `CLI_WRONG_MODE` |
| `SW1#`에서 `interface fa0/9` | `CLI_UNKNOWN_COMMAND` | `CLI_WRONG_MODE` |
| `SW1>`에서 `sh vl br` | `CLI_UNKNOWN_COMMAND` | `CLI_WRONG_MODE` |

전에는 "줄 전체가 다른 모드에서 맞을 때"만 모드 불일치로 봤다. 그래서 뒤의 값이 틀렸거나, 줄여 쓴 첫 단어가 다른 모드의 여러 명령어로 읽히면 "알 수 없는 명령어"가 됐다. 지금은 **첫 단어가 다른 모드의 어떤 명령어의 첫 단어(또는 그 줄임)이면** 모드 불일치다.

### 오류와 위치

| 오류 | 코드 | 위치 |
|---|---|---|
| 알 수 없는 명령어 | `CLI_UNKNOWN_COMMAND { token }` | 틀린 단어의 시작 |
| 끝나지 않은 명령어 | `CLI_INCOMPLETE_COMMAND` | 없음 (빠진 것이라 가리킬 단어가 없다) |
| 값이 틀림 | 형식이 틀리면 `CLI_INVALID_VALUE { token }`, 범위를 벗어나면 `shared`의 코드(`INVALID_VLAN_ID` 등) | 그 값의 시작 |
| 모드가 틀림 | `CLI_WRONG_MODE { token }` | 첫 단어 (0 또는 앞의 공백 뒤) |
| 여러 명령어로 읽힘 | `CLI_AMBIGUOUS_COMMAND { token }` | 그 단어의 시작 |

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 모드 불일치를 첫 단어만으로 판정 | 다른 모드의 명령어를 쳤으면 뒤의 값이 맞든 틀리든 먼저 알려야 할 것은 모드다. T5.4.1 기록 7절에 남긴 "오류가 고르지 않다"가 이것이다 | 줄 전체가 맞을 때만 |
| 끝나지 않은 명령어에는 위치를 두지 않음 | 틀린 단어가 없다. 실제 장비도 표시 없이 알린다 | 줄의 끝을 가리킴 |

## 7. 남은 일과 다음 Task에 전할 것

- **`no`로 시작하는 줄은 모드 불일치를 못 가린다 (검토에서 나옴, 고치지 않음)**: `(config)#`에서 `shutdown`은 `CLI_WRONG_MODE`지만 `no shutdown`은 `CLI_UNKNOWN_COMMAND`(위치 3)다. 첫 단어 `no`가 그 모드의 `no vlan`과 맞기 때문이다. 이 Task 전에도 같았다.
