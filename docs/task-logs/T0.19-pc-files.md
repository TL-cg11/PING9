## 1. 목표와 완료 기준

PC 콘솔에서 실제 OS처럼 폴더를 오가고 파일을 만들고 지운다. 네트워크 동작과는 상관없고, "진짜 컴퓨터를 만지는 느낌"이 목적이다.

- [x] PC마다 가상의 파일 트리. Runtime에만 둔다 (Document는 그대로)
- [x] OS별 파일 명령어: Linux `ls`, `ls -l`, `cd`, `pwd`, `mkdir`, `touch`, `cat`, `cp`, `cp -r`, `mv`, `rm`, `rm -r`, `rmdir`, `clear` / Windows `dir`, `cd`, `cd..`, `cd\`, `mkdir`, `md`, `type`, `copy`, `move`, `ren`, `del`, `rmdir`, `rd`, `rmdir /s`, `rmdir /s /q`, `cls`
- [x] 두 OS 모두 `echo <글>`, `echo <글> > <파일>`
- [x] 프롬프트에 장비 이름과 지금 폴더 이름: Windows `PC1 User>`, `PC1 lab>`, `PC1 C:\>` / Linux `user@PC2 ~ $`, `user@PC2 lab $`, `user@PC2 / $`
- [x] `clear`·`cls`로 화면 기록 지우기
- [x] Tab: 후보가 하나면 채우고, 여럿이면 겹치는 데까지 채우고, 한 번 더 누르면 후보 목록. 명령어와 파일·폴더 이름 모두
- [x] 공통 완료 조건: lint, 타입 검사, 단위 테스트, 빌드 (4절). 리뷰는 PR에서

## 2. 진행 방식

1. 설계안(바탕화면 `설계안/T0.9-pc-files-설계안.md`, 2026-11-09 초안)을 지금 main(`0a29044`)에 맞춰 다시 쓰고, 정할 것 7가지를 사용자가 정했다 (2026-11-12). 처음 쓴 ID `T0.9`는 그 사이 다른 두 작업이 써서 `T0.19`로 바꿨다.
2. 프롬프트는 시안 두 장(`T0.9-시안-프롬프트.png`, `T0.9-시안-프롬프트2.png`)을 보고 D안(맥 터미널처럼 지금 폴더 이름만)으로 정했다.
3. Tab 후보는 시안(`T0.19-시안-Tab후보.png`)을 보고 A안(두 OS 모두 bash처럼 Tab 두 번이면 목록)으로 정했다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 파일 트리는 Runtime에만 (`simulator.ts`의 `files` Map). 문서를 다시 열거나 PC의 OS를 바꾸면 처음 상태 | 실습에서 파일을 남길 일이 적고 Document 계약(`schemaVersion`, 검증, 내보내기)을 건드리지 않는다 | Document의 PC 구성에 넣기 |
| `echo <글> > <파일>` 한 형태만 기호 검사의 예외 | 파일에 글을 쓸 길이 이것뿐이다. `>>`, 파이프, 다른 기호가 섞이면 지금처럼 막는다 | 리디렉션 일반 허용, `touch`만 |
| 프롬프트 D안: 장비 이름 + 지금 폴더 이름 | 폴더가 깊어져도 짧고, 콘솔을 여러 개 띄워도 PC가 구분된다 | 지금 그대로(위치가 안 보임), 실제 OS처럼 전체 위치(길어짐), 이름 + 전체 위치 |
| Tab A안: 두 OS 모두 bash처럼 | 몇 개 중에서 고르는지 한눈에 보인다. 두 OS가 같게 동작한다 | Windows만 cmd처럼 Tab마다 다음 후보로 바꾸기 |
| 화면 지우기는 콘솔 줄 종류 `clear` | engine은 화면을 모른다. web이 이 줄을 받으면 그때까지의 기록을 지운다 | 콘솔 결과에 따로 칸 |
| 오류는 OS 형식의 영어 줄 (`cat: x: No such file or directory`, `The directory is not empty.`) | 실제 컴퓨터와 같은 화면이 목적이다. 새 오류 코드를 만들지 않는다 | 한국어 오류 코드 |
| 한도: PC 하나에 파일·폴더 200개, 깊이 16단계, 이름은 영문자·숫자·`.` `-` `_` 64자, 파일 내용 4096자 | 메모리. Runtime의 값이라 `LIMITS`가 아니라 `file-tree.ts`의 `FILE_LIMITS` | 한도 없음 |
| `cd`, `mkdir`, `rmdir` 뒤의 Tab은 폴더만 | 실제 bash(bash-completion)와 cmd와 같다 | 파일도 |
| 기호 검사(`unsupportedSyntaxAt`)를 `syntax.ts`로 뺐다 | `file-commands.ts`도 쓰는데 `os.ts`에서 가져오면 서로 가져오게 된다. `os.ts`는 그대로 다시 내보낸다 | |

## 6. 계획과 달라진 점

- 계획 문서(04-tasks)에 이 Task가 없어 `T0.19`를 썼다.
- VPC 기능 명세서 초안과 어긋난다. 명세서는 1절·3.3절에서 파일 명령을 빼고, 4절에서 리다이렉트를 거부하고, 7절 시나리오 7에서 `PC2 ls`를 "command not found"로 본다. 이 Task로 Linux `ls`가 생기고 `echo <글> > <파일>`만 예외로 받는다. 명세서는 팀이 합의한 뒤 고친다.
- 프롬프트가 바뀌어 예시 자료 `two-pc.ts`의 `prompt: "PC1>"`(T1.2.3, SDY)가 `"PC1 User>"`로 바뀌었다.

## 7. 남은 일과 다음 Task에 전할 것

- 팀 확인: VPC 명세서와 어긋나는 점, 예시 자료의 프롬프트.
- 처음 홈 폴더에 하위 폴더가 없어, 처음에 `cd` + Tab을 두 번 눌러도 후보가 없다. 홈에 `Desktop`, `Documents`, `Downloads`를 둘지 정하지 않았다.
- Windows에는 `ls`가 없다 (실제 cmd와 같음). PowerShell처럼 `dir`과 같은 명령으로 더할지 정하지 않았다.
- 터미널에서 빈 줄(`dir`, `ipconfig` 출력의 빈 줄)이 높이 없이 붙어 보인다. 이 Task 전부터 그렇다.
- 파일 명령을 더하는 사람: 경로 자리는 `file-commands.ts`의 `pathParam`(폴더만이면 `FOLDER`)으로 만들면 Tab이 파일 이름을 채운다.
