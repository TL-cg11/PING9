## 2. 진행 방식

케이블 버튼에서 기본 HTML dialog를 열고, 첫 번째/두 번째 장비와 포트를 선택한다. 선택된 장비가 있으면 첫 연결점으로 사용한다. 나머지 기본값은 빈 포트가 있는 장비를 우선한다. 포트의 켜짐 여부와 관계없이 물리 연결은 가능하다. 제출 직전의 Document 변경 검증은 엔진이 다시 수행하며 오류는 모달 안에 표시한다.

`availablePorts`는 문서의 링크 양쪽 끝에서 점유된 포트를 찾고, `PORT_NAMES` 순서로 나머지를 반환한다. Document/Runtime 사본을 화면 상태에 보관하지 않는다. 모달이 열린 동안 연결 상태가 바뀌어도 현재 Document에서 빈 포트를 다시 읽는다.

선은 클릭 또는 키보드로 선택할 수 있다. 넓은 투명 선을 클릭 영역으로 사용하고, 오른쪽 속성 패널에 두 장비의 이름/전체 포트 이름과 케이블 삭제 버튼을 표시한다. 장비나 터미널을 선택하면 링크 선택을 비운다.

### 주요 결정

| 결정 | 이유 | 선택하지 않은 대안 |
|---|---|---|
| 장비/포트 선택 창부터 제공 | 현재 캔버스에는 드래그 기반 편집 계약이 없어도 실제 연결을 조작 가능 | 드래그 편집기를 전부 기다림 |
| 기본 HTML modal dialog 사용 | 포커스 유지, Escape 취소, 배경 조작 차단을 브라우저가 처리 | 일반 div로 포커스 처리를 직접 구현 |
| 연결/삭제는 기존 Simulator.dispatch만 사용 | 설정 원본을 엔진이 관리 | 화면에서 Document 배열 직접 수정 |
| 빈 포트만 선택, 꺼진 포트는 허용 | 중복 점유를 막으면서 Router 기본 꺼짐 상태에서도 케이블을 꽂을 수 있음 | 켜진 포트만 선택 허용 |

실제 Chrome의 로컬 개발 화면에서도 아래를 확인했다.

1. Router를 추가하고 케이블 버튼을 클릭 → R1, Gi0/0, SW1, 빈 포트 Fa0/3이 선택 창에 표시.
2. 연결 버튼 클릭 → `케이블 R1 Gi0/0 ↔ SW1 Fa0/3` 선과 오른쪽 케이블 정보/삭제 버튼 표시.
3. R1 선택 → 포트 4개, 1개 연결, Gi0/0의 상대 SW1 표시.
4. R1 콘솔에서 `no shutdown`, `show ip interface brief` → Gi0/0이 `up`이고 패널도 같은 상태.
5. 선 선택 → 케이블 삭제 → 연결선이 없어지고 R1이 0개 연결, Gi0/0 `no-link`로 복귀.

## 6. 계획과 달라진 점

- 선 끌기 대신 장비 두 대를 선택하는 창으로 먼저 연결을 제공한다. 전체 드래그 편집기를 구현하면 현재 모달과 공통 `link/add` 경로를 재사용할 수 있다.
- 기존 케이블도 선택/삭제 가능하다. 장비 삭제 화면이나 확인 창은 포함하지 않는다.
- Router 생성 → 링크 엔진 → 연결 화면 순으로 Task별 로컬 브랜치와 커밋을 쌓았다. PR 제출 시 각각의 기준 브랜치를 확인한다.
