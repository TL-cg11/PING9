## 1. 목표와 완료 기준

T6.4.1의 "장비에 마우스를 올리면 인터페이스별 IP"를 먼저 캔버스에 바로 보이는 글자로 만들었다. 마우스를 올리지 않아도 어느 포트에 어떤 주소가 있고 케이블이 어느 대역인지 보이게 하는 것이 목표다.

- [x] 포트 이름 위에 그 포트 IP의 끝자리 (`.1`). PC는 장비의 IP, Router는 인터페이스의 IP. Switch 포트는 없음
- [x] 케이블 가운데에 대역 칩 (`10.0.12.0/30`). Switch로 이어진 구간마다 한 번, Router 쪽 링크에
- [x] 케이블에 마우스를 올리면 대역과 양 끝의 전체 주소 (`<title>`)
- [x] 포트 이름과 주소를 케이블 바깥(같은 장비의 다른 케이블 반대쪽)에 둔다
- [x] 주소가 장비 아이콘·이름·PC IP나 다른 포트 이름과 겹치면 포트 이름 밑으로 내린다
- [x] 짧은 케이블에는 대역 칩을 숨긴다
- [x] 펭귄이 케이블 글자를 밟고 지나간다 (글자 층을 케이블 바로 위로)
- [x] 펭귄이 장비 아이콘 뒤로 가려지지 않는다 (펭귄 층을 장비 위, 장비 이름 아래로)
- [x] ARP 펭귄의 `?`, `!`를 키운다
- [ ] 링크 양 끝의 `PortStatus` 표시 (색과 모양), 범례 — 이 PR에 없음
- [x] 공통 완료 조건: lint, 타입 검사, 단위 테스트, 빌드 통과. 리뷰는 PR에서

## 2. 진행 방식

1. 디자인 사본(5180)에서 시안을 여러 번 만들어 고르고(마우스 오버 카드 → 포트 위 주소 → 바깥에 놓기 → Switch·Router 구간 → 겹치면 아래로 → 펭귄 층), 실제 화면을 캡처해 확인했다.
2. 정해진 것을 저장소로 옮겼다. 저장소의 `canvas.tsx`는 5180의 작업 전 파일과 주석 한 줄만 달라서 이번 변경을 그대로 적용했다. CSS는 5180 전용 시안 규칙이 섞여 있어 이번에 추가한 규칙만 옮겼다.
3. 계산은 `format/port-address.ts`의 순수 함수로 두고 단위 테스트를 붙였다. 캔버스는 그 결과로 글자를 그린다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 주소는 끝자리만 (`.1`) | 케이블 옆 자리가 좁다. 대역은 칩에 있어 끝자리로 충분하다 | 전체 주소 (글자가 길어 겹침), 마우스 오버 카드만 |
| 대역은 Switch 구간마다 한 번, Router 쪽 링크에 | 같은 대역이 PC 케이블마다 반복되면 시끄럽다 | 모든 링크에, Switch–Switch 링크에도 |
| 포트 글자는 케이블 바깥에. 같은 장비의 다른 케이블 방향 합과의 내적이 0.35보다 크면 반대쪽 | 장비 둘레에 케이블이 여러 개일 때 글자가 케이블 사이에 끼지 않게 | 항상 위쪽 |
| 주소는 위가 겹치고 아래가 비어 있을 때만 포트 이름 밑 | 평소 모양(주소 위)을 유지하면서 장비 이름과 붙는 경우만 피한다 | 항상 밑, 겹침 무시 |
| 대역 칩은 케이블 길이가 칩 폭 + 40보다 짧으면 숨김 | 짧은 케이블에서 칩이 장비를 덮는다 | 고정 길이 기준, 칩을 케이블 밑으로 |
| 층 순서: 케이블 → 받침 → 케이블 글자 → 장비 → 펭귄 → 장비 이름 | 펭귄이 글자나 장비 아이콘 뒤로 지나가면 몸이 가려진다. 장비 이름은 늘 읽혀야 해서 맨 위. 같은 프레임을 멈춰 세 순서를 비교한 시안에서 골랐다 | 펭귄을 장비 밑에 (T6.1.2 그대로, 안내판에 가려짐), 펭귄을 맨 위에 (장비 이름을 덮음) |
| ARP `?`·`!`만 22px, RIP `R?`·`R!`는 15px 그대로 | 한 글자라 작으면 잘 안 보인다. 두 글자는 키우면 펭귄 머리를 덮는다 | 모두 키우기 |

## 6. 계획과 달라진 점

- 계획은 "장비에 마우스를 올리면 인터페이스별 IP"다. 이 PR은 마우스 없이 캔버스에 끝자리와 대역을 보이고, 전체 주소는 케이블에 마우스를 올렸을 때 보인다.
- 계획은 "스냅샷의 `views`에서 값 사용 (화면에서 계산하지 않음)"이다. 주소는 Document의 설정에서 읽고, 대역은 화면에서 shared의 `networkAddress`로 계산한다. 설정값만 보이고 동적 상태는 쓰지 않아서 `views`가 필요 없다고 봤다. 팀 확인 필요.
- 펭귄 층 순서와 ARP 표시 크기는 계획에 없는 추가다 (T6.1.2 쪽 화면). T6.1.2는 "펭귄이 장비 아이콘 밑에서 나와 밑으로 들어간다"로 정했는데, 이 PR에서 펭귄이 아이콘 위로 지나가게 바꿨다. 팀 확인 필요.
