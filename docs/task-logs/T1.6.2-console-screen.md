## 2. 진행 방식

1. 계획의 항목을 지금 코드와 하나씩 비교해 빈 곳을 찾았다 (1절 표).
2. 키 판단은 DOM 없이 테스트하도록 순수 함수로 두었다: 터미널은 기존 `terminal/keys.ts`에 `leave`(Esc)를 더하고, 캔버스 노드는 `components/canvas-keys.ts`를 새로 만들었다.
3. 캔버스 노드와 터미널 입력란은 서로 다른 컴포넌트라, 포커스는 장비 ID를 담은 `data-device-id`로 찾아 옮긴다 (`focus.ts`).

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 캔버스 노드는 `tabIndex=0`, `role="button"`. Enter는 콘솔 열기, Space는 선택 | 버튼과 같은 키다. 더블클릭(열기), 클릭(선택)과 짝이 맞는다 | 화살표로 노드 사이 이동 (요구사항에 없음) |
| 콘솔을 열면 이미 열려 있던 창이어도 입력란으로 포커스를 옮긴다 | Esc로 나와 다른 노드에서 Enter → 그 콘솔로, 이것이 키보드로 콘솔을 오가는 길이다. 따로 단축키를 두지 않았다 | 창 전환 단축키 |
| Esc는 창을 닫지 않고 포커스만 캔버스 노드로 옮긴다. 한글 조합 중의 Esc는 가로채지 않는다 | 다시 돌아올 때 키를 한 번 덜 누른다. 닫기는 Shift+Tab으로 × 버튼에 갈 수 있다 | Esc로 창 닫기 |
| 키보드 포커스는 아이콘 둘레의 점선 원. `:focus-visible`일 때만 | T0.6에서 카드가 투명해져 테두리 자리가 없다. 선택(퍼지는 빛)과 모양이 달라 겹쳐도 구별된다 | 브라우저 기본 테두리 (SVG `<g>`에서 모양이 일정하지 않음) |
| 창은 `role="region"`, 출력은 `role="log"` + `aria-live="polite"`. 입력란은 기록 밖 | 새 줄을 화면 낭독기가 읽는다. 입력하는 글자는 읽지 않는다 | 창 전체에 `aria-live` |
| 오류·알림 줄 앞에 글자(`%`, `!`)를 붙이지 않음 | T1.6.2 작업 목록에 없고, 문구가 문장이라 내용으로 구별된다. 입력 오류에는 `^` 줄이 있다 | 붙이기 (NFR-12를 넓게 읽으면) |

## 6. 계획과 달라진 점

- **`@xterm/xterm` 대신 입력란(`<input>`)이다.** T5.4.1의 결정을 이어 간다. 입력란으로 계획의 기능(편집, 이력, Tab, `?`, 한도, 제어 문자 제거)이 모두 되고, xterm은 의존성이 크며 한글 조합과 화면 낭독기를 다시 맞춰야 한다.
- **장비별 콘솔 "탭"(하단 도크) 대신 떠 있는 창이다.** 시안의 모양이고, 여러 콘솔을 나란히 볼 수 있다. FR-19("여러 콘솔을 열어 두고 전환")는 창으로도 된다. 하단 도크는 이벤트 목록(T1.9.2)에 쓴다.
- 계획 문서 본문은 팀이 합의한 뒤에 고친다.
