## 2. 진행 방식

작업 트리가 깨끗한 상태에서 origin을 fetch하고 main을 병합했다. 충돌은 `views.ts` 하나였다. main에서 분리한 topology의 공통 isAdminUp/portLink와 현재 브랜치의 routingTable 계산을 모두 유지했다. Simulator의 새 Runtime.fillViews는 PC ARP만 채우므로 Router 경로를 덮어쓰지 않는다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 현재 라우팅 브랜치에 main 병합 | 세 작업 커밋과 팀 전송 기능을 함께 보존 | main 코드로 로컬 작업 덮어쓰기 |
| 공통 topology 함수 재사용 | 링크 전송과 화면이 같은 규칙 사용 | 기존 로컬 포트 조회 함수 중복 보존 |
| 회귀 검증은 PC 직결과 별도 Router 연결을 한 문서에 둠 | Router 패킷 모델 없이도 두 기능의 공존 확인 | 미구현 라우터 전달을 성공처럼 처리 |


통합 회귀 검사에서는 PC 직결 ping의 응답과 성공 Trace, ARP 학습, Document 보존과 runtimeVersion 증가를 확인했다. 동시에 Router의 C/S 경로와 목적지 조회가 유지됐다. Router 포트를 끄면 경로만 사라지고 별도 PC의 ARP는 보존됐다. load 후에는 ARP·추적이 초기화되고 구성에서 계산한 경로는 유지됐다.
