## 2. 진행 방식

커널은 장비 종류를 모르는 실행기로 만들었다. Router, Switch, PC 모델을 만들거나 `Document`를 수정하지 않는다. `KernelRun.start`, `onFrame`, `onTimer`에 받은 동기 처리기만 호출한다. 장비 모델과 링크 어댑터가 이 처리기에 연결되는 것은 T1.7.2 이후다.

예를 들어 시작 처리기가 1,000 마이크로초 뒤의 프레임 도착과 2,000,000 마이크로초 뒤의 ARP 타이머를 예약하면, 실제 시간을 기다리지 않고 프레임 처리기를 먼저 실행한다. 응답 처리 중 타이머를 취소하면 타이머 처리기를 실행하지 않고 그 시각으로 시계도 진행하지 않는다.

### 주요 결정

| 결정 | 이유 | 선택하지 않은 대안 |
|---|---|---|
| 최소 힙으로 사건 큐 구현 | 시각·예약 순번으로 프레임과 타이머를 함께 처리 | 반복할 때마다 전체 배열 정렬 |
| 커널 절대 시계는 실행 사이에 유지, Trace 시간은 실행 시작을 0으로 기록 | AD-5와 AD-6 준수 | Trace마다 커널 시계 초기화 |
| Trace 번호는 커널에서 증가, 프레임 번호는 Trace마다 1부터 | Trace 계약 준수 | 화면이나 장비가 임의 번호 생성 |
| 성공 여부는 `outcome()`이 결정, 기본은 실패 | 빈 큐는 ping 성공의 증거가 아님 | 큐가 비면 자동 성공 |
| `Frame`은 id와 변경 불가능한 스냅샷 | 과거 Trace를 바꾸지 않고 TTL/VLAN 변경을 표현 | 전달하면서 같은 프레임 객체를 직접 수정 |
| 커널은 engine 내부 API로만 제공 | web은 기존 Simulator 경계만 사용 | `packages/engine/src/index.ts`에 새 API 공개 |
| 기존 `shared` 타입을 그대로 사용 | 문서·Trace 스키마 변경 없이 진행 | 새로운 이벤트 종류와 자료형을 shared에 중복 정의 |

## 6. 계획과 달라진 점

- **T1.11.1의 한도 보호 일부를 먼저 구현했다.** 프레임·타이머 처리 수, 예약 큐 크기, Trace 기록 수를 `LIMITS.maxTraceEvents`로 제한한다. 마지막 한 칸은 `LOOP_GUARD` 기록에 예약한다. 프레임 기록이 전혀 없는 경우 결과만 `loop-guard`이며 `primaryDropSeq`는 없다. 실제 고리 토폴로지 검증은 T1.11.1에 남는다.
- 타이머 취소를 추가했다. ARP 응답 뒤 대기 타이머가 계속 실행되는 것을 막는 데 필요하다.
- `DeviceModel`, 송신 포트 확인, 토폴로지에서 링크 상대 찾기, 1,000 마이크로초 링크 지연 적용은 **T1.7.2**에서 구현한다. 현재 `ctx.sendFrame`은 수신 `PortRef`와 지연을 명시적으로 받는 내부 예약 함수다.

## 7. 남은 일과 다음 Task에 전할 것

1. **T1.7.2:** `DeviceModel`과 링크 전달 어댑터에서 `ctx.sendFrame(target, frame, LINK_DELAY_MICROSECONDS)`를 호출한다. 연결이 없거나 포트가 꺼졌으면 기존 폐기 코드를 기록한다. 현재 커널은 그런 도착 가능성을 검사하지 않는다.
2. **Simulator 연결:** `load` 때 커널을 새로 만들거나 `reset()`한다. 공개 API를 바꾸지 않고 내부에서 `run()`을 호출하고 완성된 Trace를 보관한다. 이 연결은 아직 구현하지 않았다.
3. **Switch 모델 연결:** 기존 `switchForward`에 `ctx.now()`를 넘긴다. 출력 포트별로 forward 기록을 남기고 해당 `seq`를 수신 사건의 원인으로 예약한다.
4. **프레임 규칙:** 같은 프레임의 내용이 바뀌면 `updateFrame()`으로 id를 유지한다. ARP 응답/ICMP 응답은 `createFrame()`으로 새 id를 만들고 원인 이벤트를 `parentSeq`에 넣는다.
5. **원인 규칙:** `record()`의 기본 원인은 현재 콜백을 일으킨 사건의 `parentSeq`다. 같은 콜백에서 기록한 이벤트끼리 이어야 하면 반환된 `seq`를 명시한다. 예약의 기본 원인은 해당 콜백에서 마지막으로 기록한 `seq`다. flooding처럼 분기하면 부모 seq를 명시해서 형제 이벤트끼리 연결하지 않도록 한다.
6. **타이머/문맥:** 취소에 쓸 `TimerRef`를 보관한다. `SimContext`는 해당 콜백 안에서만 쓰고 보관해서 다음 콜백에서 재사용하지 않는다. 시간·프레임 소속·부모 seq 위반의 예외는 내부 개발 오류다. 사용자 입력의 오류 처리는 기존 CLI/reducer 경로가 맡는다.
7. **성공 판정:** 요청을 보냈다는 사실이 아니라, 출발 PC가 일치하는 echo 응답을 받은 상태를 `outcome()`으로 반환한다. 실패 Trace는 기록 중 첫 실패 폐기를 가리키며 `NOT_FOR_ME`는 제외한다. 프로토콜 수준에서 여러 폐기의 우선순위 판정은 후속 Task에서 보완할 수 있다.
