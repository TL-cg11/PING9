## 2. 진행 방식

기존 변경을 보존하고 별도 브랜치에서 가이드를 수정했다. 사용자 추가 지시를 반영해 Firewall을 Router R2로 교체했다. ISP·R2는 중간 라우터, R1은 VPN 서버다. 구간별로 198.168.0.0/24, 1.0/30, 2.0/30, 내부 3.0/24, VPN 4.0/29를 사용한다. 요청한 198.168 표기를 그대로 적용했다.

ISP는 서버 대역으로 가는 정적 경로를, R2/R1은 외부 PC로 돌아가는 기본 경로를 가진다. 사전 설정된 ?lab=ssl은 기존 구성으로 유지하므로 이 가이드와 섞지 않도록 적었다. 새 구성을 바로 확인하려면 별도 실습 JSON을 가져온다.

## 4. 결과와 검증

임시 검증 파일에서 빈 Simulator에 PC 2대·Router 3대·케이블 4개를 생성했다. PC 주소는 문서 표에서, Router 명령은 문서 코드 블록에서 추출했다. 양쪽 게이트웨이와 외부 PC→VPN 서버 물리 IP의 ping을 확인했다.

문서의 PC/서버 config JSON을 내보내기 파일 구조에 적용해 parseExportJson → load를 통과했다. 그 파일을 완성 예제로 저장했다. 접속 후 가상 IP 198.168.4.2, 중간 Router 각각의 제어 메시지 6회 전달, 해제·IP 반환, R2 shutdown 후 timeout, no shutdown 후 재접속을 확인했다. 내부 PC ping은 Destination net unreachable로 확인했다.

가져오기 후 CLI가 user 모드로 초기화되는 것을 확인해 장애 실습 첫 줄에 enable을 추가했다. 중간 Router의 unreachable 응답도 Reply from 문구를 포함하므로, 내부 PC의 bytes 응답과 구분해 검증하고 문서에 설명했다.

```text
pnpm --filter @ping9/engine exec vitest run src/vpn/ssl-vpn-address-rehearsal.test.ts
  Test Files 1 passed (1)
  Tests 1 passed (1)
```

임시 검증 파일은 확인 후 삭제했다. 제품 코드 변경이 없어 전체 빌드·검사는 반복하지 않았다. 수동 브라우저 조작은 하지 않았다. 최종 문서·JSON의 상대 링크/비밀값/공백을 별도 확인했다.
