## 1. 목표와 완료 기준

VPC 기능 명세서(초안, 팀 합의 전)의 입력 규칙 가운데 빠진 것을 채운다.

- [x] 한 줄에 명령 하나: 파이프, 리다이렉트, 명령 연결 기호가 있으면 실행하지 않고 그 위치를 알린다
- [x] 대소문자: Linux는 구분, Windows는 무시
- [x] 모르는 명령: OS 형식의 줄(`ls: command not found`, `'ls' is not recognized ...`)과 한국어 안내
- [x] `help`: 그 OS에서 칠 수 있는 명령어를 모두 보인다
- [ ] 출력 길이 한도 (명령 하나당 64 KiB): 하지 않음 (6절)
- [x] 공통 완료 조건: lint, 타입 검사, 단위 테스트, 빌드 (4절). 리뷰는 PR에서

## 2. 진행 방식

1. 명세서의 입력 규칙을 지금 코드와 하나씩 맞춰 봤다. 입력 512자, 축약과 Tab 완성은 이미 됐다. 나머지 넷을 이번에 한다.
2. 대소문자: 해석기(`cli/ios/parse.ts`)는 Switch·Router·PC가 같이 쓴다. 명령 정의에 `caseSensitive`를 더하고, Linux 목록에만 켠다. 실행, Tab 완성, `?`가 같은 비교 함수(`keyOf`, `sameKeyword`, `startsKeyword`)를 쓴다.
3. 기호 거부와 모르는 명령은 PC 콘솔에서만 한다 (`console.ts`). 해석 전에 기호를 찾고, 해석 뒤에 "첫 단어가 없는 명령어" 오류를 OS 형식으로 바꾼다.
4. `help`는 명령 정의 목록에서 쓰는 형태(`ping -c <count> <ip>`)와 설명을 만들어 알파벳순으로 보인다.
5. 개발 서버(5180)의 사본에 같은 변경을 넣어 사용자가 화면에서 확인한다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 기호 거부는 PC만 | Switch의 `show ... \| include`는 나중에 쓸 수 있다 | 모든 장비 |
| `&&`가 아니라 `&` 하나도 막음 | Windows는 `&` 하나로 명령을 잇는다 | 명세서대로 `&&`만 |
| 모르는 명령의 OS 형식 줄은 첫 단어가 없을 때만 | 첫 단어는 맞고 뒤가 틀리면(`ip bogus`) 틀린 위치의 `^` 표시가 더 도움이 된다 | 모든 해석 오류를 OS 형식으로 |
| 한국어 안내는 알림(`notice`) 코드 `PC_UNKNOWN_COMMAND` | 명세서 4절. OS 형식 줄 다음에 오므로 `^` 표시가 필요 없다 | 오류 줄로 (`^`가 OS 형식 줄 밑에 찍힘) |
| 대소문자 구분은 명령 정의마다 | 해석기는 장비 종류를 모른다. 목록을 고르는 쪽(`cli/pc/os.ts`)이 정한다 | 해석기에 장비 종류·OS를 넘김 |
| 한국어 문구에 조사를 붙이지 않음 (`ls 명령어는`, `\| 기호를`) | 영어 단어와 기호 뒤에 조사를 고르는 함수가 없다 | `ls는`, `\|를` |

## 6. 계획과 달라진 점

- 계획 문서(04-tasks)에 OS별 PC 콘솔 Task가 없어 `T0.9`를 썼다. 근거는 팀 합의 전인 VPC 기능 명세서 초안이다.
- 출력 길이 한도(64 KiB)는 넣지 않았다. 지금 PC 명령 중 그만큼 출력하는 것이 없다 (ping 최대 10회, ARP 표는 장비 수만큼). 긴 출력을 내는 명령이 생길 때 넣는다.
- `help`는 [T1.6.1](T1.6.1-pc-commands.md)에서 "T3.2.2에서 모든 장비 공용으로" 미뤘다. T3.2.2는 `?`만 만들어, 이번에 PC 명령으로 넣었다. Switch·Router의 `help`는 그대로 없다.

## 7. 남은 일과 다음 Task에 전할 것

- Linux에서 `-c` 없는 `ping`은 지금처럼 4회. 실제처럼 Ctrl+C까지 계속 보내는 것(Windows `ping -t`와 함께)은 엔진과 콘솔 계약을 바꿔야 해 따로 한다.
- 명령 정의를 더하는 사람: Linux PC 목록에 넣은 정의는 `cli/pc/os.ts`에서 자동으로 대소문자를 구분한다. 키워드는 소문자로 적는다.
- 명세서 초안의 나머지(2단계 `route print`·`ip route` 조회, `ip link set`, OS별 fixture)는 아직 없다.
