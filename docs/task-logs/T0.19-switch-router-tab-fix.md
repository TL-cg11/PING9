## 1. 목표와 완료 기준

T0.19(PR #61)는 PC 콘솔에 bash 방식의 Tab(공통 부분까지 채우기, 두 번 누르면 후보 나열)을 넣었다. PR 설명은 "PC만, Switch와 Router는 그대로"였지만 두 가지가 Switch·Router에도 적용됐다. 그것을 되돌린다.

- [x] Switch·Router 콘솔에서 Tab을 두 번 눌러도 후보를 나열하지 않는다. 실제 IOS처럼 목록은 `?`가 한다
- [x] Switch·Router의 Tab은 하나로 정해질 때만 완성한다. 여러 키워드의 공통 부분만 채우지 않는다
- [x] PC 콘솔의 Tab(T0.19)은 그대로다: 공통 부분 채우기, 후보 나열, 경로 완성
- [x] Switch·Router의 Tab 한 번 완성과 `?` 도움말은 그대로다
- [x] 공통 완료 조건: lint, 타입 검사, 단위 테스트, 빌드 (4절). 리뷰는 PR에서

## 2. 진행 방식

1. PR #61을 병합하기 전 검토에서 임시 테스트로 확인했다: Switch 사용자 모드에서 `candidates("e")`가 `["enable", "exit"]`, Router 특권 모드에서 `candidates("c")`가 `["clear", "configure"]`. 병합 뒤에 고친다.
2. 실패하는 테스트를 먼저 썼다. Switch 콘솔, Router 콘솔, `completeLine`에 하나씩. 고치기 전에 돌려 세 개가 기대한 이유로 실패하는 것을 봤다 (4절).
3. 바뀌면 안 되는 동작을 고정하는 테스트도 함께 넣었다: Switch의 Tab 한 번 완성과 `?`, 똑같은 키워드가 있을 때의 완성, 경로 완성이 있을 때(PC)의 공통 부분 채우기. 이것들은 고치기 전에도 통과한다.
4. `ConsolePort.candidates`는 PC가 아니면 빈 목록을 돌려주게 하고, `completeLine`은 경로 완성(`paths`)이 없으면 공통 부분을 채우지 않게 했다.
5. 전체 검사를 돌리고 개발 서버에서 Switch와 PC의 터미널을 직접 눌러 봤다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 후보 나열은 `console.ts`의 `candidates`에서 장비 종류로 막는다 | `ConsolePort`가 화면이 쓰는 경계다. 화면(`terminal-window.tsx`)은 장비 종류를 몰라도 된다 | 화면에서 PC일 때만 `candidates`를 부르기 |
| 공통 부분 채우기는 `completeLine`에서 `paths`가 없으면 하지 않는다 | `paths`는 PC에만 준다(`console.ts`의 `pathsOf`). PC와 IOS 장비를 가르는 값이 이미 있다 | `completeLine`에 장비 종류를 따로 넘기기 |
| 지금 명령어로는 결과가 달라지지 않는 `completeLine`도 함께 고친다 | Switch·Router에는 한 자리에서 앞 두 글자가 같은 키워드가 아직 없어 우연히 같았을 뿐이다. `show mac`과 `show mac-address-table` 같은 것이 생기면 `show m` + Tab이 달라진다 | 그런 명령어가 생길 때 고치기 |
| PC의 Tab과 줄여 쓰기는 건드리지 않는다 | 이 수정은 Switch·Router를 되돌리는 것이다 | PR #61 리뷰의 다른 항목(줄여 쓴 삭제 명령 등)도 함께 고치기 |

## 7. 남은 일과 다음 Task에 전할 것

PR #61 리뷰에 적은 것 가운데 이 수정에 넣지 않은 것 (모두 PC 콘솔):

- 줄여 쓴 삭제 명령: Windows PC의 `rm /s /q lab`(`rmdir`로 읽힘), Linux의 `rm - d`(`rm -r d`로 읽힘), `de x`(`del x`).
- OS를 바꿨다 돌아오면 옛 파일 트리가 되살아난다. 지운 PC의 트리가 남는다.
- 빈 단어에서 Tab이 옵션 하나를 넣는다 (`ipconfig ` → `ipconfig /all `). "같은 입력에서 두 번" 상태가 글자를 치거나 지워도 풀리지 않는다.
- 새 첫 단어 때문에 `r print`, `t <ip>`, `p <ip>` 같은 기존 줄임이 모호해졌다.

Router에는 Switch의 "실제 명령 정의 전체로 Tab을 확인하는 테스트"(`assist.test.ts`)에 해당하는 것이 없다. Router 명령어를 더할 때 함께 넣으면 좋다.

다음에 `cli/ios`의 완성·도움말을 고칠 때는 PC가 아닌 장비의 결과가 바뀌지 않는지 `assist-console.test.ts`와 `router-console.test.ts`로 확인한다.
