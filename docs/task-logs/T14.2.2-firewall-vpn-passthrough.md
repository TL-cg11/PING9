## 1. 목표와 완료 기준

Firewall(T14.2.1, PR #65)과 GRE·IPsec(T15, PR #63)은 서로를 모른 채 같은 날 `main`에 들어왔다. 둘을 함께 쓰면, 터널 양 끝 사이에 Firewall이 있을 때 FORWARD가 모두 ACCEPT여도 터널이 끊긴다. Firewall이 넘기는 프레임을 IPv4와 ICMP만으로 다시 만들어서, 바깥 헤더(프로토콜 47, 50)만 남고 감싼 내용(`gre`, `esp`)이 사라지기 때문이다. 받는 Router는 멀쩡한 터널 설정을 탓하는 사유(`GRE_REJECTED`, `IPSEC_REJECTED`)를 남긴다.

- [x] Router — Firewall — Router에서 규칙이 없으면 GRE와 IPsec 양쪽 모두 PC 사이의 ping이 된다
- [x] Firewall이 넘긴 프레임에 감싼 내용이 그대로 있고, 추적이 검사(`validateTrace`)를 통과한다
- [x] 필터는 바깥 패킷을 본다: `-p icmp` 규칙은 감싼 ping에 맞지 않고, 프로토콜을 정하지 않은 규칙은 맞는다
- [x] 공통 완료 조건: lint, 타입 검사, 단위 테스트, 빌드 (4절)
- [ ] 리뷰

## 2. 진행 방식

1. 실패하는 테스트를 먼저 썼다. VPN 실습 예제(`greLabDocument`, `ipsecLabDocument`)의 가운데 Router를 같은 주소의 Firewall로 바꾼 토폴로지를 만들고, 테스트 3가지를 GRE와 IPsec에 각각 돌린다 (6개).
2. 고치기 전에 돌려 4개가 기대한 이유로 실패하는 것을 봤다 (4절). 나머지 2개("프로토콜을 정하지 않은 규칙은 감싼 패킷도 막는다")는 이미 되는 동작을 붙잡아 두는 테스트라 이때도 통과한다.
3. `FirewallModel`의 전달에서 프로토콜이 47이면 `gre`를, 50이면 `esp`를 원래 프레임에서 옮기게 했다. Router의 전달(`RouterModel`의 `#send`)이 PR #63에서 하게 된 것과 같다.
4. 전체 검사를 돌리고, 개발 서버에서 같은 토폴로지를 불러 직접 확인했다.

### 주요 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| Firewall은 감싼 패킷의 안을 열어 보지 않고 그대로 넘긴다 | 실제 방화벽도 터널의 끝이 아니면 바깥 패킷만 본다. IPsec은 안을 볼 수 없는 것이 맞다 | Firewall이 안쪽 패킷으로 필터를 판정하기 (GRE에서만 가능하고, 실제 iptables의 동작과 다르다) |
| 필터가 보는 값(`filterPacketOf`)은 고치지 않는다. GRE·ESP 패킷은 프로토콜이 없는 패킷으로 판정된다 | `-p icmp`, `-p tcp`, `-p udp` 규칙에 맞지 않고 프로토콜을 정하지 않은 규칙에는 맞는다. 바깥 패킷이 ICMP가 아니므로 맞는 결과다. 테스트로 붙잡았다 | `-p gre`, `-p esp`를 규칙에 받기 (`FirewallRule`과 iptables 파서, 화면까지 바뀌는 새 기능이다. 7절) |
| Router와 같은 두 줄을 Firewall에 그대로 썼다 | 두 모델은 따로 쓰기로 한 구조다 (T14.2.1의 결정). 옮기는 계층이 둘뿐이다 | `transportLayersOf`처럼 공통 함수로 빼기 (Router 담당의 파일을 함께 고쳐야 한다) |

## 7. 남은 일과 다음 Task에 전할 것

이 수정에 넣지 않은 것:

- **Firewall 자신의 주소로 온 GRE·ESP 패킷**은 `IPV4_RECEIVED`만 남기고 조용히 끝난다. Firewall은 터널의 끝이 될 수 없으니 버리는 것은 맞지만, 폐기 사유가 없어 이벤트 탭이 원인을 찾지 못한다. 맞는 사유 코드가 없어(`PORT_CLOSED`는 TCP·UDP용) 새 코드가 필요하다.
- **GRE·ESP 패킷을 REJECT하거나 TTL이 다해 버릴 때 ICMP 오류를 돌려주지 않는다.** Router도 감싼 패킷에는 오류를 만들지 않는다. 폐기 사유는 남는다.
- **`-p gre`, `-p esp` 규칙이 없다.** 터널만 골라 막거나 허용하려면 출발지·목적지 주소로 써야 한다. 넣으려면 `FirewallRule`의 프로토콜, iptables 파서, 속성 패널을 함께 고친다.
- 캔버스의 주소 표시(T6.4.1)와 Router의 겹치는 주소 알림은 아직 Firewall을 모른다 ([PR #64](https://github.com/TL-cg11/PING9/pull/64), [PR #63](https://github.com/TL-cg11/PING9/pull/63) 리뷰에 적었다).

전달하는 장비(Router, Firewall)는 프레임을 계층별로 다시 만든다. `FrameSnapshot`에 계층을 더할 때는 두 모델의 `#send`가 그 계층을 옮기는지 함께 본다. TCP·UDP(T0.20)는 `transportLayersOf`로 양쪽에 넣었고, GRE·ESP는 이 수정으로 맞췄다.
